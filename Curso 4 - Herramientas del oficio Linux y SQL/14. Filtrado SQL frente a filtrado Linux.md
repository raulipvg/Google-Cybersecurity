# Filtrado SQL frente a Filtrado Linux

En esta lectura del **Curso 4: Herramientas del oficio (Linux y SQL)**, se analizan las diferencias fundamentales entre el filtrado de datos en **Linux** (a nivel de sistema de archivos y texto plano) y el filtrado en **SQL** (a nivel de bases de datos estructuradas y relaciones tabulares), así como los métodos de acceso a SQL desde la línea de comandos.

---

## 1. Acceso a SQL desde la Línea de Comandos de Linux

Existen diversas interfaces gráficas y de consola para interactuar con bases de datos. Una de las vías más comunes para los analistas de ciberseguridad es acceder directamente a través de la terminal de Linux.

```
┌────────────────────────────────────────────────────────┐
│                   TERMINAL DE LINUX                    │
└──────────────────────────┬─────────────────────────────┘
                           │ Ejecución: sqlite3 / mysql / psql
                           ▼
┌────────────────────────────────────────────────────────┐
│                   CLIENTE INTERACTIVO SQL              │
│       (Los comandos ingresados se envían al motor      │
│      de base de datos, en lugar del shell de Linux)    │
└────────────────────────────────────────────────────────┘
```

* **Ejemplo práctico:** Al introducir `sqlite3` (o `sqlite3 base_de_datos.db`), la sesión del shell pasa al intérprete interactivo de SQLite.
* **Comportamiento:** A partir de ese momento, las instrucciones ingresadas deben seguir la sintaxis de SQL (como `SELECT * FROM...`) en lugar de comandos estándar de Linux (`ls`, `grep`, etc.).

### Tabla Comparativa de Características

| Dimensión | Filtrado en Linux | Filtrado en SQL |
| :--- | :--- | :--- |
| **Propósito Principal** | Búsqueda y manipulación de archivos, carpetas, procesos y registros de texto plano. | Consulta, agregación y extracción de datos organizados dentro de un RDBMS. |
| **Formato de Entrada** | Archivos de texto sin procesar (`.txt`, `.log`), salida estándar (`stdout`). | Tablas estructuradas con esquemas, tipos de datos y columnas predefinidas. |
| **Sintaxis** | Comandos utilitarios independientes (`grep`, `find`, `sed`, `cut`, `awk`, `\|`). | Lenguaje de consulta declarativo estandarizado (`SELECT`, `WHERE`, `JOIN`, `GROUP BY`). |
| **Estructura del Resultado** | Líneas de texto continuo o flujos de caracteres no estructurados. | Conjuntos de resultados (*result sets*) tabulares altamente organizados. |
| **Capacidad de Cruce de Datos** | Limitada; requiere scripts complejos para correlacionar diferentes ficheros. | **Nativa y potente** mediante cláusulas `JOIN` para combinar múltiples tablas. |

---

## 3. Dimensiones Clave de Diferenciación

### A. Estructura y Legibilidad
* **SQL:** Organiza la información en campos y columnas definidos (por ejemplo: `timestamp`, `username`, `ip_address`, `status`). Permite aislar y ordenar columnas específicas con gran precisión.
* **Linux:** Imprime líneas de texto consecutivas. Aunque es posible cortar delimitadores mediante comandos como `cut` o `awk`, carece del orden relacional inherente de una base de datos.

### B. Unión de Tablas (*JOINs*)
* En ciberseguridad, muchas investigaciones requieren correlacionar eventos (ej. vincular una dirección IP sospechosa de la tabla `intentos_login` con la tabla `empleados`).
* **SQL** permite combinar estas fuentes en una única consulta mediante `JOIN`.
* **Linux** procesa archivos de forma aislada, lo que vuelve más complejo conectar datos dispares entre sí sin herramientas avanzadas de scripting.

## 4. Cuándo Usar Cada Herramienta en Ciberseguridad

```bash
# Ejemplo de filtrado rápido en Linux (archivo de log plano):
grep "Failed password" /var/log/auth.log | cut -d' ' -f9-
```

```sql
-- Ejemplo de filtrado estructurado en SQL (base de datos relacional):
SELECT username, ip_address, login_time 
FROM user_logins 
WHERE login_status = 'FAILED' 
ORDER BY login_time DESC;
```

### Casos de Uso Recomendados:

| Escenario de Seguridad | Herramienta Recomendada | Razón Técnica |
| :--- | :---: | :--- |
| **Inspección rápida de logs en servidores remotos** | **Linux** (`grep`, `tail`, `less`) | Acceso directo sin necesidad de importar a una base de datos. |
| **Análisis de eventos masivos en plataformas SIEM** | **SQL / Motores SQL** | Permite consultas estructuradas, indexadas y uniones relacionales. |
| **Búsqueda de archivos infectados o por extensión** | **Linux** (`find`) | Operación directa sobre el sistema de archivos (*FHS*). |
| **Auditoría de privilegios cruzando roles y accesos** | **SQL** (`JOIN`) | Cruce relacional de tablas de usuarios, permisos y departamentos. |

---

## Puntos Clave

> [!IMPORTANT]
> * **Enfoques Complementarios:** Linux filtra cadenas y archivos dentro del sistema operativo, mientras que SQL manipula y consulta datos tabulares dentro de sistemas gestores de bases de datos.
> * **Acceso a SQL:** Puede iniciarse directamente desde la consola de Linux ejecutando el cliente del motor correspondiente (como `sqlite3`).
> * **Estructura y Relaciones:** SQL ofrece mayor ordenamiento por columnas y permite unir múltiples tablas mediante `JOIN`, facilitando análisis de seguridad complejos.
> * **Versatilidad del Analista:** El analista de ciberseguridad debe dominar ambas técnicas: Linux para archivos de texto plano inmediatos y SQL para repositorios estructurados.
