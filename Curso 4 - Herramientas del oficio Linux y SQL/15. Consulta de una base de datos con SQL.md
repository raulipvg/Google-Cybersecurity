# Consulta de una Base de Datos con SQL

En esta lectura del **Curso 4: Herramientas del oficio (Linux y SQL)**, se exploran los fundamentos para construir consultas estructuradas en SQL, analizando la estructura de la base de datos de ejemplo **Chinook**, las cláusulas esenciales **`SELECT`** y **`FROM`**, y el ordenamiento de resultados con **`ORDER BY`** (ascendente, descendente y multicriterio).

---

## 1. La Base de Datos de Prueba: Chinook

Para aprender a consultar datos sin la complejidad de diseñar un motor relacional desde cero (analogía de aprender a conducir un vehículo antes de fabricarlo), el curso utiliza la base de datos relacional **Chinook**.

```
┌────────────────────────────────────────────────────────┐
│               BASE DE DATOS CHINOOK (11 Tablas)        │
├───────────────────┬───────────────────┬────────────────┤
│    employees      │    customers      │    invoices    │
│ (Datos empleados) │ (Datos clientes)  │ (Facturación)  │
├───────────────────┼───────────────────┼────────────────┤
│ • employee_id     │ • customerid      │ • invoiceid    │
│ • lastname        │ • city            │ • total        │
│ • title           │ • country         │ • customerid   │
└───────────────────┴───────────────────┴────────────────┘
```

* **Contexto de negocio:** Simula la operativa de una tienda de medios digitales.
* **Relevancia en Ciberseguridad:** Los analistas consultan habitualmente tablas de empleados, clientes y facturación para auditar accesos, detectar anomalías de compras o investigar posibles filtraciones de datos.

## 2. Estructura Básica de una Consulta SQL: `SELECT` y `FROM`

Cualquier consulta básica en SQL requiere un mínimo de dos componentes: **qué campos extraer** y **de dónde extraerlos**.

```
┌────────────────────────────────────────────────────────┐
│                   ANATOMÍA DE LA CONSULTA              │
└──────────────────────────┬─────────────────────────────┘
                           │
           ┌───────────────┴───────────────┐
           ▼                               ▼
┌─────────────────────┐         ┌─────────────────────┐
│       SELECT        │         │        FROM         │
├─────────────────────┤         ├─────────────────────┤
│ Define las COLUMNAS │         │ Define la TABLA     │
│ que se mostrarán.   │         │ origen de los datos.│
└─────────────────────┘         └─────────────────────┘
```

### A. La Cláusula `SELECT`
Indica las columnas o campos específicos que devolverá el resultado.

* **Columna individual:**
  ```sql
  SELECT customerid FROM customers;
  ```
* **Múltiples columnas (separadas por coma):**
  ```sql
  SELECT customerid, city, country FROM customers;
  ```
* **Todas las columnas (comodín asterisco `*`):**
  ```sql
  SELECT * FROM customers;
  ```

> [!WARNING]
> **Rendimiento y Seguridad con `SELECT *`:** En bases de datos corporativas con millones de registros, usar `SELECT *` satura la memoria, ralentiza la consulta y expone campos sensibles innecesarios. Se recomienda especificar únicamente las columnas requeridas para la investigación.

---

### B. La Cláusula `FROM`
Indica la tabla de la base de datos sobre la cual se ejecutará la consulta.

* **Sintaxis estándar multilínea:**
  ```sql
  SELECT employee_id, device_id
  FROM employees;
  ```
* **Punto y coma (`;`):** Indica al motor SQL el fin formal de la sentencia o consulta.
* **Formato:** Aunque SQL ignora los saltos de línea (pudiendo escribirse en una sola línea), separar las cláusulas en líneas independientes mejora la legibilidad y mantenimiento del código.

## 3. Organización y Ordenamiento de Datos: `ORDER BY`

La cláusula **`ORDER BY`** organiza los registros devueltos en función de una o varias columnas especificadas, en sentido ascendente o descendente.

```
                  ┌─────────────────────────────────────┐
                  │       DIRECCIÓN DE ORDENAMIENTO     │
                  └──────────────────┬──────────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
┌─────────────────────┐                             ┌─────────────────────┐
│  ASCENDENTE (ASC)   │                             │  DESCENDENTE (DESC) │
├─────────────────────┤                             ├─────────────────────┤
│ • Por defecto       │                             │ • Requiere 'DESC'   │
│ • Números: 1 ➔ 100  │                             │ • Números: 100 ➔ 1  │
│ • Letras: A ➔ Z     │                             │ • Letras: Z ➔ A     │
└─────────────────────┘                             └─────────────────────┘
```

---

### A. Orden Ascendente (Comportamiento por Defecto)
Si no se especifica dirección, SQL ordena automáticamente en orden ascendente:
* **Datos numéricos:** De menor a mayor (`1` ➔ `999`).
* **Datos de texto:** En orden alfabético (`A` ➔ `Z`).

```sql
SELECT customerid, city, country
FROM customers
ORDER BY city;
```

---

### B. Orden Descendente con la Cláusula `DESC`
Para invertir el orden, se añade la palabra clave **`DESC`** inmediatamente después del nombre de la columna:
* **Datos numéricos:** De mayor a menor (`999` ➔ `1`).
* **Datos de texto:** En orden alfabético inverso (`Z` ➔ `A`).

```sql
SELECT customerid, city, country
FROM customers
ORDER BY city DESC;
```

---

### C. Ordenamiento por Múltiples Columnas (Multicriterio)
Es posible definir una jerarquía de ordenación listando varias columnas separadas por comas. SQL ordenará primero por la columna primaria y, en caso de empates o valores idénticos, ordenará por la columna secundaria.

```sql
SELECT customerid, city, country
FROM customers
ORDER BY country, city;
```

> [!TIP]
> En este ejemplo, todos los clientes del mismo país (`country`) aparecerán agrupados, y dentro de cada país las ciudades (`city`) estarán ordenadas alfabéticamente de la A a la Z.

---

## Puntos Clave

> [!IMPORTANT]
> * **Cláusulas Fundamentales:** Toda consulta de lectura básica en SQL parte de la combinación obligatoria de **`SELECT`** (columnas deseadas) y **`FROM`** (tabla de origen).
> * **Comodín Universal (`*`):** Devuelve la totalidad de las columnas de una tabla, aunque debe usarse con precaución en producción.
> * **Terminador de Sentencia (`;`):** Define el cierre de una instrucción SQL.
> * **Organización con `ORDER BY`:** Permite ordenar los registros devueltos de forma ascendente (por defecto) o descendente (**`DESC`**), admitiendo múltiples criterios de ordenación jerárquica.
