# Uso Responsable de sudo y Administración de Usuarios

En esta lectura del **Curso 4: Herramientas del oficio (Linux y SQL)**, se analiza el concepto de privilegios elevados mediante **`sudo`**, los riesgos de la cuenta `root`, el principio de uso responsable, y los comandos de administración de usuarios y propiedad de archivos: **`useradd`**, **`usermod`**, **`userdel`** y **`chown`**.

---

## 1. El Comando `sudo` y el Principio de Privilegio Elevado

El comando **`sudo`** (*SuperUser DO*) permite a usuarios autorizados ejecutar comandos temporales con privilegios elevados de superusuario (`root`), sin necesidad de iniciar sesión directamente como la cuenta `root`.

```
┌────────────────────────────────────────────────────────┐
│                   ACCESO AL SISTEMA                    │
└──────────────────────────┬─────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          ▼                                 ▼
┌──────────────────┐               ┌──────────────────┐
│ INICIO COMO ROOT │               │  USO DE SUDO     │
├──────────────────┤               ├──────────────────┤
│ ❌ Alto Riesgo   │               │ ✅ Privilegio    │
│ ❌ Sin Auditoría │               │    Temporal      │
│ ❌ Error Fatal   │               │ ✅ Rastreable    │
└──────────────────┘               └──────────────────┘
```

### ¿Por qué NO es recomendable iniciar sesión como `root`?
1. **Falta de Trazabilidad y Auditoría:** Los registros del sistema no pueden diferenciar qué individuo humano ejecutó una acción si todos inician sesión directamente como `root`.
2. **Riesgos de Seguridad Extremos:** Si una sesión `root` activa es comprometida, el atacante obtiene control total e irrestricto sobre la máquina.
3. **Errores Irreversibles:** Los comandos ejecutados como `root` no solicitan confirmación y pueden destruir el sistema operativo por accidente.

> [!NOTE]
> **Archivo `/etc/sudoers`:** Los permisos para utilizar `sudo` se gestionan centralizadamente en el archivo de configuración `/etc/sudoers`. Únicamente las cuentas declaradas en este archivo pueden ejecutar comandos elevados.

### Analogía de Ciberseguridad: La Llave Maestra del Hotel

```
┌──────────────────────────────────────────────────────────────────────────┐
│                             ANALOGÍA HOTEL                               │
├───────────────────────────────────┬──────────────────────────────────────┤
│ Llave Maestra                     │ Privilegio de Superusuario (root)    │
├───────────────────────────────────┼──────────────────────────────────────┤
│ Tarjeta de Identificación Conserje│ Autenticación de Usuario Sudo        │
├───────────────────────────────────┼──────────────────────────────────────┤
│ Registro de Accesos al Hotel      │ Logs de Auditoría de sudo            │
└───────────────────────────────────┴──────────────────────────────────────┘
```

Un conserje necesita la **llave maestra** para limpiar habitaciones, pero debe validar su tarjeta de identificación cada vez que la utiliza. Si un atacante roba la tarjeta y la llave maestra, obtiene acceso ilimitado a todas las habitaciones. Por ello, **`sudo` debe otorgarse únicamente a quienes lo necesiten estrictamente**.

## 2. Comandos de Administración de Usuarios con `sudo`

### `useradd` (Creación de Usuarios)

Crea una nueva cuenta de usuario en el sistema.

```bash
sudo useradd [opciones] [nombre_usuario]
```

| Opción | Tipo de Grupo | Ejemplo | Descripción |
| :---: | :--- | :--- | :--- |
| **`-g`** | **Grupo Primario** | `sudo useradd -g security fgarcia` | Asigna `security` como grupo principal por defecto. |
| **`-G`** | **Grupos Secundarios** | `sudo useradd -G finance,admin fgarcia` | Añade al usuario a los grupos suplementarios `finance` y `admin`. |

---

### `usermod` (Modificación de Cuentas Existentes)

Modifica las propiedades de un usuario previamente registrado.

| Opción | Función | Ejemplo de Uso | Descripción / Notas |
| :---: | :--- | :--- | :--- |
| **`-g`** | Cambiar Grupo Primario | `sudo usermod -g executive fgarcia` | Reemplaza el grupo principal por `executive`. |
| **`-a -G`** | **Añadir Grupo Secundario** | `sudo usermod -a -G marketing fgarcia` | **Añade** `marketing` a los grupos secundarios sin borrar los existentes. |
| **`-d`** | Directorio Personal | `sudo usermod -d /home/garcia_f fgarcia` | Cambia la ruta del directorio `$HOME` del usuario. |
| **`-l`** | Cambiar Username | `sudo usermod -l garcia_f fgarcia` | Modifica el nombre de usuario de inicio de sesión. |
| **`-L`** | **Bloquear Cuenta** (*Lock*) | `sudo usermod -L fgarcia` | Desactiva el inicio de sesión manteniendo sus archivos y permisos intactos. |

> [!WARNING]
> **Peligro con `-G` sin `-a`:** Si usa `usermod -G` sin incluir la opción `-a` (*append*), el sistema **eliminará al usuario de todos sus grupos secundarios previos** y solo lo dejará en los especificados. Siempre combine `-a -G`.

---

### `userdel` (Eliminación de Cuentas)

Borra una cuenta de usuario del sistema.

```bash
# Elimina el usuario pero conserva su directorio personal (/home)
sudo userdel fgarcia

# Elimina el usuario Y BORRA de forma permanente su directorio /home
sudo userdel -r fgarcia
```

> [!TIP]
> **Mejor Práctica en Ciberseguridad:** Cuando un empleado abandona la organización, es preferible deshabilitar la cuenta con **`usermod -L`** en lugar de eliminarla inmediatamente con `userdel -r`. Esto permite auditar la propiedad de sus archivos y transferir la custodia adecuadamente.

---

## 3. El Comando `chown` (Cambio de Propietario)

El comando **`chown`** (*Change Owner*) modifica el usuario propietario y/o el grupo propietario de un archivo o directorio.

```bash
# Cambiar solo el usuario propietario:
sudo chown fgarcia access.txt

# Cambiar solo el grupo propietario (requiere los dos puntos ':' prefijados):
sudo chown :security access.txt

# Cambiar usuario y grupo simultáneamente:
sudo chown fgarcia:security access.txt
```

---

## Puntos Clave

> [!IMPORTANT]
> * **Uso Responsable de `sudo`:** Otorga elevación de privilegios temporal y trazable. Evite iniciar sesión directamente como `root`.
> * **Gestión de Cuentas:** `useradd` crea usuarios, `usermod` modifica atributos y `userdel` elimina cuentas.
> * **Preservación con `-L`:** La opción `usermod -L` bloquea usuarios sin destruir sus archivos, facilitando la auditoría forense y traspaso de propiedad.
> * **Gestión de Propiedad (`chown`):** Permite reasignar el usuario propietario (`chown usuario`) o el grupo (`chown :grupo`).
