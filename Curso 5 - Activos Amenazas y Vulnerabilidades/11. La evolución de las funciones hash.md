# La Evolución de las Funciones Hash: Fundamentos, Resistencia a Colisiones y Almacenamiento Seguro de Contraseñas

En esta guía exhaustiva del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza en profundidad la teoría matemática y la evolución histórica de las **funciones hash criptográficas**, desde sus orígenes en **MD5** hasta la familia de algoritmos seguros **SHA-2** y **SHA-3**, el fenómeno crítico de las **colisiones de hash**, las amenazas de **Tablas Rainbow** (*Rainbow Tables*), y las técnicas defensivas avanzadas como el **Salting** (*salado criptográfico*) para el almacenamiento seguro de credenciales.

---

## 1. ¿Qué es una Función Hash Criptográfica?

Una **función hash** es un algoritmo matemático determinista que toma una entrada de datos de **cualquier tamaño y longitud** (desde una sola letra hasta un archivo ejecutable o base de datos de varios terabytes) y la transforma en una cadena alfanumérica de **longitud fija**, conocida como **valor hash**, **compendio** (*digest*) o **huella digital**.

```
ENTRADA DE TAMAÑO VARIABLE                   FUNCIÓN HASH             COMPENDIO FIJO (Digest)
┌───────────────────────────────┐          ┌──────────────┐          ┌───────────────────────┐
│ "Hola" (4 caracteres)         │ ───────► │              │ ───────► │ 4d186321c1a7f0f354b29 │ (256 bits)
├───────────────────────────────┤          │              │          ├───────────────────────┤
│ Contrato_Legal.pdf (50 MB)    │ ───────► │   SHA-256    │ ───────► │ 8f4b23a9e10c73210d76a │ (256 bits)
├───────────────────────────────┤          │  Algoritmo   │          ├───────────────────────┤
│ Sistema_Operativo.iso (4 GB)  │ ───────► │              │ ───────► │ 3e2918bbfa870c9154a32 │ (256 bits)
└───────────────────────────────┘          └──────────────┘          └───────────────────────┘
```

---

### Propiedades Fundamentales de una Función Hash Criptográfica

Para que una función hash sea considerada segura en ciberseguridad, debe cumplir de manera estricta con cinco propiedades esenciales:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   PROPIEDADES DE UN HASH CRIPTOGRÁFICO                   │
├──────────────────────────────────┬───────────────────────────────────────┤
│ Propiedad                        │ Explicación Técnica Detallada         │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 1. Salida de Longitud Fija       │ Independientemente de la cantidad de  │
│    (Fixed Output Size)           │ datos ingresados, el resultado siempre│
│                                  │ tiene exactamente el mismo número de  │
│                                  │ bits (ej. SHA-256 genera 256 bits).   │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 2. Unidireccionalidad            │ Es computacionalmente inviable        │
│    (One-Way Function / Pre-image)│ revertir el proceso. Dado un hash $h$,│
│                                  │ no se puede calcular la entrada $x$.  │
│                                  │ **Un hash NO se puede desencriptar.** │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 3. Determinismo Absoluto         │ La misma entrada exacta siempre       │
│    (Deterministic)               │ generará invariablemente el mismo hash│
│                                  │ en cualquier computadora del mundo.   │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 4. Efecto Avalancha              │ Cambiar un solo bit o carácter en la  │
│    (Avalanche Effect)            │ entrada provoca un cambio radical e   │
│                                  │ impredecible en todo el compendio.    │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 5. Resistencia a Colisiones      │ Debe ser matemáticamente casi         │
│    (Collision Resistance)        │ imposible encontrar dos entradas      │
│                                  │ distintas que generen el mismo hash.  │
└──────────────────────────────────┴───────────────────────────────────────┘
```

## 2. Aplicaciones Primarias del Hashing en Ciberseguridad

El hashing no se utiliza para ocultar mensajes que deban ser leídos posteriormente (para eso se utiliza el **cifrado**); se emplea para garantizar la **Integridad**, la **Autenticación** y el **No Repudio**:

```
┌────────────────────────────────────────────────────────┐
│                   APLICACIONES DEL HASHING             │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────┬────────────────┐
 ▼                ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ VERIFICACIÓN │ │ALMACENAMIENTO│ │    FIRMAS    │ │ ANÁLISIS     │
│ DE INTEGRIDAD│ │DE CONTRASEÑAS│ │  DIGITALES   │ │ FORENSE Y SOC│
├──────────────┤ ├──────────────┤ ├──────────────┤ ├──────────────┤
│ Comprobar si │ │ Guardar solo │ │ Garantizar   │ │ Identificar  │
│ un archivo o │ │ hashes en BD │ │ autenticidad │ │ malware por  │
│ software fue │ │ y no texto   │ │ y no repudio │ │ su hash en   │
│ alterado.    │ │ plano.       │ │ en PKI.      │ │ VirusTotal.  │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
```

1. **Verificación de Integridad de Archivos y Software:** Cuando un desarrollador publica un archivo de instalación (ej. `ubuntu.iso`), publica también su valor hash SHA-256. Al descargarlo, el usuario calcula el hash localmente; si coincide exactamente, se demuestra que el archivo no se corrompió ni fue infectado por un atacante durante la descarga.
2. **Autenticación y No Repudio (*Non-Repudiation*):** El no repudio es el concepto de que el emisor de un mensaje o transacción no puede negar la autoría o autenticidad de la información transmitida. Al combinar una función hash con una firma digital asimétrica, se crea una prueba legal y técnica vinculante.
3. **Identificación de Malware en Operaciones SOC:** Los analistas de seguridad utilizan los valores hash de archivos ejecutables sospechosos para consultar bases de datos globales de inteligencia de amenazas (como *VirusTotal* o *AlienVault OTX*) y determinar al instante si un archivo coincide con una cepa conocida de ransomware o troyano.

## 3. Orígenes Históricos y el Algoritmo MD5

Originalmente, las funciones hash se crearon en las primeras décadas de la informática como estructuras de datos (**Tablas Hash**) para indexar, ubicar y buscar registros en bases de datos con gran velocidad.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                 EVOLUCIÓN HISTÓRICA: MESSAGE DIGEST 5 (MD5)                  │
└──────────────────────────────────────────────────────────────────────────────┘

 1991: El profesor Ronald Rivest (co-creador de RSA en el MIT) desarrolla MD5.
  │
  ├─► Objetivo: Verificar la integridad de archivos transferidos por red.
  │
  ├─► Especificación: Convierte datos de cualquier tamaño en un valor de 128 bits.
  │
  └─► Representación: Cadena hexadecimal de 32 caracteres (ej: d41d8cd98f00b204e9800998ecf8427e).
```

### El Efecto Avalancha en MD5:
* **Entrada 1:** `"El veloz murcielago hindu"` ➔ `MD5: e2fc714c4727ee9395f324cd2e7f331f`
* **Entrada 2:** `"El veloz murcielago hindu."` (solo se añadió un punto final) ➔ `MD5: 56930d6b9d628876b6d5fb9ff2c8d234`
* Aunque la diferencia fue de un único carácter, el 100% del valor hash resultante cambió de forma impredecible.

## 4. El Problema de las Colisiones de Hash (*Hash Collisions*)

A pesar del éxito inicial de MD5, los investigadores de seguridad identificaron rápidamente su talón de Aquiles: **la vulnerabilidad a colisiones**.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   EL PRINCIPIO DEL PALOMAR Y LAS COLISIONES              │
├──────────────────────────────────────────────────────────────────────────┤
│ • Universo de Entradas: INFINITAS (Cualquier archivo, texto o combinación)│
│ • Universo de Salidas MD5: FINITO (2^128 combinaciones posibles)         │
│                                                                          │
│ ┌──────────────────────┐                    ┌──────────────────────────┐ │
│ │  Entrada A ("Doc1")  │ ─── Algoritmo ───► │                          │ │
│ └──────────────────────┘        MD5         │ Hash IDÉNTICO            │ │
│                                             │ "79054025255fb1a26e4bc"  │ │
│ ┌──────────────────────┐        MD5         │                          │ │
│ │ Entrada B ("Malware")│ ─── Algoritmo ───► │                          │ │
│ └──────────────────────┘                    └──────────────────────────┘ │
│                                             ⚠️ COLISIÓN DE HASH          │
└──────────────────────────────────────────────────────────────────────────┘
```

* **¿Qué es una Colisión de Hash?** Ocurre cuando **dos entradas completamente diferentes** ($Entrada_A \neq Entrada_B$) producen exactamente el **mismo valor hash** final ($Hash(Entrada_A) = Hash(Entrada_B)$).
* **Riesgo en Ciberseguridad:** Dado que los hashes se utilizan para autenticar identidades y firmas, una colisión equivale a **clonar la identidad digital** de un documento. Un atacante puede crear un documento malicioso o un contrato fraudulento diseñado especialmente para que arroje el mismo hash MD5 que un archivo legítimo y confiable.
* **Estado de MD5:** En 2004, un equipo de criptógrafos liderado por Xiaoyun Wang demostró que se podían generar colisiones prácticas en MD5 en cuestión de minutos. **MD5 está completamente roto criptográficamente y no debe utilizarse bajo ninguna circunstancia para seguridad.**

## 5. La Familia de Algoritmos Hash Seguros (SHA)

Para responder a la crisis de colisiones en MD5, el **Instituto Nacional de Estándares y Tecnología (NIST)** estandarizó la familia de algoritmos **SHA (*Secure Hash Algorithms*)**:

```
                                  FAMILIA DE ALGORITMOS SHA
                                             │
         ┌───────────────────────────────────┴───────────────────────────────────┐
         ▼                                                                       ▼
┌──────────────────┐                                                    ┌──────────────────┐
│      SHA-1       │                                                    │      SHA-2       │
├──────────────────┤                                                    ├──────────────────┤
│ • 160 bits       │                                                    │ • SHA-224        │
│ • 40 caracteres  │                                                    │ • SHA-256        │
│ • Roto en 2017   │                                                    │ • SHA-384        │
│   (SHAttered)    │                                                    │ • SHA-512        │
│ ❌ OBSOLETO      │                                                    │ ✅ ESTÁNDAR ORO  │
└──────────────────┘                                                    └──────────────────┘
```

---

### Análisis Detallado de Algoritmos SHA:

#### 1. SHA-1 (Secure Hash Algorithm 1)
* **Especificaciones:** Genera un compendio de **160 bits** (cadena hexadecimal de 40 caracteres).
* **Vulnerabilidad:** En 2017, investigadores de Google y CWI Amsterdam ejecutaron el ataque **SHAttered**, generando dos documentos PDF con contenidos visiblemente diferentes pero con el mismo hash SHA-1 exacto.
* **Estado:** El NIST y los principales navegadores web han retirado formalmente SHA-1. Está **deprecado e inseguro**.

#### 2. Familia SHA-2 (SHA-224, SHA-256, SHA-384, SHA-512)
* **Arquitectura:** Diseñada con estructuras matemáticas mucho más complejas y tamaños de bloque más amplios, eliminando las debilidades de SHA-1.
* **Variantes Principales:**
  * **SHA-256:** Genera compendios de **256 bits** (64 caracteres hexadecimales). Es el estándar de oro utilizado en certificados TLS/HTTPS, DNSSEC, almacenamiento de contraseñas y tecnologías de cadena de bloques (*blockchain*).
  * **SHA-512:** Genera compendios de **512 bits** (128 caracteres hexadecimales). Proporciona la máxima resistencia criptográfica para datos gubernamentales y militares.
* **Resistencia a Colisiones:** Inmune a ataques de colisión prácticos con la potencia de cómputo actual.

## 6. Almacenamiento Seguro de Contraseñas y Amenazas

### El Riesgo del Texto Plano frente a la Solución con Hash
Si una empresa almacena las contraseñas de sus usuarios en texto plano dentro de su base de datos, cualquier intrusión, inyección SQL o filtración expone de inmediato las credenciales de todos los clientes.

```
FLUJO SEGURO DE REGISTRO E INICIO DE SESIÓN
───────────────────────────────────────────────────────────────────────────────
1. REGISTRO DE USUARIO:
   Usuario escribe: "ClaveSecreta123" ──► Función SHA-256 ──► Almacena en BD: "5e884898da2804..."

2. INICIO DE SESIÓN:
   Usuario introduce: "ClaveSecreta123" ──► Función SHA-256 ──► Genera: "5e884898da2804..."
                                                                          │
                                                                   ¿Coincide con BD?
                                                                   ├── SÍ ──► ACCESO CONCEDIDO
                                                                   └── NO ──► ACCESO DENEGADO
```

> [!NOTE]
> El servidor **nunca necesita saber cuál es la contraseña real** en texto plano; solo necesita comparar si el hash generado en el login coincide con el hash guardado en el registro.

---

### Vectores de Ataque contra Hashes: Tablas Rainbow (*Rainbow Tables*)

Aunque una base de datos almacene solo hashes, los atacantes desarrollaron una técnica computacional conocida como **Tablas Rainbow**:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   FUNCIONAMIENTO DE UNA TABLA RAINBOW                    │
├──────────────────────────────────────────────────────────────────────────┤
│ Es un diccionario masivo precalculado de cientos de miles de millones de │
│ contraseñas comunes mapeadas contra sus respectivos valores hash.        │
│                                                                          │
│  TEXTO PLANO PRECALCULADO             HASH ASOCIADO (En la Tabla)        │
│  "123456"                 ◄────────►  "e10adc3949ba59abbe56e057f20f883e" │
│  "password"               ◄────────►  "5f4dcc3b5aa765d61d8327deb882cf99" │
│  "admin"                  ◄────────►  "21232f297a57a5a743894a0e4a801fc3" │
│                                                                          │
│ 1. Atacante roba la base de datos de hashes.                             │
│ 2. Realiza una búsqueda inversa instantánea en la Tabla Rainbow.         │
│ 3. Recupera la contraseña original en milisegundos sin calcular nada.   │
└──────────────────────────────────────────────────────────────────────────┘
```

## 7. La Defensa Definitiva: Salting (*Salado Criptográfico*)

Para neutralizar por completo las Tablas Rainbow y los ataques de diccionario paralelos, la industria implementó el **Salting** (*salado*).

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                     MECANISMO DE SALTING CRIPTOGRÁFICO                       │
└──────────────────────────────────────────────────────────────────────────────┘

 Contraseña Usuario:        "password"
 + Sal Aleatoria Única:     "x7$kL9#mP"  (Generada criptográficamente por usuario)
 ─────────────────────────────────────────────────────────────────────────────
 Entrada Combinada:         "passwordx7$kL9#mP"
            │
            ▼ Función Hash SHA-256
 Hash Salado Resultante:    "d3b07384d113edec49eaa6238ad5ff00..."
```

```
┌──────────────────────────────────────────────────────────────────────────┐
│            COMPARACIÓN: BASE DE DATOS SIN SAL VS. CON SAL                │
├──────────────────────────────────────────────────────────────────────────┤
│ BASE DE DATOS SIN SAL (Vulnerable a Rainbow Tables):                     │
│ • Usuario A ("password") ──► Hash: 5f4dcc3b5aa765d61d8327deb882cf99      │
│ • Usuario B ("password") ──► Hash: 5f4dcc3b5aa765d61d8327deb882cf99      │
│   (El atacante deduce al instante que ambos usuarios usan la misma clave)│
├──────────────────────────────────────────────────────────────────────────┤
│ BASE DE DATOS CON SAL (Inmune a Rainbow Tables):                         │
│ • Usuario A ("password" + Sal: "9f#1a") ──► Hash: a89c10d4e32156bb0...   │
│ • Usuario B ("password" + Sal: "k4$9z") ──► Hash: 7e31ff02a991823cd...   │
│   (Misma contraseña pero hashes 100% distintos; las Rainbow Tables fallan)│
└──────────────────────────────────────────────────────────────────────────┘
```

### Reglas Críticas del Salting:
1. **Unicidad:** La sal debe ser generada de forma aleatoria mediante un generador criptográficamente seguro (*CSPRNG*) y debe ser **única para cada usuario**.
2. **Almacenamiento:** La sal no es secreta; se almacena en texto plano en la base de datos junto al hash (el formato estándar suele ser `$algoritmo$sal$hash`).
3. **Efecto Defensivo:** Obliga al atacante a calcular una tabla rainbow individual y personalizada para cada usuario de la base de datos, haciendo que el tiempo de ataque pase de segundos a miles de años.

> [!TIP]
> **Evolución Moderna:** En la actualidad, para contraseñas se utilizan funciones de derivación de claves lentas (*Key Derivation Functions - KDF*) como **bcrypt**, **Argon2** o **PBKDF2**, las cuales incorporan salado automático y factores de costo (*work factor*) que ralentizan deliberadamente los cálculos para anular ataques masivos por GPUs.

## Puntos Clave para Exámenes y Práctica Profesional

> [!IMPORTANT]
> * **Función Unidireccional:** Un hash **no se desencripta jamás**. Transforma datos variables en una huella digital determinista de longitud fija.
> * **Integridad y No Repudio:** El hashing verifica que los archivos no hayan sido manipulados y valida firmas digitales.
> * **Colisión de Hash:** Ocurre cuando dos entradas diferentes producen el mismo hash. Es la razón por la que **MD5** y **SHA-1** están formalmente rotos y deprecados.
> * **Estándares Actuales:** **SHA-256** y **SHA-512** son los estándares aprobados por el NIST con resistencia total a colisiones prácticas.
> * **Tablas Rainbow:** Archivos de hashes precalculados para descifrar contraseñas comunes rápidamente.
> * **Salting:** Añadir una cadena aleatoria única a la contraseña antes de aplicar el hash destruye la efectividad de las Tablas Rainbow y garantiza hashes únicos para contraseñas idénticas.
