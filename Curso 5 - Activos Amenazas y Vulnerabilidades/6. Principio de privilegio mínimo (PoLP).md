# Principio de Privilegio Mínimo (PoLP)

En esta lectura del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza el **Principio de Privilegio Mínimo** (*Principle of Least Privilege - PoLP*), su rol en la mitigación de riesgos de seguridad, la tipología de cuentas en servicios de directorio, y los tres tipos de auditorías indispensables para prevenir la **acumulación de privilegios** (*Privilege Creep*).

---

## 1. ¿Qué es el Principio de Privilegio Mínimo (PoLP)?

El **Principio de Privilegio Mínimo (*PoLP*)** establece que a cualquier entidad (usuario, dispositivo, aplicación o proceso) se le debe conceder **únicamente el nivel mínimo indispensable de acceso y autorización** estrictamente necesario para desempeñar su función legítima.

```
┌────────────────────────────────────────────────────────┐
│             PRINCIPIO DE PRIVILEGIO MÍNIMO             │
└──────────────────────────┬─────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          ▼                                 ▼
┌──────────────────┐               ┌──────────────────┐
│ SIN PoLP (Riesgo)│               │ CON PoLP (Seguro)│
├──────────────────┤               ├──────────────────┤
│ ❌ Acceso total  │               │ ✅ Acceso acotado│
│ ❌ Modificación  │               │ ✅ Datos blindados│
│    accidental    │               │ ✅ Menor impacto │
│ ❌ Mayor impacto │               │    ante brechas  │
│    de brechas    │               │                  │
└──────────────────┘               └──────────────────┘
```

### Beneficios Clave en la Mitigación del Riesgo:
1. **Contención de Brechas de Datos:** Si una cuenta estándar es comprometida por un atacante, el daño queda restringido únicamente a los recursos asignados a ese usuario.
2. **Prevención de Errores Humanos:** Evita alteraciones, manipulaciones indebidas o borrados accidentales de bases de datos y configuraciones críticas.
3. **Optimización de la Auditoría:** Facilita el monitoreo y la trazabilidad forense al vincular acciones específicas con roles claramente definidos.

> [!NOTE]
> **Separación de Funciones (*Separation of Duties - SoD*):** Concepto estrechamente ligado a PoLP que divide las responsabilidades críticas entre múltiples usuarios (ej. quien solicita una compra no puede ser quien la autorice) para evitar que una sola persona tenga control absoluto sobre procesos vitales.

## 2. Tipología de Cuentas en Servicios de Directorio

La gestión centralizada de identidades se administra mediante **Servicios de Directorio** (como *Active Directory*, *LDAP* o *Microsoft Entra ID*), clasificando las cuentas en cuatro categorías principales:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                       TIPOS DE CUENTAS DE USUARIO                        │
├───────────────────┬──────────────────────────────┬───────────────────────┤
│    DE INVITADO    │         ESTÁNDAR             │     DE SERVICIO       │
│      (Guest)      │          (User)              │      (Service)        │
├───────────────────┼──────────────────────────────┼───────────────────────┤
│ Acceso temporal   │ Asignadas a empleados según  │ Utilizadas por apps y │
│ y restringido para│ sus funciones laborales      │ procesos para         │
│ contratistas o    │ cotidianas (sin permisos     │ interactuar con la    │
│ socios externos.  │ administrativos).            │ red automáticamente.  │
└───────────────────┴──────────────────────────────┴───────────────────────┘
                                      │
                                      ▼
                        ┌───────────────────────────┐
                        │      CON PRIVILEGIOS      │
                        │        (Privileged)       │
                        ├───────────────────────────┤
                        │ Permisos elevados y de    │
                        │ administración (root,     │
                        │ domain admin, sysadmin).  │
                        └───────────────────────────┘
```

### Características y Mejores Prácticas:

| Tipo de Cuenta | Destinatario | Nivel de Acceso | Recomendación de Seguridad |
| :--- | :--- | :--- | :--- |
| **Invitado (*Guest*)** | Clientes, contratistas, consultores temporales. | Mínimo estricto y temporal. | Establecer fechas de caducidad automática y acceso aislado en DMZ o VLAN de invitados. |
| **Usuario (*Standard User*)** | Empleados de plantilla. | Específico para su puesto. | Nunca otorgar permisos de administrador local en estaciones de trabajo. |
| **Servicio (*Service Account*)** | Aplicaciones, daemons, scripts, APIs. | Acceso programático a BD/red. | Deshabilitar el inicio de sesión interactivo y rotar credenciales periódicamente. |
| **Privilegiada (*Privileged*)** | Administradores de sistemas y seguridad. | Control total / Elevado. | Requerir MFA obligatorio, estaciones de trabajo dedicadas (PAW) y uso Just-In-Time (JIT). |

## 3. Auditoría de Cuentas y Prevención del *Privilege Creep*

Establecer privilegios mínimos al inicio es insuficiente si no se realizan revisiones continuas.

```
                          ACUMULACIÓN DE PRIVILEGIOS (Privilege Creep)
┌──────────────────┐       Promoción / Cambio       ┌──────────────────┐       Nuevo Rol        ┌──────────────────┐
│   Rol Inicial    │ ─────────────────────────────► │   Segundo Rol    │ ─────────────────────► │   Tercer Rol     │
│   (Ventas: R1)   │                                │ (Soporte: R1+R2) │                        │ (Admin: R1+R2+R3)│
└──────────────────┘                                └──────────────────┘                        └──────────────────┘
                                                                                                  ⚠️ EXCESO DE ACCESOS
```

> [!WARNING]
> **Acumulación de Privilegios (*Privilege Creep*):** Fenómeno donde un empleado acumula permisos residuales de puestos anteriores a medida que recibe ascensos o cambia de departamento, violando el principio de privilegio mínimo.

### Los Tres Enfoques de Auditoría de Cuentas:

```
┌────────────────────────────────────────────────────────┐
│                   TIPOS DE AUDITORÍAS                  │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────────────┐
 ▼                ▼                        ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│  AUDITORÍAS  │ │  AUDITORÍAS  │ │  AUDITORÍAS DE   │
│   DE USO     │ │DE PRIVILEGIOS│ │CAMBIOS DE CUENTAS│
├──────────────┤ ├──────────────┤ ├──────────────────┤
│ ¿A qué entra │ │ ¿Los permisos│ │ Monitoreo de logs│
│ y qué hace el│ │ corresponden │ │ de cambios de pwd│
│ usuario?     │ │ a su rol?    │ │ y altas sospech. │
└──────────────┘ └──────────────┘ └──────────────────┘
```

1. **Auditorías de Uso (*Usage Audits*):**
   * **Objetivo:** Analizar qué recursos abre el usuario y con qué frecuencia los utiliza.
   * **Beneficio:** Permite revocar licencias y permisos sobre aplicaciones o carpetas que llevan meses inactivas.

2. **Auditorías de Privilegios (*Privilege Audits*):**
   * **Objetivo:** Cotejar la descripción del puesto actual de un trabajador con su matriz de accesos en el servicio de directorio.
   * **Beneficio:** Erradica el *Privilege Creep* al retirar accesos obsoletos tras traslados de equipo o promociones.

3. **Auditorías de Cambios en Cuentas (*Account Change Audits*):**
   * **Objetivo:** Inspeccionar los registros de eventos (*logs*) del directorio de identidades.
   * **Beneficio:** Detecta actividades sospechosas o anómalas (ej. múltiples intentos fallidos de cambio de contraseña, escalada de privilegios no autorizada o creación de usuarios fuera de horario laboral).

---

## Puntos Clave

> [!IMPORTANT]
> * **Fundamento de PoLP:** Conceder únicamente el acceso necesario durante el tiempo estrictamente requerido para realizar la tarea (*Just-In-Time*).
> * **Gestión por Perfiles:** Clasificar cuentas en Invitados, Usuarios Estándar, Servicios y Cuentas Privilegiadas para definir líneas base de seguridad.
> * **Riesgo del *Privilege Creep*:** Los permisos deben revocarse activamente cuando cambian las funciones laborales del personal.
> * **Auditoría Continua:** Implementar auditorías periódicas de **Uso**, **Privilegios** y **Cambios de Cuentas** garantiza la integridad de los controles de acceso en la organización.
