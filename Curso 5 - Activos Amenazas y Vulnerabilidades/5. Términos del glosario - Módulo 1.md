# Términos del Glosario — Módulo 1 (Curso 5)

Este documento recopila, clasifica y define los conceptos fundamentales del **Módulo 1: Activos, Amenazas y Vulnerabilidades** del Curso 5 de la certificación Google Cybersecurity.

---

## 1. Gestión y Clasificación de Activos (*Asset Management*)

```
┌────────────────────────────────────────────────────────┐
│                   CICLO DE GESTIÓN DE ACTIVOS          │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────┬────────────────┐
 ▼                ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│    ACTIVO    │ │  INVENTARIO  │ │ CLASIFICACIÓN│ │   GESTIÓN    │
│   (Asset)    │ │  (Inventory) │ │(Classification││ (Management) │
├──────────────┤ ├──────────────┤ ├──────────────┤ ├──────────────┤
│ Recurso con  │ │ Catálogo     │ │ Etiquetado   │ │ Supervisión  │
│ valor para el│ │ centralizado │ │ por valor y  │ │ continua de  │
│ negocio.     │ │ de activos.  │ │ sensibilidad.│ │ riesgos.     │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
```

* **Activo (*Asset*):** Cualquier artículo, dato, sistema o recurso tangible o intangible que posee valor económico, operativo o estratégico para una organización.
* **Inventario de activos (*Asset Inventory*):** Catálogo exhaustivo y actualizado de todos los recursos y sistemas que deben ser protegidos y monitoreados.
* **Clasificación de activos (*Asset Classification*):** Práctica sistemática de asignar etiquetas de sensibilidad e importancia a los activos (ej. Restringido, Confidencial, Uso Interno, Público) para definir los controles de seguridad pertinentes.
* **Gestión de activos (*Asset Management*):** Proceso continuo de identificación, seguimiento, mantenimiento y evaluación de riesgos sobre los activos durante todo su ciclo de vida.

## 2. Estados de los Datos y Seguridad de la Información (*InfoSec*)

Los datos existen en tres estados dinámicos que requieren controles de protección diferenciados:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         LOS TRES ESTADOS DE LOS DATOS                    │
├───────────────────────┬──────────────────────────┬───────────────────────┤
│    DATOS EN REPOSO    │     DATOS EN TRÁNSITO    │     DATOS EN USO      │
│   (Data at Rest)      │   (Data in Transit)      │    (Data in Use)      │
├───────────────────────┼──────────────────────────┼───────────────────────┤
│ Datos almacenados en  │ Datos viajando a través  │ Datos cargados en     │
│ discos, bases de datos│ de redes locales o       │ memoria RAM, caché o  │
│ o copias de seguridad.│ internet (paquetes IP).  │ procesadores activos. │
│                       │                          │                       │
│ Control: Cifrado AES. │ Control: TLS/HTTPS/VPN.  │ Control: Enclaves/IAM.│
└───────────────────────┴──────────────────────────┴───────────────────────┘
```

* **Datos (*Data*):** Información en formato digital que es traducida, procesada, transmitida o almacenada por un sistema informático.
* **Datos en reposo (*Data at Rest*):** Información almacenada en medios persistentes (discos duros, bases de datos, almacenamiento en la nube o cintas) a la que no se está accediendo activamente.
* **Datos en tránsito (*Data in Transit / Motion*):** Información que se desplaza de un nodo a otro a través de redes públicas o privadas (correo electrónico, transferencias API, tráfico web).
* **Datos en uso (*Data in Use*):** Información que está siendo procesada, leída o actualizada activamente en memoria por usuarios, aplicaciones o hilos de CPU.
* **Seguridad de la información (*InfoSec - Information Security*):** Práctica integral y metodológica dedicada a preservar la Confidencialidad, Integridad y Disponibilidad de los datos en todos sus estados frente a accesos o manipulaciones no autorizadas.

## 3. Gobernanza, Marcos y Cumplimiento

```
┌────────────────────────────────────────────────────────┐
│               JERARQUÍA DE GOBERNANZA DE SEGURIDAD     │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
               ┌───────────────────────┐
               │     REGULACIONES      │ ➔ Leyes obligatorias externas (GDPR, HIPAA, PCI)
               └───────────┬───────────┘
                           │
                           ▼
               ┌───────────────────────┐
               │        MARCOS         │ ➔ Guías voluntarias de mejores prácticas (NIST CSF)
               └───────────┬───────────┘
                           │
                           ▼
               ┌───────────────────────┐
               │       POLÍTICAS       │ ➔ Reglas internas de alto nivel de la empresa
               └───────────┬───────────┘
                           │
                           ▼
               ┌───────────────────────┐
               │      ESTÁNDARES       │ ➔ Requisitos técnicos obligatorios de soporte
               └───────────┬───────────┘
                           │
                           ▼
               ┌───────────────────────┐
               │    PROCEDIMIENTOS     │ ➔ Instrucciones operativas paso a paso
               └───────────────────────┘
```

* **Marco de Ciberseguridad del NIST (*NIST CSF - Cybersecurity Framework*):** Conjunto voluntario de normas, directrices y mejores prácticas desarrollado por el NIST para estructurar, evaluar y madurar la gestión del riesgo cibernético.
* **Cumplimiento normativo (*Compliance*):** Proceso de verificación y adhesión formal a estándares y políticas internas, así como a leyes y regulaciones externas aplicables.
* **Regulaciones (*Regulations*):** Normativas de obligado cumplimiento legal impuestas por gobiernos o autoridades regulatorias (ej. HIPAA, PCI DSS, GDPR).
* **Políticas (*Policies*):** Declaraciones formales de alto nivel emitidas por la dirección que dictan las reglas organizacionales para reducir riesgos y salvaguardar la información.
* **Estándares (*Standards*):** Documentos y especificaciones técnicas que establecen requisitos obligatorios y uniformes para implementar las políticas de seguridad.
* **Procedimientos (*Procedures*):** Guías operativas detalladas paso a paso para ejecutar tareas y protocolos de seguridad específicos (ej. procedimiento de alta de usuarios o respuesta a incidentes).

## 4. La Tríada del Riesgo de Seguridad

| Término | Definición Técnica | Pregunta Clave de Análisis |
| :--- | :--- | :--- |
| **Amenaza (*Threat*)** | Cualquier circunstancia, agente o evento potencial capaz de causar daño o impacto adverso sobre un activo. | *¿Qué o quién puede causarnos daño?* |
| **Vulnerabilidad (*Vulnerability*)** | Debilidad o fallo en el diseño, configuración o implementación que puede ser explotado por una amenaza. | *¿Cuál es nuestro punto débil?* |
| **Riesgo (*Risk*)** | Medida cuantitativa o cualitativa del impacto adverso potencial sobre un activo ante la materialización de una amenaza explotando una debilidad. | *¿Qué tan probable y grave será el daño?* |

> [!IMPORTANT]
> **Fórmula Operativa:** $\text{Riesgo} = \text{Probabilidad} \times \text{Impacto}$. El objetivo primario de la ciberseguridad es mitigar vulnerabilidades e implementar salvaguardas para reducir la probabilidad de que las amenazas se conviertan en incidentes reales.
