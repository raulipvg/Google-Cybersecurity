# La Emergencia de la Seguridad en la Nube

En esta lectura del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza la transformación de la infraestructura empresarial impulsada por la **computación en la nube**, los tres modelos de servicio fundamentales (**SaaS**, **PaaS**, **IaaS**), el **Modelo de Responsabilidad Compartida**, y los principales retos de ciberseguridad que enfrentan los entornos multi-inquilino (*multi-tenant*).

---

## 1. ¿Qué es la Computación en la Nube?

El **Centro Nacional de Ciberseguridad del Reino Unido (NCSC)** define la computación en la nube como:
> *"Un servicio a la carta (bajo demanda), masivamente escalable, alojado en una infraestructura compartida, accesible a través de Internet."*

```
┌────────────────────────────────────────────────────────┐
│             EVOLUCIÓN DE LA INFRAESTRUCTURA            │
└──────────────────────────┬─────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          ▼                                 ▼
┌──────────────────┐               ┌──────────────────┐
│   ON-PREMISES    │               │  NUBE (CLOUD)    │
├──────────────────┤               ├──────────────────┤
│ • Servidores     │               │ • Bajo demanda   │
│   propios        │               │ • Escalabilidad  │
│ • Alto costo CapEx│              │   inmediata      │
│ • Mantenimiento  │               │ • Costos OpEx    │
│   100% interno   │               │ • Multi-tenant   │
└──────────────────┘               └──────────────────┘
```

* **Beneficios de Negocio:** Permite desplegar servicios globales en minutos, reducir costos de hardware físico y escalar recursos elásticamente según la demanda.
* **Impacto en Seguridad:** El perímetro de red corporativo tradicional desaparece, desplazando el enfoque de seguridad hacia la **Gestión de Identidades y Accesos (IAM)** y la **protección del dato**.

## 2. Modelos de Servicio en la Nube (IaaS, PaaS, SaaS)

```
┌──────────────────────────────────────────────────────────────────────────┐
│                     MODELOS DE SERVICIO EN LA NUBE                       │
├───────────────────┬──────────────────────────────┬───────────────────────┤
│   IaaS (Infra.)   │        PaaS (Plataforma)     │     SaaS (Software)   │
├───────────────────┼──────────────────────────────┼───────────────────────┤
│ Servidores, redes │ Entornos de desarrollo,      │ Aplicaciones completas│
│ y almacenamiento  │ runtimes y bases de datos    │ accesibles vía web    │
│ virtuales.        │ gestionadas.                 │ o navegador.          │
│                   │                              │                       │
│ Ej: AWS EC2, GCP  │ Ej: Google App Engine,       │ Ej: Gmail, Slack,     │
│ Compute Engine    │ Heroku, AWS Elastic Beanstalk│ Zoom, Microsoft 365   │
└───────────────────┴──────────────────────────────┴───────────────────────┘
```

### A. Software como Servicio (SaaS - *Software as a Service*)
* **Alcance:** Aplicaciones front-end listas para el usuario final.
* **Gestión:** El proveedor de la nube (*Cloud Service Provider - CSP*) gestiona y mantiene toda la infraestructura subyacente, el sistema operativo, los parches y el código.
* **Ejemplos:** Gmail, Slack, Zoom, Google Workspace, Salesforce.

### B. Plataforma como Servicio (PaaS - *Platform as a Service*)
* **Alcance:** Herramientas y entornos de ejecución para desarrolladores.
* **Gestión:** El cliente programa y administra sus aplicaciones y datos; el proveedor gestiona el hardware, sistema operativo, frameworks y middleware.
* **Ejemplos:** Google App Engine, Heroku, VMware Cloud Foundry, AWS Elastic Beanstalk.

### C. Infraestructura como Servicio (IaaS - *Infrastructure as a Service*)
* **Alcance:** Recursos fundamentales de computación (máquinas virtuales, almacenamiento en bloque/objeto, routers y firewalls virtuales).
* **Gestión:** El cliente tiene control sobre el sistema operativo, configuración de red, parches y software instalado; el proveedor solo mantiene la infraestructura física y el hipervisor.
* **Ejemplos:** Google Cloud Platform (GCP), Microsoft Azure, Amazon Web Services (AWS).

## 3. El Modelo de Responsabilidad Compartida (*Shared Responsibility Model*)

A diferencia del entorno tradicional *On-Premises* (donde la organización es responsable del 100% de la pila tecnológica), en la nube la seguridad se divide entre el **proveedor** y el **cliente**:

```
CAPAS DE LA PILA          ON-PREMISES        IaaS             PaaS             SaaS
──────────────────────────────────────────────────────────────────────────────────────
Datos y Clasificación      [ CLIENTE ]    [ CLIENTE ]      [ CLIENTE ]      [ CLIENTE ]
Identidad y Accesos (IAM)  [ CLIENTE ]    [ CLIENTE ]      [ CLIENTE ]      [ CLIENTE ]
Aplicaciones               [ CLIENTE ]    [ CLIENTE ]      [ CLIENTE ]      ( PROVEEDOR )
Sistema Operativo / OS     [ CLIENTE ]    [ CLIENTE ]      ( PROVEEDOR )    ( PROVEEDOR )
Red y Virtualización       [ CLIENTE ]    ( PROVEEDOR )    ( PROVEEDOR )    ( PROVEEDOR )
Infraestructura Física     [ CLIENTE ]    ( PROVEEDOR )    ( PROVEEDOR )    ( PROVEEDOR )
```

### Responsabilidades Clave Universales del Cliente:
1. **Gestión de Identidades y Accesos (IAM):** Configuración de roles de privilegios mínimos (*RBAC*), autenticación multifactor (*MFA*) y revocación de accesos.
2. **Configuración de Recursos:** Aseguramiento (*hardening*) de instancias, reglas de firewall (*Security Groups*) y políticas de cifrado.
3. **Gobierno y Protección de Datos:** Clasificación, encriptación en reposo/tránsito y políticas de respaldo.

## 4. Retos Críticos de Seguridad en la Nube

```
┌────────────────────────────────────────────────────────┐
│             RETOS DE CIBERSEGURIDAD EN CLOUD           │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────┬────────────────┐
 ▼                ▼                ▼                ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│DESCONFIGURAC.│ │ VISIBILIDAD  │ │ CUMPLIMIENTO │ │ RIESGO MULTI-│
│(Misconfigs)  │ │  DE ACCESOS  │ │ (Compliance) │ │   TENANT     │
├──────────────┤ ├──────────────┤ ├──────────────┤ ├──────────────┤
│ Cubos S3 o   │ │ Dificultad   │ │ Exigencias de│ │ Riesgo de    │
│ BD expuestas │ │ para auditar │ │ HIPAA, GDPR, │ │ aislamiento  │
│ a internet.  │ │ llamadas API.│ │ PCI DSS.     │ │ entre clientes│
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
```

1. **Mala Configuración (*Cloud Misconfiguration*):** Es la causa número uno de incidentes en la nube (ej. almacenamiento en la nube sin autenticación, contraseñas predeterminadas o puertos de administración `22`/`3389` abiertos al mundo).
2. **Monitoreo y Detección de Amenazas:** El tráfico interno de la nube y las llamadas a APIs requieren herramientas avanzadas de registro (*CloudTrail*, *Cloud Audit Logs*) y visibilidad centralizada (*SIEM/SOAR*).
3. **Cumplimiento Normativo (*Compliance*):** Obligación de demostrar controles efectivos en auditorías regulatorias (**HIPAA**, **PCI DSS**, **GDPR**, **SOC 2**).

## 5. Recursos y Certificaciones del Sector

* **[NCSC UK - Cloud Security Guidance](https://www.ncsc.gov.uk/collection/cloud/understanding-cloud-services/cloud-security-shared-responsibility-model):** Marco integral para seleccionar y configurar servicios según el Modelo de Responsabilidad Compartida.
* **[Cloud Security Alliance® (CSA)](https://cloudsecurityalliance.org/):** Organización global líder en estándares de seguridad en la nube (desarrolladores de la matriz *Cloud Controls Matrix - CCM* y la certificación *CCSK*).
* **[CompTIA Cloud+](https://www.comptia.org/blog/your-next-move-cloud-security-specialist):** Certificación profesional que valida habilidades en arquitectura y seguridad multi-nube.

## Puntos Clave

> [!IMPORTANT]
> * **Servicios Principales:** **IaaS** proporciona hardware virtual; **PaaS** ofrece plataformas de desarrollo; **SaaS** entrega aplicaciones completas.
> * **Modelo de Responsabilidad Compartida:** El proveedor protege la infraestructura *de* la nube; el cliente protege todo lo que configura e introduce *en* la nube.
> * **Mala Configuración:** Constituye el vector de ataque más explotado en infraestructuras *Cloud-Native*.
> * **Competencia de Alta Demanda:** La especialización en seguridad de la nube es una de las habilidades más solicitadas y con mayor crecimiento en el mercado laboral de ciberseguridad.
