# Enfoques para la Exploración de Vulnerabilidades: Metodologías, Tipologías de Escaneo y Análisis por Capas

En esta guía exhaustiva del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza en profundidad la **exploración de vulnerabilidades** (*Vulnerability Scanning*), la evaluación de las **cinco capas de la superficie de ataque** en una estrategia de **Defensa en Profundidad**, los tres ejes comparativos de escaneo (**Externo vs. Interno**, **Autenticado vs. No Autenticado**, **Limitado vs. Exhaustivo**), la importancia del **escaneo de descubrimiento previo**, y las principales herramientas del sector (**Nessus**, **OpenVAS**, **Qualys**, **Nmap**).

---

## 1. ¿Qué es un Escáner de Vulnerabilidades?

Un **escáner de vulnerabilidades** es una herramienta de software automatizada que sondea hosts, redes y aplicaciones para identificar debilidades de seguridad, configuraciones erróneas, servicios innecesarios abiertos y software desactualizado, comparando los hallazgos con bases de datos globales de vulnerabilidades (**CVE / NVD / OVAL**).

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   EVALUACIÓN DE VULNERABILIDADES VS. PENTESTING          │
├─────────────────────────────────────┬────────────────────────────────────┤
│   EVALUACIÓN DE VULNERABILIDADES    │       PRUEBAS DE PENETRACIÓN       │
│      (Vulnerability Assessment)     │        (Penetration Testing)       │
├─────────────────────────────────────┼────────────────────────────────────┤
│ • Proceso AUTOMATIZADO y continuo.  │ • Proceso MANUAL y simulado.       │
│ • Identifica, clasifica y reporta   │ • EXPLOTA activamente los fallos   │
│   debilidades sin dañarlas.         │   para medir el impacto real.      │
│ • Amplitud: Analiza TODA la red.    │ • Profundidad: Busca un objetivo.  │
│ • No intrusivo por diseño.          │ • Intrusivo y controlado.          │
└─────────────────────────────────────┴────────────────────────────────────┘
```

> [!NOTE]
> **Naturaleza No Intrusiva:** Los escáneres de vulnerabilidades están diseñados para no explotar las fallas ni alterar los datos del sistema; sin embargo, escaneos excesivamente agresivos pueden saturar el ancho de banda de red o colapsar temporalmente servicios *legacy* frágiles.

## 2. Las Cinco Capas de la Superficie de Ataque (Defensa en Profundidad)

Un escaneo exhaustivo no se limita a revisar un solo servidor; evalúa de manera integral las cinco capas que componen la infraestructura organizacional:

```
                                  SUPERFICIE DE ATAQUE (Defensa en Profundidad)
                                                     │
         ┌──────────────────┬────────────────────────┼────────────────────────┬──────────────────┐
         ▼                  ▼                        ▼                        ▼                  ▼
┌──────────────────┐ ┌──────────────┐      ┌──────────────────┐      ┌──────────────────┐ ┌──────────────┐
│  1. PERÍMETRO    │ │  2. RED      │      │  3. PUNTO FINAL  │      │  4. APLICACIÓN   │ │   5. DATOS   │
│   (Perimeter)    │ │  (Network)   │      │    (Endpoint)    │      │  (Application)   │ │    (Data)    │
├──────────────────┤ ├──────────────┤      ├──────────────────┤      ├──────────────────┤ ├──────────────┤
│ • Firewalls ext. │ │ • Switches   │      │ • Laptops / PCs  │      │ • Software web   │ │ • BD SQL/Cloud │
│ • Portales VPN   │ │ • VLANs      │      │ • Servidores OS  │      │ • APIs / Microserv││ • Cifrado      │
│ • Autenticación  │ │ • Enrutadores│      │ • Parches faltan.│      │ • Lógica negocio │ │ • Permisos ACL │
└──────────────────┘ └──────────────┘      └──────────────────┘      └──────────────────┘ └──────────────┘
```

| Capa Evaluada | Alcance del Escaneo | Ejemplos de Vulnerabilidades Detectadas |
| :--- | :--- | :--- |
| **1. Perímetro** | Sistemas y servicios expuestos directamente a Internet. | Puertos de administración (`SSH 22`, `RDP 3389`) abiertos al mundo, certificados SSL/TLS caducados o cifrados débiles. |
| **2. Red** | Infraestructura de comunicaciones interna y segmentación. | Configuraciones inseguras en switches/routers, protocolos no cifrados (`Telnet`, `HTTP`), fallos de aislamiento entre VLANs. |
| **3. Punto Final (*Endpoint*)** | Estaciones de trabajo, laptops y servidores corporativos. | Sistemas operativos sin actualizar (falta de parches de Windows/Linux), software vulnerable instalado, servicios innecesarios activos. |
| **4. Aplicación** | Software web, microservicios y portales de usuario. | Errores de codificación (OWASP Top 10: Inyecciones SQL, XSS, autenticación rota, dependencias vulnerables). |
| **5. Datos** | Repositorios de almacenamiento y bases de datos. | Carpetas compartidas en red (SMB/NFS) accesibles sin contraseña, bases de datos sin cifrado en reposo o permisos excesivos. |

## 3. Tipologías y Enfoques de Escaneo de Vulnerabilidades

Las organizaciones combinan diferentes modalidades de escaneo para modelar con precisión los distintos vectores que podría aprovechar un actor de amenaza:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   LOS TRES EJES DE EXPLORACIÓN DE SEGURIDAD              │
├──────────────────────────────────┬───────────────────────────────────────┤
│ Eje de Clasificación             │ Modalidades Comparadas                │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 1. Origen del Sondeo             │ Escaneo Externo vs. Escaneo Interno   │
├──────────────────────────────────┼───────────────────────────────────────┤
│ 2. Nivel de Acceso / Privilegios │ Escaneo Autenticado vs. No Autenticado│
├──────────────────────────────────┼───────────────────────────────────────┤
│ 3. Alcance y Profundidad         │ Escaneo Limitado vs. Exhaustivo       │
└──────────────────────────────────┴───────────────────────────────────────┘
```

---

### A. Escaneo Externo frente a Escaneo Interno

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    ARQUITECTURA: ESCANEO EXTERNO VS. INTERNO                 │
└──────────────────────────────────────────────────────────────────────────────┘

     INTERNET                                    RED CORPORATIVA INTERNA (LAN)
        │                                                     │
 ┌──────────────┐     ┌──────────────┐     ┌──────────────┐   │   ┌──────────────┐
 │ ESCÁNER EXT. │ ──► │ FIREWALL DMZ │ ──► │ SERVIDOR WEB │   │   │ ESTACIONES   │
 └──────────────┘     └──────────────┘     └──────────────┘   │   │ DE TRABAJO   │
 (Simula atacante                          (Expuesto a Web)   │   └──────┬───────┘
  remoto exterior)                                            │          │
                                                              │          ▼
                                                       ┌──────────────┐ ┌──────────────┐
                                                       │ ESCÁNER INT. │─►│ BASE DATOS   │
                                                       └──────────────┘ └──────────────┘
                                                       (Simula atacante  (Recurso crítico
                                                        infiltrado/insider) no expuesto)
```

* **Escaneo Externo (*External Scan*):**
  * **Perspectiva:** Simula la visión de un ciberatacante remoto situado en Internet sin acceso previo a la red corporativa.
  * **Objetivo:** Auditar la capa perimetral, sitios web públicos, firewalls de borde y servicios en la DMZ para detectar puertos accesibles y servicios expuestos.
* **Escaneo Interno (*Internal Scan*):**
  * **Perspectiva:** Simula la posición de un empleado malicioso (*Insider Threat*) o de un atacante que ya logró comprometer un equipo inicial mediante phishing.
  * **Objetivo:** Analizar la red interna para descubrir debilidades que permitan **movimientos laterales**, escalada de privilegios y acceso a bases de datos confidenciales.

---

### B. Escaneo Autenticado frente a Escaneo No Autenticado

```
┌──────────────────────────────────────────────────────────────────────────┐
│              COMPARATIVA: ESCANEO AUTENTICADO VS. NO AUTENTICADO         │
├─────────────────────────────────────┬────────────────────────────────────┤
│ ESCANEO AUTENTICADO (Credentialed)  │ ESCANEO NO AUTENTICADO (Black-Box) │
├─────────────────────────────────────┼────────────────────────────────────┤
│ • El escáner utiliza credenciales   │ • El escáner NO dispone de claves; │
│   válidas (Usuario o Administrador).│   solo sondea desde el exterior.   │
│ • Inspecciona registros del SO,     │ • Solo detecta banners de red y    │
│   parches instalados y configs.     │   puertos abiertos visibles.       │
│ • Tasa mínima de FALSOS POSITIVOS.  │ • Puede generar falsos positivos   │
│ • Máxima visibilidad profunda.      │   al basarse solo en respuestas.   │
└─────────────────────────────────────┴────────────────────────────────────┘
```

* **Escaneo Autenticado (*Credentialed Scan*):** El escáner inicia sesión formalmente en el sistema operativo mediante SSH (Linux) o WinRM/SMB (Windows). Puede auditar versiones exactas de librerías DLL, claves del registro, permisos locales de usuarios y políticas de contraseñas.
* **Escaneo No Autenticado (*Non-Credentialed Scan*):** Simula a un intruso sin credenciales. Evalúa si un servicio expone versiones vulnerables en sus banners de respuesta o si permite acceso anónimo a recursos compartidos.

---

### C. Escaneo Limitado frente a Escaneo Exhaustivo y el Rol del Descubrimiento

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    SECUENCIA RECOMENDADA DE EXPLORACIÓN                      │
└──────────────────────────────────────────────────────────────────────────────┘

 1. ESCANEO DE DESCUBRIMIENTO ➔ Barrido rápido de red (Ping sweep / SYN scan)
    (Discovery Scan)            para identificar qué IPs y hosts están vivos.
                                                  │
                                                  ▼
 2. ESCANEO LIMITADO (Targeted) ➔ Sondeo específico sobre activos críticos
    o ESCANEO EXHAUSTIVO (Full)    (ej. solo firewalls o toda la infraestructura).
```

* **Escaneo de Descubrimiento (*Discovery Scan*):** Es el paso preliminar obligatorio. Mapea la topología de la red, listando direcciones IP activas, nombres de host y puertos abiertos sin realizar comprobaciones de vulnerabilidades pesadas.
* **Escaneo Limitado (*Limited / Targeted Scan*):** Enfoca los recursos del escáner en un subconjunto específico de dispositivos o tecnologías (ej. auditar exclusivamente los servidores de bases de datos Oracle o los firewalls perimetrales).
* **Escaneo Exhaustivo (*Comprehensive / Full Scan*):** Analiza minuciosamente todos los dispositivos de la red a través de los 65.535 puertos TCP/UDP, evaluando sistemas operativos, aplicaciones, bases de datos y configuraciones.

## 5. El Ciclo de Gestión y Remediación de Vulnerabilidades

El escaneo de vulnerabilidades es solo el primer paso de un ciclo de mejora continua:

```
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│   1. ESCANEO    │ ────► │ 2. PRIORIZACIÓN │ ────► │ 3. REMEDIACIÓN  │ ────► │ 4. RE-ESCANEO   │
│ (Identificación)│       │  (Matriz CVSS)  │       │(Parches/Config) │       │ (Verificación)  │
└─────────────────┘       └─────────────────┘       └─────────────────┘       └─────────────────┘
```

1. **Escaneo Automatizado:** Detección y catalogación de fallos en las cinco capas.
2. **Priorización basada en Riesgo:** Clasificación de vulnerabilidades según su puntuación **CVSS** (*Common Vulnerability Scoring System*) y si existe un exploit activo en fuentes públicas (OSINT).
3. **Remediación y Mitigación:** Aplicación de parches de software, actualización de configuraciones o implementación de controles compensatorios (ej. reglas WAF).
4. **Re-Escaneo y Verificación:** Confirmación formal de que la vulnerabilidad fue mitigada con éxito y no se introdujeron nuevos fallos.

---

## Puntos Clave para Exámenes y Práctica Profesional

> [!IMPORTANT]
> * **Propósito del Escáner:** Automatizar la comparación de configuraciones y software de red contra bases de datos de vulnerabilidades conocidas (**CVE**).
> * **Cinco Capas de Evaluación:** **Perímetro**, **Red**, **Punto Final (Endpoint)**, **Aplicación** y **Datos**.
> * **Externo vs. Interno:** El externo audita la capa perimetral pública; el interno evalúa el riesgo de intrusos dentro de la LAN y movimientos laterales.
> * **Autenticado vs. No Autenticado:** Los escaneos autenticados utilizan credenciales para inspeccionar registros internos con mínima tasa de falsos positivos.
> * **Escaneo de Descubrimiento:** Procedimiento inicial esencial para mapear qué hosts y puertos existen antes de lanzar escaneos exhaustivos.
