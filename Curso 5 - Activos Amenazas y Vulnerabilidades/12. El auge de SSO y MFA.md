# El Auge de SSO y MFA: Tecnologías de Autenticación, Protocolos Federados y Factores de Identidad

En esta guía exhaustiva del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza la evolución de los modelos de autenticación empresarial: el **Inicio de Sesión Único** (*Single Sign-On - SSO*), la mitigación de la **fatiga de contraseñas**, los protocolos de federación de identidades (**LDAP** y **SAML**), la arquitectura del **Proveedor de Identidad (IdP)** frente al **Proveedor de Servicios (SP)**, y la integración de la **Autenticación de Múltiples Factores** (*Multi-Factor Authentication - MFA*) basada en los tres pilares de la identidad (*Conocimiento*, *Posesión* e *Inherencia*).

---

## 1. La Crisis del Modelo Tradicional de Contraseñas

Históricamente, las organizaciones dependían de esquemas de **autenticación de un solo factor** (*Single-Factor Authentication - SFA*), donde cada aplicación o servicio requería un par independiente de nombre de usuario y contraseña.

```
┌──────────────────────────────────────────────────────────────────────────┐
│              EL PROBLEMA DE LA FRAGMENTACIÓN DE CREDENCIALES             │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│                 ┌───► [Servicio Correo]     ➔ Usuario + Contraseña 1     │
│                 ├───► [Software CRM]        ➔ Usuario + Contraseña 2     │
│  [ EMPLEADO ] ──┼───► [Almacenamiento Cloud]➔ Usuario + Contraseña 3     │
│                 ├───► [Sistema Contable]    ➔ Usuario + Contraseña 4     │
│                 └───► [Mesa de Ayuda]       ➔ Usuario + Contraseña 5     │
│                                                                          │
│  CONSECUENCIA: "Fatiga de Contraseñas" y Prácticas Inseguras             │
└──────────────────────────────────────────────────────────────────────────┘
```

### Síntomas y Riesgos de la "Fatiga de Contraseñas" (*Password Fatigue*):
1. **Reutilización Masiva de Contraseñas (*Password Reuse*):** Los usuarios tienden a utilizar la misma contraseña (o variaciones mínimas predecibles) en múltiples plataformas corporativas y personales.
2. **Ataques de Relleno de Credenciales (*Credential Stuffing*):** Si una plataforma externa no relacionada sufre una filtración de datos, los atacantes prueban automáticamente esas credenciales robadas contra los sistemas corporativos de la empresa.
3. **Almacenamiento Inseguro Local:** Los empleados recurren a post-its pegados en sus monitores o archivos de texto sin cifrar en sus escritorios para recordar sus claves.
4. **Sobrecarga de la Mesa de Ayuda (*Help Desk Costs*):** Entre el 30% y el 50% de las solicitudes de soporte técnico en grandes empresas se destinan a desbloquear cuentas y restablecer contraseñas olvidadas.

## 2. Inicio de Sesión Único (SSO - *Single Sign-On*)

El **Inicio de Sesión Único (SSO)** es un modelo de autenticación centralizado que permite a un usuario identificarse una sola vez mediante un único conjunto de credenciales y obtener acceso transparente a múltiples sistemas, aplicaciones y recursos autorizados.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   ARQUITECTURA CENTRALIZADA CON SSO                      │
├──────────────────────────────────────────────────────────────────────────┤
│                                                                          │
│                 ┌──────────────────────────────────────┐                 │
│                 │   PROVEEDOR DE IDENTIDAD (IdP)       │                 │
│                 │   (Autenticación Única y Central)    │                 │
│                 └──────────────────┬───────────────────┘                 │
│                                    │                                     │
│                     Emisión de Tokens de Confianza                       │
│                                    │                                     │
│       ┌────────────────────────────┼────────────────────────────┐        │
│       ▼                            ▼                            ▼        │
│ ┌──────────────┐             ┌──────────────┐             ┌──────────────┐ │
│ │  CORREO WEB  │             │ SOFTWARE CRM │             │ REPOSITORIO  │ │
│ │  (App SaaS)  │             │ (Salesforce) │             │ CLOUD (GCP)  │ │
│ └──────────────┘             └──────────────┘             └──────────────┘ │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

### Los Tres Grandes Beneficios del SSO para la Organización:

| Dimensión | Beneficio Estratégico Detallado |
| :--- | :--- |
| **1. Experiencia de Usuario (*UX*)** | Elimina la necesidad de memorizar e introducir decenas de contraseñas al día, facilitando un flujo de trabajo ágil y sin fricciones operativas. |
| **2. Reducción de Costes de TI** | Disminuye drásticamente el volumen de tickets dirigidos a la mesa de ayuda para restablecimiento de claves, ahorrando cientos de horas de trabajo al equipo de TI. |
| **3. Centralización de la Seguridad** | Reduce la superficie de ataque al consolidar los puntos de entrada. Permite a los administradores aplicar políticas globales (complejidad, bloqueo por intentos) y **revocar el acceso a todos los servicios de forma instantánea** cuando un empleado abandona la compañía. |

## 3. Mecánica Operativa del SSO: Roles y Protocolos

El SSO funciona estableciendo una **relación de confianza federada** entre dos entidades principales:
* **Proveedor de Identidad (IdP - *Identity Provider*):** El sistema centralizado que almacena las identidades, verifica las credenciales del usuario y emite aserciones o tokens criptográficos de acceso firmados (ej. *Microsoft Entra ID*, *Okta*, *Google Workspace*, *Ping Identity*).
* **Proveedor de Servicios (SP - *Service Provider*):** Las aplicaciones finales a las que el usuario desea acceder (ej. *Slack*, *Salesforce*, *Zoom*, *AWS*). El SP **no almacena ni conoce la contraseña del usuario**; confía ciegamente en el token firmado digitalmente emitido por el IdP.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    FLUJO DE AUTENTICACIÓN SSO VÍA SAML / WEB                 │
└──────────────────────────────────────────────────────────────────────────────┘

 USUARIO (Navegador)          PROVEEDOR DE SERVICIOS (SP)     PROVEEDOR DE IDENTIDAD (IdP)
      │                                     │                              │
      │ 1. Intenta acceder a la App (SP)    │                              │
      ├────────────────────────────────────►│                              │
      │                                     │                              │
      │ 2. Redirige con solicitud SAML      │                              │
      │◄────────────────────────────────────┤                              │
      │                                                                    │
      │ 3. Presenta solicitud al IdP e introduce Credenciales + MFA        │
      ├───────────────────────────────────────────────────────────────────►│
      │                                                                    │
      │                                        [Valida credenciales        │
      │                                         y genera Token firmado]    │
      │                                                                    │
      │ 4. Recibe Token / Aserción SAML firmada criptográficamente         │
      │◄───────────────────────────────────────────────────────────────────┤
      │                                                                    │
      │ 5. Envía el Token SAML al Proveedor de Servicios                   │
      ├────────────────────────────────────►│                              │
      │                                     │ [Verifica firma del IdP      │
      │                                     │  y concede acceso]           │
      │ 6. Sesión iniciada con éxito        │                              │
      │◄────────────────────────────────────┤                              │
```

### Protocolos de Autenticación: LDAP frente a SAML

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   COMPARATIVA: PROTOCOLOS LDAP VS. SAML                  │
├─────────────────────────────────────┬────────────────────────────────────┤
│   LDAP (Lightweight Directory)      │   SAML (Security Assertion Markup) │
├─────────────────────────────────────┼────────────────────────────────────┤
│ • Protocolo local para redes        │ • Protocolo federado basado en XML │
│   corporativas On-Premises.         │   para la Web y la Nube (Cloud).   │
│ • Comunica directamente con el      │ • El navegador actúa como puente   │
│   servidor de directorio central.   │   mediante tokens firmados.        │
│ • Empleado en Active Directory,     │ • Empleado para integrar apps SaaS │
│   autenticación de VPNs y Linux PAM.│   (Google Apps, Office 365, etc.). │
└─────────────────────────────────────┴────────────────────────────────────┘
```

* **LDAP (*Lightweight Directory Access Protocol*):** Desarrollado para consultar y modificar información en servicios de directorio sobre redes IP locales. Comunica estaciones de trabajo con servidores controladores de dominio (como *Microsoft Active Directory* o *OpenLDAP*).
* **SAML (*Security Assertion Markup Language*):** Estándar abierto basado en XML que permite la federación de identidades entre dominios de seguridad independientes a través de Internet. Es el pilar del SSO moderno en la nube.

> [!NOTE]
> En infraestructuras híbridas empresariales, **LDAP y SAML suelen coexistir**: el usuario se autentica en la red local mediante LDAP/Active Directory, y un servidor de federación (como ADFS o Okta) traduce esa identidad a aserciones SAML para acceder a los servicios en la nube.

## 4. Limitaciones del SSO y el Riesgo del "Punto Único de Fallo"

A pesar de sus múltiples ventajas, el SSO introduce un riesgo crítico inherente:

```
                          EL EFECTO "LLAVE MAESTRA"
┌──────────────────┐       Compromiso de Credenciales       ┌──────────────────────────┐
│ Contraseña SSO   │ ─────────────────────────────────────► │ ACCESO TOTAL E ILIMITADO │
│ Comprometida     │     (Phishing, Malware o F. Bruta)     │ A TODAS LAS APPS DEL SP  │
└──────────────────┘                                        └──────────────────────────┘
                                                              ⚠️ BRECHA CORPORATIVA TOTAL
```

* Si un atacante roba o adivina la contraseña maestra del SSO de un empleado, no solo compromete una cuenta individual, sino que obtiene **acceso inmediato a todas las aplicaciones conectadas** en la infraestructura de la empresa.
* **Solución Técnica:** Nunca debe desplegarse SSO dependiendo únicamente de contraseñas. Es imperativo combinarlo con **Autenticación Multifactor (MFA)**.

---

## 5. Autenticación de Múltiples Factores (MFA)

La **Autenticación de Múltiples Factores (*Multi-Factor Authentication - MFA*)** es un control de seguridad que exige a un usuario verificar su identidad mediante **dos o más factores de autenticación pertenecientes a categorías independientes** antes de autorizar el acceso a un sistema.

```
                                ECUACIÓN DE LA AUTENTICACIÓN MFA
┌─────────────────────────┐       ┌─────────────────────────┐       ┌─────────────────────────┐
│     ALGO QUE SABES      │   +   │     ALGO QUE TIENES     │  ===  │    ACCESO AUTORIZADO    │
│  (Contraseña / PIN)     │       │ (App TOTP / Token USB)  │       │       Y SEGURO          │
└─────────────────────────┘       └─────────────────────────┘       └─────────────────────────┘
```

### La Analogía del Cajero Automático (ATM):
* **Paso 1 (Posesión):** Introducir la tarjeta de débito física (**Algo que tienes**).
* **Paso 2 (Conocimiento):** Escribir el código secreto PIN (**Algo que sabes**).
* Si un criminal roba la tarjeta pero no conoce el PIN, no puede retirar dinero. Si conoce el PIN pero no tiene la tarjeta física, tampoco. Solo la combinación de ambos factores independientes desbloquea la cuenta.

---

### Los Tres Factores Fundamentales de Autenticación

```
┌────────────────────────────────────────────────────────┐
│               LOS TRES FACTORES DE IDENTIDAD           │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────────────┐
 ▼                ▼                        ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│ CONOCIMIENTO │ │   POSESIÓN   │ │    INHERENCIA    │
│ (Algo que    │ │  (Algo que   │ │    (Algo que     │
│    sabes)    │ │    tienes)   │ │      eres)       │
├──────────────┤ ├──────────────┤ ├──────────────────┤
│ • Contraseña │ │ • App TOTP   │ │ • Huella digital │
│ • Frase paso │ │ • Token FIDO2│ │ • Escaneo facial │
│ • Código PIN │ │ • SMS OTP    │ │ • Reconoc. iris  │
└──────────────┘ └──────────────┘ └──────────────────┘
```

| Categoría | Concepto | Ejemplos Técnicos | Nivel de Seguridad y Consideraciones |
| :--- | :--- | :--- | :--- |
| **1. Conocimiento** | *Algo que sabes* | Contraseña maestra, frase de paso (*passphrase*), código PIN personal, respuestas de seguridad. | Vulnerable a phishing, reutilización, keyloggers y ataques de fuerza bruta. |
| **2. Posesión** | *Algo que tienes* | Aplicación de autenticación (*Google/Microsoft Authenticator* con códigos **TOTP** temporales), llaves de seguridad física por hardware (**FIDO2 / YubiKey**), tarjetas inteligentes (*smartcards*), códigos de un solo uso por SMS. | Muy seguro cuando se usan llaves físicas o apps autenticadoras. *(Nota: los SMS OTP son susceptibles a ataques de SIM Swapping e intercepción).* |
| **3. Inherencia** | *Algo que eres* | Biometría física: huella dactilar, reconocimiento facial 3D, escaneo de retina o iris, biometría conductual (patrón de tecleo). | Extremadamente difícil de suplantar o duplicar; vinculado físicamente al individuo. |

> [!WARNING]
> **Error Común:** Solicitar una contraseña y un código PIN no constituye MFA (es **2-Step Verification** dentro del mismo factor: Conocimiento + Conocimiento). Para ser verdadero MFA, los factores deben pertenecer a **categorías distintas** (ej. Conocimiento + Posesión).

## 6. Sinergia Estratégica: SSO + MFA

La convergencia de **SSO + MFA** representa el estándar de oro en arquitecturas modernas de seguridad e identidades (*Zero Trust*):

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    EL MODELO INTEGRADO: SSO BLINDADO CON MFA                 │
└──────────────────────────────────────────────────────────────────────────────┘

 1. Usuario ingresa su Contraseña Única en el Portal SSO (IdP).
    └──► [FACTOR 1: Algo que sabe]

 2. El sistema solicita verificación en la App Móvil o llave de seguridad física.
    └──► [FACTOR 2: Algo que tiene / Algo que es]

 3. Tras validar ambos factores, el IdP emite tokens firmados hacia TODO el entorno:
    ├──► Sesión activa en Slack
    ├──► Sesión activa en Salesforce
    ├──► Sesión activa en Google Cloud Platform
    └──► Sesión activa en Correo Corporativo
```

* **Mitigación Cuántica de Amenazas:** Informes de telemetría de seguridad demuestran que habilitar MFA sobre portales de SSO neutraliza más del **99.9% de los ataques automatizados de robo de credenciales**, cerrando la puerta al phishing tradicional y al credential stuffing.
* **Seguridad sin Fricción:** El usuario solo realiza la autenticación robusta una vez al inicio de su jornada laboral, manteniendo todas sus herramientas conectadas de forma segura y productiva.

---

## Puntos Clave para Exámenes y Práctica Profesional

> [!IMPORTANT]
> * **Propósito del SSO:** Simplificar la autenticación consolidando múltiples credenciales en un único inicio de sesión, reduciendo la fatiga de contraseñas y los costes de soporte.
> * **Roles SSO:** El **IdP** autentica al usuario y firma el token; el **SP** valida el token y entrega el servicio sin conocer la contraseña.
> * **Protocolos:** **LDAP** se utiliza primordialmente en redes locales y directorios internos; **SAML** es el estándar basado en XML para federación web y aplicaciones en la nube.
> * **Los Tres Factores de MFA:** **Conocimiento** (*algo que sabes*), **Posesión** (*algo que tienes*) e **Inherencia** (*algo que eres / biometría*).
> * **Fórmula Defensiva:** El SSO centraliza el acceso; el MFA blinda esa entrada centralizada frente a cualquier filtración o robo de contraseñas.
