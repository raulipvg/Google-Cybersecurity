# Gestión de Identidad y Acceso (IAM): Marcos AAA, Modelos de Autorización (MAC, DAC, RBAC) y Ciclo de Vida de Identidades

En esta guía exhaustiva del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza en profundidad la disciplina de **Gestión de Identidad y Acceso** (*Identity and Access Management - IAM*), la relación entre los principios de **Privilegio Mínimo (PoLP)** y **Separación de Funciones (SoD)**, la convergencia con el marco **AAA** (*Autenticación, Autorización y Contabilidad*), el **ciclo de vida de identidades** (*Aprovisionamiento y Desaprovisionamiento*), y los tres modelos fundamentales de control de acceso: **MAC**, **DAC** y **RBAC**.

---

## 1. Los Dos Principios Fundamentales del Control de Acceso

La seguridad de la información no consiste en añadir herramientas de manera aislada, sino en estructurar una arquitectura defensiva basada en dos principios esenciales que limitan y distribuyen el poder dentro de la organización:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   PRINCIPIOS CLAVE DE CONTROL DE ACCESO                  │
├─────────────────────────────────────┬────────────────────────────────────┤
│   PRIVILEGIO MÍNIMO (PoLP)          │   SEPARACIÓN DE FUNCIONES (SoD)    │
├─────────────────────────────────────┼────────────────────────────────────┤
│ • "A cada usuario solo se le otorga │ • "Ningún usuario debe poseer      │
│   el nivel mínimo indispensable de  │   privilegios suficientes para     │
│   acceso para realizar su labor".   │   hacer un uso indebido del sistema│
│ • Limita la PROFUNDIDAD del acceso  │   o cometer fraude sin ser visto". │
│   de un solo individuo.             │ • Divide las responsabilidades     │
│                                     │   entre MÚLTIPLES personas.        │
└─────────────────────────────────────┴────────────────────────────────────┘
```

```
                   EJEMPLO PRÁCTICO: GESTIÓN DE COMPRAS DE TI
┌──────────────────────────────────────────────────────────────────────────────┐
│ 1. Aplicación de PoLP (Privilegio Mínimo):                                   │
│    El gerente de TI puede autorizar compras de TI, pero NO de Finanzas ni RRHH│
│                                                                              │
│ 2. Aplicación de SoD (Separación de Funciones):                              │
│    ┌──────────────────┐       ┌──────────────────┐       ┌─────────────────┐ │
│    │ Empleado A       │ ────► │ Empleado B       │ ────► │ Empleado C      │ │
│    │ Solicita compra  │       │ Aprueba compra   │       │ Ejecuta el pago │ │
│    └──────────────────┘       └──────────────────┘       └─────────────────┘ │
│    (La persona que crea el pedido NO puede ser quien lo apruebe ni lo pague) │
└──────────────────────────────────────────────────────────────────────────────┘
```

> [!NOTE]
> La **Separación de Funciones (*Separation of Duties - SoD*)** también se denomina formalmente **Segregación de Funciones**. Es un control mandatorio en normativas financieras y de cumplimiento como *Sarbanes-Oxley (SOX)* e *ISO 27001*.

Para implementar estos principios, las organizaciones estructuran sus defensas bajo dos marcos complementarios:

```
┌────────────────────────────────────────────────────────┐
│                   ARQUITECTURA DEL MARCO AAA           │

                           │
 ┌────────────────┬────────┴───────────────┐
 ▼                ▼                        ▼

│ ¿Quién eres? │ │ ¿Qué tienes  │ │ ¿Qué hiciste y   │
│ Validación   │ │ permitido    │ │ cuándo?          │
│ de identidad.│ │ hacer?       │ │ Auditoría / Logs.│
└──────────────┘ └──────────────┘ └──────────────────┘
```

### ¿Qué es la Gestión de Identidad y Acceso (IAM)?
**IAM (*Identity and Access Management*)** es el conjunto integral de procesos empresariales, políticas de gobernanza y tecnologías diseñadas para administrar las identidades digitales en toda la organización durante todo su ciclo de vida.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                        LA REGLA DE ORO DE IAM                            │
├──────────────────────────────────────────────────────────────────────────┤
│  Garantizar que el USUARIO ADECUADO (Persona, Dispositivo o Software)    │
│  acceda a los RECURSOS ADECUADOS (Datos, Aplicaciones o Servidores),     │
│  en el MOMENTO ADECUADO (Ventana de trabajo legítima),                   │
│  y por las RAZONES ADECUADAS (Justificación de negocio válida).          │
└──────────────────────────────────────────────────────────────────────────┘
```

## 3. El Ciclo de Vida de las Identidades: Aprovisionamiento y Desaprovisionamiento

La gestión de identidades es un proceso continuo que acompaña al usuario desde su ingreso a la organización hasta su desvinculación:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    CICLO DE VIDA DE LA IDENTIDAD DIGITAL                     │
└──────────────────────────────────────────────────────────────────────────────┘

 1. APROVISIONAMIENTO (Onboarding)  ➔ Creación de cuenta, asignación de roles
                                       iniciales y entrega de credenciales.
                                                  │
                                                  ▼
 2. MANTENIMIENTO Y MODIFICACIÓN    ➔ Modificación de permisos por promociones
                                       o cambios de área (Auditoría Anti-Creep).
                                                  │
                                                  ▼
 3. DESAPROVISIONAMIENTO (Offboarding)➔ REVOCACIÓN INMEDIATA Y TOTAL DE ACCESOS
                                       cuando la relación laboral finaliza.
```

### A. Aprovisionamiento de Usuarios (*User Provisioning*)
* Proceso formal de creación, configuración y asignación de permisos a la identidad digital de un usuario en los directorios de la empresa.
* **Ejemplo:** Cuando una universidad contrata a un profesor, se aprovisiona su cuenta con acceso exclusivo a las actas de sus asignaturas y recursos de su facultad mientras dure su contrato.

### B. Desaprovisionamiento (*User Deprovisioning*)
* Proceso crítico de eliminación o deshabilitación inmediata de todos los derechos de acceso, cuentas y tokens cuando un usuario abandona la compañía o cambia de rol.
* **Riesgo Crítico de las "Cuentas Fantasma" (*Orphan Accounts*):** Si un empleado despedido conserva cuentas activas, se convierte en una de las mayores vulnerabilidades para accesos no autorizados, espionaje corporativo o sabotaje.

## 4. Modelos de Concesión de Autorización: MAC, DAC y RBAC

Una vez autenticado el usuario, el sistema debe determinar qué acciones puede ejecutar. Existen tres modelos formales de control de acceso:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                     MODELOS DE CONTROL DE ACCESO                         │
├───────────────────┬──────────────────────────────┬───────────────────────┤
│     1. MAC        │            2. DAC            │        3. RBAC        │
│  (Obligatorio)    │        (Discrecional)        │   (Basado en Roles)   │
├───────────────────┼──────────────────────────────┼───────────────────────┤
│ La AUTORIDAD      │ El PROPIETARIO DEL DATO      │ La FUNCIÓN LABORAL    │
│ CENTRAL define    │ decide quién accede y con    │ (Rol) determina los   │
│ las reglas de     │ qué nivel de permiso.        │ privilegios asignados.│
│ acceso fijas.     │                              │                       │
│ Ej: Militar / Top │ Ej: Compartir carpetas       │ Ej: Rol "Contador" o  │
│ Secret.           │ en Google Drive / NTFS.      │ "Analista SOC".       │
└───────────────────┴──────────────────────────────┴───────────────────────┘
```

---

### A. Control de Acceso Obligatorio (MAC - *Mandatory Access Control*)
* **Mecanismo:** Es el modelo más rígido y estricto. El acceso está regulado por una **autoridad central** mediante etiquetas de seguridad fijas y niveles de acreditación (*Clearance*).
* **Naturaleza No Discrecional:** Los usuarios y propietarios de datos **no tienen la facultad de compartir ni modificar permisos**; el sistema operativo aplica las reglas de forma obligatoria basándose en la clasificación del dato (ej. *Público*, *Secreto*, *Ultrasecreto*) y la acreditación del usuario.
* **Entornos de Aplicación:** Fuerzas armadas, agencias de inteligencia, defensa nacional y sistemas de máxima seguridad (ej. *SELinux*).

---

### B. Control de Acceso Discrecional (DAC - *Discretionary Access Control*)
* **Mecanismo:** El **propietario del recurso (*Data Owner*)** tiene la potestad y discreción absoluta para conceder, modificar o revocar permisos de acceso a otros usuarios sobre sus archivos.
* **Ejemplos Cotidianos:**
  * Permisos en sistemas de archivos locales (Linux `chmod`, listas de control de acceso ACL en Windows NTFS).
  * Almacenamiento en la nube: Cuando el creador de un documento en Google Drive o Dropbox decide otorgar permisos de "Lector", "Comentador" o "Editor" a un colega.

---

### C. Control de Acceso Basado en Roles (RBAC - *Role-Based Access Control*)
* **Mecanismo:** Los permisos no se asignan a personas individuales ni a archivos específicos, sino a **roles organizacionales predefinidos** (ej. "Administrador de Red", "Especialista de Nóminas", "Auditor de Seguridad").
* **Flujo Operativo:**
  1. El administrador crea el rol `Analista_SOC` y le asigna permisos de lectura sobre los registros del SIEM.
  2. Cuando se contrata a un nuevo analista, simplemente se le añade al grupo `Analista_SOC`.
  3. Si el empleado cambia al equipo de desarrollo, se le retira del rol `Analista_SOC` y se le asigna el rol `Desarrollador`, actualizando todos sus accesos de forma instantánea.
* **Entornos de Aplicación:** Es el estándar por excelencia en el sector empresarial corporativo debido a su escalabilidad y facilidad de auditoría.

---

### Matriz Comparativa Integral de Modelos de Control de Acceso

| Criterio | MAC (*Mandatory*) | DAC (*Discretionary*) | RBAC (*Role-Based*) |
| :--- | :--- | :--- | :--- |
| **¿Quién decide el acceso?** | Autoridad Central / Políticas del Sistema | Propietario del Recurso (*Owner*) | Administrador según Función Laboral |
| **Flexibilidad** | Muy baja (Extremadamente rígido) | Muy alta (Descentralizada) | Moderada / Alta (Estructurada) |
| **Nivel de Seguridad** | **Máximo** (Resistente a fugas) | Variable (Vulnerable a errores de usuario) | **Alto** (Alineado con PoLP) |
| **Complejidad de Gestión** | Alta (Requiere clasificación exhaustiva) | Baja inicialmente, difícil a gran escala | Muy eficiente y escalable para empresas |
| **Ámbito Típico** | Gobierno, Milicia, Defensa | Sistemas Operativos de PC, Cloud Drive | Entornos Corporativos, ERPs, SaaS |

## 5. Arquitectura de las Tecnologías de Control de Acceso

Un sistema IAM moderno integra múltiples componentes modulares que operan de forma automatizada y sincronizada:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                      ARQUITECTURA DE UN ECOSISTEMA IAM                       │
└──────────────────────────────────────────────────────────────────────────────┘

 ┌────────────────────────────────┐       ┌────────────────────────────────┐
 │ 1. DIRECTORIO DE IDENTIDADES   │       │ 2. MOTOR DE AUTENTICACIÓN      │
 │ (Active Directory / LDAP / BD) │ ────► │ (SSO, MFA, Tokens SAML/OIDC)   │
 └────────────────────────────────┘       └───────────────┬────────────────┘
                                                          │
                                                          ▼
 ┌────────────────────────────────┐       ┌────────────────────────────────┐
 │ 4. SISTEMA DE AUDITORÍA Y LOGS │       │ 3. MOTOR DE AUTORIZACIÓN       │
 │ (SIEM, Trazabilidad, Informes) │ ◄──── │ (Políticas RBAC, PAM, ACLs)    │
 └────────────────────────────────┘       └────────────────────────────────┘
```

* **Soluciones Propietarias vs. Plataformas Comerciales (COTS/Cloud):** Desarrollar un sistema IAM interno personalizado es costoso, complejo de mantener y propenso a vulnerabilidades. Las organizaciones modernas implementan soluciones líderes del mercado como **Microsoft Entra ID**, **Okta**, **Ping Identity** o **CyberArk** (*Privileged Access Management - PAM*).

## Puntos Clave para Exámenes y Práctica Profesional

> [!IMPORTANT]
> * **PoLP vs. SoD:** El Privilegio Mínimo limita la *profundidad* de acceso de una persona; la Separación de Funciones *divide* los pasos críticos entre varias personas para evitar fraudes.
> * **Marco AAA:** **Autenticación** (verificar identidad), **Autorización** (conceder permisos) y **Contabilidad** (auditar acciones en logs).
> * **Aprovisionamiento y Desaprovisionamiento:** Procesos esenciales de alta y baja de identidades; el desaprovisionamiento inmediato elimina el riesgo de cuentas huérfanas.
> * **Trilogía de Control de Acceso:**
>   * **MAC:** Autoridad central basada en etiquetas fijas (milicia/defensa).
>   * **DAC:** El propietario del dato decide libremente quién accede.
>   * **RBAC:** Los permisos se asignan a roles laborales (estándar corporativo).
