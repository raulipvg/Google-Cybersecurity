# Cifrado Simétrico y Asimétrico: Fundamentos, Algoritmos y Aplicaciones Prácticas

En esta guía exhaustiva del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se profundiza detalladamente en los dos paradigmas esenciales de la criptografía moderna: el **cifrado simétrico** y el **cifrado asimétrico**, el análisis matemático de la **longitud de clave**, la evolución y especificaciones técnicas de los algoritmos aprobados (**DES**, **3DES**, **AES**, **RSA**, **DSA**), la gestión de claves con **OpenSSL**, la vulnerabilidad histórica **Heartbleed**, el **Principio de Kerckhoffs**, y la implementación del **cifrado híbrido** en protocolos web modernos (TLS/HTTPS) bajo estándares regulatorios como **FIPS 140-3** y **GDPR**.

---

## 1. Conceptos Fundamentales de Criptografía

Toda la información digital en una organización —ya sea en reposo en discos duros, en tránsito a través de redes públicas o en uso en memoria— debe protegerse frente a intercepciones, accesos no autorizados y manipulaciones. El cifrado es la herramienta técnica primaria para garantizar la **Confidencialidad** y la **Integridad** de los datos.

```

│                      TÉRMINOS ESENCIALES DE CRIPTOGRAFÍA                 │

├──────────────────────────────────┼───────────────────────────────────────┤

├──────────────────────────────────┼───────────────────────────────────────┤
```

### A. Cifrado Simétrico (*Symmetric Encryption*)

En el cifrado simétrico, el emisor y el receptor utilizan **exactamente la misma clave secreta** para realizar tanto el cifrado como el descifrado. 

```
                       ┌────────────────────────┐
                       │  CLAVE SECRETA (K)     │
                       │  (Conocida por ambos)  │
                       └───────────┬────────────┘
                                   │
             ┌─────────────────────┴─────────────────────┐
             ▼                                           ▼
┌─────────────────────────┐                 ┌─────────────────────────┐
│     PROCESO EMISOR      │                 │    PROCESO RECEPTOR     │
├─────────────────────────┤                 ├─────────────────────────┤
│ 1. Texto Plano (Mensaje)│                 │ 1. Texto Cifrado Recib. │
│ 2. + Clave Secreta (K)  │                 │ 2. + Clave Secreta (K)  │
│ 3. Algoritmo Simétrico  │                 │ 3. Algoritmo Simétrico  │
│           │             │                 │           │             │
│           ▼             │                 │           ▼             │
│     Texto Cifrado       │ ── CANAL RED ─► │     Texto Plano Original│
└─────────────────────────┘   (Inseguro)    └─────────────────────────┘
```

* **Mecanismo Operativo:** Si Alicia quiere enviar un documento confidencial a Roberto, ambos deben haber acordado previamente una clave secreta $K$. Alicia cifra el documento con $K$, lo envía a través de Internet (donde ningún tercero puede leerlo), y Roberto usa la misma clave $K$ para descifrarlo.
* **Ventajas Principales:**
  * **Velocidad Extrema:** Los algoritmos simétricos están optimizados a nivel de hardware e instrucciones de CPU (como el conjunto de instrucciones *AES-NI* de Intel y AMD), procesando gigabytes de datos por segundo.
  * **Eficiencia de Recursos:** Consumo mínimo de memoria y procesador, haciéndolo ideal para transferir flujos masivos de datos (bases de datos, streaming de video, túneles VPN).
* **El Problema de Distribución de Claves (*Key Distribution Problem*):**
  * Si Alicia y Roberto nunca se han conocido en persona y están separados por miles de kilómetros, ¿cómo transmiten la clave secreta por primera vez a través de un canal inseguro (Internet) sin que un espía la intercepte?
  * Si la clave es interceptada durante el trayecto, el atacante podrá descifrar todas las comunicaciones presentes y futuras.

---

### B. Cifrado Asimétrico (*Asymmetric Encryption / Public Key Cryptography*)

Para resolver definitivamente el problema del intercambio de claves del cifrado simétrico, a finales de la década de 1970 se desarrolló la **criptografía asimétrica**, la cual utiliza un **par de claves complementarias**:

```
                       ┌─────────────────────────────────┐
                       │     PAR DE CLAVES DE ROBERTO    │
                       ├────────────────┬────────────────┤
                       │  CLAVE PÚBLICA │ CLAVE PRIVADA  │
                       │  (De libre     │ (Secreta /     │
                       │   difusión)    │  Solo Roberto) │
                       └────────┬───────┴────────┬───────┘
                                │                │
             ┌──────────────────┘                └──────────────────┐
             ▼                                                      ▼
┌─────────────────────────┐                            ┌─────────────────────────┐
│     PROCESO EMISOR      │                            │    PROCESO RECEPTOR     │
│        (Alicia)         │                            │        (Roberto)        │
├─────────────────────────┤                            ├─────────────────────────┤
│ 1. Texto Plano (Mensaje)│                            │ 1. Texto Cifrado Recib. │
│ 2. + Clave PÚBLICA      │                            │ 2. + Clave PRIVADA      │
│    de Roberto           │                            │    de Roberto           │
│ 3. Cifrado Asimétrico   │                            │ 3. Descifrado Asimétrico│
│           │             │                            │           │             │
│           ▼             │                            │           ▼             │
│     Texto Cifrado       │ ────── CANAL RED ────────► │     Texto Plano Original│
└─────────────────────────┘         (Internet)         └─────────────────────────┘
```

* **Mecanismo Operativo:**
  1. **Generación del Par:** Roberto genera un par de claves en su sistema: una **Clave Pública** ($K_{pub}$) y una **Clave Privada** ($K_{priv}$).
  2. **Publicación:** Roberto publica su clave pública en un directorio accesible para todo el mundo.
  3. **Cifrado:** Cualquier persona (como Alicia) puede tomar la clave pública de Roberto y cifrar un mensaje.
  4. **Propiedad Unidireccional:** Una vez que el mensaje ha sido cifrado con la clave pública de Roberto, **nadie (ni siquiera Alicia que lo escribió)** puede descifrarlo utilizando esa misma clave pública.
  5. **Descifrado Exclusivo:** El único elemento en el mundo capaz de revertir la operación matemática y leer el mensaje es la **Clave Privada** de Roberto, que permanece exclusivamente en su poder.
* **Ventajas Principales:**
  * **Seguridad en Canales Abiertos:** Permite a dos entidades que nunca han tenido contacto previo comunicarse de manera confidencial sin requerir un canal seguro previo para compartir secretos.
  * **Autenticación y Firma Digital:** Permite autenticar la identidad del emisor y garantizar el no repudio.
* **Desafíos:**
  * **Alto Costo Computacional:** Las operaciones matemáticas asimétricas (multiplicación y factorización de números primos gigantescos) son miles de veces más lentas que las simétricas.
  * **Longitudes de Clave Muy Grandes:** Requiere claves de miles de bits para ofrecer un nivel de seguridad equivalente al de claves simétricas cortas.

## 3. La Longitud de la Clave y Ataques de Fuerza Bruta

### ¿Qué es un Ataque de Fuerza Bruta (*Brute-Force Attack*)?
Es un método criptoanalítico que consiste en probar sistemáticamente todas las combinaciones posibles de bits de una clave hasta encontrar la correcta que descifre el mensaje. Es el análogo digital de probar todas las combinaciones numéricas de un candado.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   ESPACIO DE BÚSQUEDA SEGÚN EL NÚMERO DE BITS            │
├───────────────┬───────────────────────────────┬──────────────────────────┤
│ Longitud (n)  │ Total de Combinaciones (2^n)  │ Tiempo de Cómputo        │
├───────────────┼───────────────────────────────┼──────────────────────────┤
│ 56 bits (DES) │ 2^56 ≈ 7.2 × 10^16 combinac.  │ Horas / Días (Vulnerable)│
├───────────────┼───────────────────────────────┼──────────────────────────┤
│ 128 bits (AES)│ 2^128 ≈ 3.4 × 10^38 combinac. │ Miles de millones de años│
├───────────────┼───────────────────────────────┼──────────────────────────┤
│ 256 bits (AES)│ 2^256 ≈ 1.1 × 10^77 combinac. │ Prácticamente infinito   │
│               │ (Más que átomos en universo)  │ (Inmune a fuerza bruta)  │
└───────────────┴───────────────────────────────┴──────────────────────────┘
```

### El Compromiso entre Seguridad y Rendimiento
* **Claves Cortas:** Se procesan muy rápido en microprocesadores y servidores, reduciendo la latencia de las aplicaciones, pero son susceptibles de ser quebradas mediante clústeres de cómputo moderno.
* **Claves Largas:** Ofrecen una barrera matemática impenetrable contra ataques de fuerza bruta presentes y futuros, pero incrementan el tiempo de cálculo, el consumo de energía y la latencia en las conexiones de red.
* **Objetivo del Analista:** Seleccionar algoritmos y longitudes de clave estandarizados que ofrezcan seguridad absoluta sin penalizar innecesariamente la experiencia del usuario.

### A. Algoritmos Simétricos

#### 1. Data Encryption Standard (DES) y Triple DES (3DES)
* **DES (Data Encryption Standard):** Desarrollado por IBM y adoptado por el gobierno de EE.UU. a principios de la década de 1970. Operaba sobre bloques de datos de 64 bits y utilizaba claves de 64 bits (de las cuales solo **56 bits** se usaban efectivamente para el cifrado, reservándose 8 bits para paridad). Debido al aumento de la potencia de cómputo, una clave de 56 bits hoy puede ser descifrada en pocas horas.
* **3DES (Triple DES):** Diseñado para extender la vida útil de DES sin cambiar la arquitectura del algoritmo. Aplica el cifrador DES **tres veces consecutivas** sobre cada bloque de datos:
  $$\text{Texto Cifrado} = E_{K3}(D_{K2}(E_{K1}(\text{Texto Plano})))$$
  * Utiliza **tres claves independientes de 56 bits**, logrando una longitud de clave nominal de **168 bits** (efectiva de 112 bits debido a ataques de tipo *meet-in-the-middle*).
* **Estado Actual:** Aunque 3DES solventó temporalmente la debilidad del tamaño de clave de DES, su tamaño de bloque de 64 bits lo hace vulnerable a ataques de colisión en grandes volúmenes de datos (*Sweet32*). El NIST ha retirado formalmente 3DES de los estándares recomendados, y las organizaciones lo están eliminando, manteniéndolo únicamente en sistemas bancarios heredados (*legacy*) por razones de retrocompatibilidad.

#### 2. Advanced Encryption Standard (AES)
* **Historia y Adopción:** Tras un concurso público internacional de cinco años organizado por el NIST, el algoritmo *Rijndael* (creado por los criptógrafos belgas Joan Daemen y Vincent Rijmen) fue seleccionado en 2001 para sustituir a DES/3DES bajo el nombre de **AES**.
* **Especificaciones Técnicas:**
  * Cifrador por bloques simétrico con un tamaño de bloque fijo de **128 bits**.
  * Admite tres longitudes de clave estandarizadas: **128 bits**, **192 bits** y **256 bits**.
  * Realiza múltiples rondas de transformaciones matemáticas (sustitución, permutación, mezcla de columnas y adición de clave): 10 rondas para 128 bits, 12 rondas para 192 bits y 14 rondas para 256 bits.
* **Nivel de Seguridad:** No existe ningún ataque práctico conocido contra AES. Un ordenador moderno tardaría **miles de millones de años** en probar todas las combinaciones de una clave de 128 bits. Es el estándar utilizado por gobiernos, agencias militares y corporaciones mundiales para proteger información clasificada como Secreta y Ultrasecreta (*Top Secret*).

---

### B. Algoritmos Asimétricos

#### 1. RSA (Rivest-Shamir-Adleman)
* **Origen:** Desarrollado en 1977 en el Instituto Tecnológico de Massachusetts (MIT) por Ron Rivest, Adi Shamir y Leonard Adleman.
* **Fundamento Matemático:** Se basa en la **dificultad computacional de factorizar el producto de dos números primos gigantescos**. Mientras que multiplicar dos números primos es instantáneo, descomponer el número resultante en sus factores originales requiere un esfuerzo de cálculo descomunal.
* **Longitudes de Clave Típicas:** **1.024 bits** (actualmente considerada insegura y deprecada), **2.048 bits** (estándar mínimo recomendado en la actualidad) y **4.096 bits** (utilizada para infraestructuras críticas y autoridades de certificación raíz).
* **Aplicaciones:** Protección de credenciales, autenticación de identidades, firma de documentos digitales y协商 de claves en conexiones SSL/TLS y SSH.

#### 2. DSA (Digital Signature Algorithm)
* **Origen:** Estándar federal de procesamiento de información (FIPS 186) propuesto por el NIST en 1991 para su uso en firmas digitales.
* **Fundamento Matemático:** Se basa en el problema matemático del **logaritmo discreto** en aritmética modular.
* **Longitudes de Clave:** Originalmente utilizaba claves de 512 a 1.024 bits; en sus revisiones modernas opera con claves de **2.048 y 3.076 bits**.
* **Aplicaciones:** Diseñado exclusivamente para generar y validar **firmas digitales**, garantizando la autenticidad, la integridad y el no repudio en transacciones de la Infraestructura de Clave Pública (PKI), actuando como complemento a RSA.

## 5. El Modelo de Cifrado Híbrido en Comunicaciones Web (TLS/HTTPS)

En el tráfico de Internet moderno, ninguna aplicación utiliza exclusivamente cifrado simétrico o asimétrico de forma aislada. En su lugar, se implementa una arquitectura de **Cifrado Híbrido** que aprovecha las ventajas de ambos métodos:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                  ARQUITECTURA DE CIFRADO HÍBRIDO (TLS / HTTPS)               │
└──────────────────────────────────────────────────────────────────────────────┘

     NAVEGADOR (Cliente)                                SERVIDOR WEB
              │                                                │
              │  1. Inicio de conexión (Client Hello)          │
              ├───────────────────────────────────────────────►│
              │                                                │
              │  2. Certificado Digital + CLAVE PÚBLICA RSA    │
              │◄───────────────────────────────────────────────┤
              │                                                │
 [Verifica Certificado]                                        │
 [Genera Clave Simétrica                                       │
  Efímera de Sesión (K)]                                       │
              │                                                │
              │  3. Clave Simétrica (K) CIFRADA con RSA Públ.  │
              ├───────────────────────────────────────────────►│
              │                                                │ [Descifra (K) usando
              │                                                │  su CLAVE PRIVADA RSA]
              │                                                │
══════════════╪════════════════════════════════════════════════╪══════════════
              ▼                                                ▼
     FASE 2: TRANSFERENCIA DE DATOS DE ALTA VELOCIDAD CON CIFRADO SIMÉTRICO (AES)
              │                                                │
              │ ◄─── Tráfico web cifrado con Clave Simétrica K ───► │
              │      (Páginas HTML, APIs, formularios, vídeos) │
```

1. **Fase Asimétrica (Apretón de Manos / *Handshake*):**
   * El cliente y el servidor se autentican utilizando certificados digitales y **cifrado asimétrico (RSA)**.
   * El cliente genera una clave simétrica temporal (llamada **clave de sesión** o *session key*) y la cifra con la clave pública del servidor.
   * El servidor recibe el paquete y lo descifra con su clave privada. Ahora ambos comparten la misma clave secreta sin haberla expuesto en texto plano en ningún momento.
2. **Fase Simétrica (Transferencia de Datos en Tiempo Real):**
   * A partir de ese milisegundo, la conexión conmuta a **cifrado simétrico (AES)**.
   * Todas las contraseñas, datos bancarios, imágenes y peticiones HTTP se transmiten cifradas con AES a máxima velocidad sin sobrecargar el procesador del servidor ni del cliente.

## 6. Generación de Claves, Herramientas y Casos Prácticos

### A. Herramienta de Línea de Comandos: OpenSSL
**OpenSSL** es la suite criptográfica y biblioteca de código abierto más utilizada a nivel mundial para generar claves criptográficas, crear solicitudes de firma de certificados (*CSR*), verificar cadenas de confianza PKI y habilitar comunicaciones TLS.

```bash
# Ejemplo conceptual: Generación de una clave privada RSA de 2048 bits
openssl genpkey -algorithm RSA -out private_key.pem -pkeyopt rsa_keygen_bits:2048

# Extracción de la clave pública asociada a partir de la clave privada
openssl rsa -pubout -in private_key.pem -out public_key.pem

# Cifrado simétrico de un archivo utilizando AES-256 en modo CBC
openssl enc -aes-256-cbc -salt -in confidencial.txt -out confidencial.enc
```

---

### B. Estudio de Caso: La Vulnerabilidad *Heartbleed* (2014)
* **Descripción del Fallo:** A principios de 2014 se descubrió una vulnerabilidad crítica en la extensión *Heartbeat* de OpenSSL (registrada como **CVE-2014-0160**).
* **Impacto Técnico:** Permitía a cualquier atacante en Internet enviar una solicitud manipulada y leer hasta 64 kilobytes de memoria RAM del servidor sin dejar rastro en los registros.
* **Consecuencias:** Se expusieron en texto plano claves privadas RSA maestras de servidores web globales, credenciales de usuarios, tokens de sesión y mensajes privados.
* **Lección en Ciberseguridad:** Demuestra que la seguridad no depende únicamente de la solidez matemática de un algoritmo (como RSA o AES), sino de la **correcta implementación del software** y la necesidad urgente de aplicar **parches de seguridad continuos**.

---

### C. El Principio de Kerckhoffs: "La Oscuridad no es Seguridad"
Formulado por el criptógrafo militar Auguste Kerckhoffs en el siglo XIX:

> *"Un sistema criptográfico debe ser seguro incluso si todo lo relativo a su funcionamiento interno, diseño del algoritmo y código fuente es de conocimiento público, siempre y cuando la clave se mantenga en secreto."*

```
┌────────────────────────────────────────────────────────┐
│             PRINCIPIO DE KERCKHOFFS                    │
└──────────────────────────┬─────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          ▼                                 ▼
┌──────────────────┐               ┌──────────────────┐
│ SEGURIDAD POR    │               │ ESTÁNDARES       │
│ OSCURIDAD (Error)│               │ ABIERTOS (Éxito) │
├──────────────────┤               ├──────────────────┤
│ ❌ Algoritmos    │               │ ✅ Algoritmos    │
│    secretos      │               │    públicos      │
│ ❌ Criptoanálisis│               │ ✅ Auditados por │
│    deficiente    │               │    la comunidad  │
│ ❌ Fácil quiebre │               │ ✅ Secreto solo  │
│    al revelarse  │               │    en la clave   │
└──────────────────┘               └──────────────────┘
```

* **La Falacia de la Seguridad por Oscuridad (*Security through Obscurity*):** Diseñar un algoritmo propio en secreto y confiar en que los atacantes no descubrirán su mecánica es una receta para el desastre. Algoritmos secretos comerciales creados por empresas privadas han sido descifrados casi de inmediato tras realizar ingeniería inversa sobre sus ejecutables.
* Los algoritmos líderes (**AES**, **RSA**) son públicos y su código está disponible en internet; su invulnerabilidad no depende del misterio, sino de la complejidad matemática de sus ecuaciones.

## 7. Marco Normativo y Cumplimiento Legal

El uso de algoritmos criptográficos robustos no es solo una recomendación técnica, sino un requisito legal obligatorio:

1. **FIPS 140-3 (*Federal Information Processing Standard*):** Estándar de acreditación del gobierno de EE.UU. que valida que los módulos criptográficos utilizados por agencias y contratistas cumplan con requisitos estrictos de seguridad física y algorítmica.
2. **GDPR / RGPD (Art. 32):** Exige expresamente a cualquier organización que procese datos personales de residentes de la Unión Europea aplicar medidas técnicas como el **cifrado de datos personales** para garantizar un nivel de seguridad adecuado frente al riesgo.
3. **PCI DSS (Requisito 3 y 4):** Obliga a cifrar los datos de los titulares de tarjetas de pago tanto cuando están almacenados (*Data at Rest*) como cuando se transmiten a través de redes públicas abiertas (*Data in Transit*).

## Puntos Clave para Exámenes y Práctica Profesional

> [!IMPORTANT]
> * **Cifrado Simétrico:** Utiliza una sola clave compartida. Rápido, de bajo costo computacional, idóneo para grandes volúmenes de datos (**AES** con claves de 128, 192 o 256 bits es el estándar absoluto).
> * **Cifrado Asimétrico:** Utiliza un par de claves (pública para cifrar, privada para descifrar). Resuelve el problema de la distribución de claves (**RSA** con mínimo 2048 bits y **DSA** para firmas digitales).
> * **Enfoque Híbrido (TLS/HTTPS):** Combina cifrado asimétrico para el intercambio inicial y autenticación, y cifrado simétrico para el tráfico de la sesión en tiempo real.
> * **Fuerza Bruta y Longitud de Clave:** Las claves más largas aumentan exponencialmente la resistencia a ataques de fuerza bruta.
> * **Principio de Kerckhoffs:** La seguridad reside únicamente en mantener secreta la clave; los algoritmos criptográficos deben ser públicos y abiertos al escrutinio científico.
> * **Higiene de Software:** Incidentes como *Heartbleed* subrayan que el software criptográfico (como OpenSSL) debe auditarse y parchearse de forma continua.
