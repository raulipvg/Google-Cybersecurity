# Privacidad de la Información: Regulaciones y Cumplimiento Normativo

En esta lectura del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza la distinción técnica entre **Seguridad de la Información (InfoSec)** y **Privacidad de la Información**, las tres normativas internacionales más influyentes (**GDPR**, **PCI DSS**, **HIPAA**) y las diferencias metodológicas entre **Auditorías de Seguridad** y **Evaluaciones de Seguridad**.

---

## 1. Seguridad de la Información frente a Privacidad de la Información

Aunque a menudo se confunden en el lenguaje coloquial, representan dos dimensiones complementarias pero diferenciadas:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   PRIVACIDAD VS. SEGURIDAD DE LA INFORMACIÓN             │
├─────────────────────────────────────────┬────────────────────────────────┤
│       PRIVACIDAD DE LA INFORMACIÓN      │   SEGURIDAD DE LA INFORMACIÓN  │
│             (Data Privacy)              │            (InfoSec)           │
├─────────────────────────────────────────┼────────────────────────────────┤
│ • Se enfoca en los DERECHOS y el        │ • Se enfoca en las SALVAGUARDAS│
│   CONTROL de la persona sobre sus datos.│   TÉCNICAS para proteger datos.│
│ • ¿Qué se recopila? ¿Con quién se       │ • Mantiene los datos en reposo,│
│   comparte? ¿Hay opción de exclusión?   │   tránsito y uso lejos de      │
│ • Garantiza el consentimiento y la ética│   amenazas no autorizadas.     │
└─────────────────────────────────────────┴────────────────────────────────┘
```

```
┌─────────────────────────┐                                 ┌─────────────────────────┐
│       PRIVACIDAD        │ ──── Define las reglas y ─────► │        SEGURIDAD        │
│ (Consentimiento / Ley)  │      derechos del usuario       │  (Cifrado, IAM, FW)     │
└─────────────────────────┘                                 └─────────────────────────┘
```

* **Ejemplo Práctico:** Una tienda online solicita consentimiento para recopilar ubicación y edad con fines de marketing (**Privacidad**). Una vez obtenido el permiso, aplica cifrado AES y control de acceso estricto a esa base de datos (**Seguridad**).

> [!NOTE]
> La privacidad define **el qué y el por qué** (derecho y gobernanza del usuario); la seguridad implementa **el cómo** (defensa tecnológica y operativa).

## 2. Normativas Internacionales Destacadas

Las normativas establecen requisitos obligatorios que las empresas deben cumplir para operar legalmente y evitar multas millonarias:

```
┌────────────────────────────────────────────────────────┐
│               MARCOS REGULATORIOS GLOBALES             │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────────────┐
 ▼                ▼                        ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│     GDPR     │ │   PCI DSS    │ │      HIPAA       │
├──────────────┤ ├──────────────┤ ├──────────────────┤
│ Unión Europea│ │ Sector Pagos │ │ Salud / Sanidad  │
│ Privacidad   │ │ Transacciones│ │ Expedientes      │
│ global PII.  │ │ financieras. │ │ médicos (PHI).   │
└──────────────┘ └──────────────┘ └──────────────────┘
```

### Matriz de Regulaciones Clave:

| Regulación | Ámbito / Origen | Tipo de Datos Regulados | Requisito Principal | Alcance / Aplicación |
| :--- | :--- | :--- | :--- | :--- |
| **GDPR** (*General Data Protection Regulation*) | Unión Europea (UE) | Datos personales de individuos (PII). | Control total al usuario sobre sus datos (derecho de acceso, rectificación y supresión / olvido). | **Extraterritorial:** Aplica a cualquier empresa del mundo que procese datos de residentes de la UE. |
| **PCI DSS** (*Payment Card Industry Data Security Standard*) | Consejo de Seguridad de la Industria Financiera | Datos de titulares de tarjetas de crédito y débito. | Proteger transacciones y almacenamiento contra fraude, robo de números de tarjeta y CVV. | Universal para cualquier entidad que procese, transmita o almacene datos de tarjetas. |
| **HIPAA** (*Health Insurance Portability and Accountability Act*) | Ley Federal (EE.UU.) | Información médica y sanitaria protegida (PHI). | Prohíbe divulgar o transferir historiales clínicos sin autorización expresa del paciente. | Hospitales, clínicas, aseguradoras y proveedores de software de salud. |

## 3. Auditorías frente a Evaluaciones de Seguridad

El cumplimiento normativo y el mantenimiento de una postura sólida se sustentan en dos tipos de revisiones periódicas:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   AUDITORÍAS VS. EVALUACIONES                            │
├──────────────────────────────────┬───────────────────────────────────────┤
│       AUDITORÍA DE SEGURIDAD     │        EVALUACIÓN DE SEGURIDAD        │
│          (Security Audit)        │         (Security Assessment)         │
├──────────────────────────────────┼───────────────────────────────────────┤
│ • Revisión formal de CUMPLIMIENTO│ • Comprobación de RESISTENCIA TÉCNICA │
│   frente a un estándar o ley.    │   frente a amenazas reales.           │
│ • Frecuencia: ~1 vez al año.     │ • Frecuencia: Cada 3 a 6 meses.       │
│ • Ejecutores: Auditores internos │ • Ejecutores: Personal técnico        │
│   o firmas externas (terceros).  │   interno (preparación continua).     │
└──────────────────────────────────┴───────────────────────────────────────┘
```

### Flujo Operativo Integrado:

```
┌───────────────────────┐       Identifica debilidades       ┌───────────────────────┐
│     EVALUACIÓN        │ ─────────────────────────────────► │  CORRECCIÓN Y MEJORA  │
│ (Trimestral/Interna)  │                                    │  (Habilitar MFA, etc) │
└───────────────────────┘                                    └───────────┬───────────┘
                                                                         │
                                       Supera con éxito                  ▼
                                ┌────────────────────────────────────────────────────┐
                                │                 AUDITORÍA FORMAL                   │
                                │                 (Anual/Certificación)              │
                                └────────────────────────────────────────────────────┘
```

> [!TIP]
> **Ejemplo de Coordinación:** Una **auditoría** comprueba formalmente que las cuentas de administrador tengan MFA obligatorio conforme a la norma. Posteriormente, una **evaluación interna** descubre que usuarios estándar usan contraseñas débiles, recomendando extender MFA a toda la organización antes de la siguiente auditoría anual.

---

## Puntos Clave

> [!IMPORTANT]
> * **Binomio Indisociable:** La privacidad otorga la potestad de control al titular de los datos; la seguridad técnica hace cumplir dicho mandato.
> * **Efecto Extraterritorial del GDPR:** Cualquier organización que procese datos de ciudadanos europeos está sujeta a su cumplimiento, sin importar su sede física.
> * **Protección de Tarjetas y Salud:** **PCI DSS** blinda el ecosistema financiero y **HIPAA** garantiza la confidencialidad estricta de la información médica (**PHI**).
> * **Ciclo de Verificación:** Las **evaluaciones internas frecuentes (3-6 meses)** preparan a la organización para superar las **auditorías formales anuales**, previniendo incidentes y sanciones regulatorias.
