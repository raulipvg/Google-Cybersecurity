# El Ciclo de Vida de los Datos y Gobierno de la Información

En esta lectura del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza el **Ciclo de Vida de los Datos** en sus 5 etapas consecutivas, la estructura y roles del **Gobierno de Datos** (*Data Governance*), y la protección de información legalmente regulada: **PII**, **SPII** y **PHI** bajo marcos de cumplimiento normativo como **HIPAA** y **GDPR**.

---

## 1. Las 5 Etapas del Ciclo de Vida de los Datos

El **ciclo de vida de los datos** describe la trayectoria completa de la información desde el instante de su creación o ingesta hasta su eliminación definitiva:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                CICLO DE VIDA DE LOS DATOS                              │
├──────────────┬──────────────┬──────────────┬──────────────────────────┬────────────────┤
│ 1. RECOPILAR │ 2. ALMACENAR │  3. UTILIZAR │       4. ARCHIVAR        │  5. DESTRUIR   │
│   (Collect)  │   (Store)    │    (Use)     │        (Archive)         │   (Destroy)    │
├──────────────┼──────────────┼──────────────┼──────────────────────────┼────────────────┤
│ Ingesta o    │ Guardado en  │ Acceso,      │ Retención a largo plazo  │ Borrado seguro │
│ captura de   │ repositorios │ consulta y   │ de datos inactivos para  │ irreversible   │
│ nueva info.  │ seguros/BD.  │ procesado.   │ cumplimiento legal.      │ y certificado. │
└──────────────┴──────────────┴──────────────┴──────────────────────────┴────────────────┘
```

```
┌─────────────┐       ┌─────────────┐       ┌─────────────┐       ┌─────────────┐       ┌─────────────┐
│ 1. RECOGER  │ ────► │2. ALMACENAR │ ────► │ 3. UTILIZAR │ ────► │ 4. ARCHIVAR │ ────► │ 5. DESTRUIR │
│  (Collect)  │       │   (Store)   │       │    (Use)    │       │  (Archive)  │       │  (Destroy)  │
└─────────────┘       └─────────────┘       └─────────────┘       └─────────────┘       └─────────────┘
  Captura/API          Cifrado Reposo        Control Acceso        Copias Frías          Sanitización
```

### Controles Defensivos por Etapa:
1. **Recopilar (*Collect*):** Minimización de datos (recolectar solo lo estrictamente necesario) y validación de entradas.
2. **Almacenar (*Store*):** Cifrado robusto en reposo (*AES-256*), controles de redundancia y copias de seguridad periódicas.
3. **Utilizar (*Use*):** Control de acceso basado en roles (*RBAC*), registro de auditoría (*logging*) y enmascaramiento de datos sensibles.
4. **Archivar (*Archive*):** Almacenamiento secundario inmutable (*WORM - Write Once, Read Many*) conforme a los plazos legales de retención.
5. **Destruir (*Destroy*):** Sanitización de medios, desmagnetización (*degaussing*), sobreescritura criptográfica o destrucción física de discos para evitar la recuperación no autorizada.

## 2. Roles Clave en el Gobierno de Datos (*Data Governance*)

El **Gobierno de Datos** es el marco de políticas y responsabilidades que asegura que la información permanezca precisa, privada, disponible y protegida durante todo su ciclo vital.

```
┌────────────────────────────────────────────────────────┐
│                   ROLES DE GOBIERNO DE DATOS           │
└──────────────────────────┬─────────────────────────────┘
                           │
 ┌────────────────┬────────┴───────────────┐
 ▼                ▼                        ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────────┐
│  PROPIETARIO │ │   CUSTODIO   │ │  ADMINISTRADOR   │
│ (Data Owner) │ │(Data Custodian││  (Data Steward)  │
├──────────────┤ ├──────────────┤ ├──────────────────┤
│ Decide quién │ │ Administra y │ │ Supervisa el uso │
│ accede, edita│ │ protege los  │ │ y cumplimiento de│
│ y destruye.  │ │ sistemas/TI. │ │ las políticas.   │
└──────────────┘ └──────────────┘ └──────────────────┘
```

| Rol | Responsabilidades Principales | Perfil Típico |
| :--- | :--- | :--- |
| **Propietario de Datos (*Data Owner*)** | Clasifica la información y autoriza formalmente quién tiene derecho a acceder, modificar o divulgar los datos de su unidad de negocio. | Directores de departamento, gerentes de finanzas o RRHH. |
| **Custodio de Datos (*Data Custodian*)** | Implementa los controles técnicos de seguridad, configuración de almacenamiento, respaldos y cifrado para proteger la información. | **Analistas de ciberseguridad**, administradores de bases de datos (DBA) e ingenieros de TI. |
| **Administrador de Datos (*Data Steward*)** | Garantiza la calidad de los datos, vela por el cumplimiento de las políticas de gobernanza en el día a día y asesora sobre su uso ético. | Oficiales de privacidad, analistas de gobierno de datos y auditores internos. |

> [!NOTE]
> Como profesional de seguridad, su rol habitual será el de **Custodio de Datos**, siendo el responsable directo de velar por que los datos no sufran accesos no autorizados, robo o alteraciones indebidas.

## 3. Tipologías de Información Protegida Legalmente

Los marcos regulatorios exigen a las organizaciones aplicar salvaguardas especiales sobre ciertas categorías de datos personales y sensibles:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                    CATEGORÍAS DE DATOS REGULADOS                         │
├───────────────────┬──────────────────────────────┬───────────────────────┤
│       PII         │            SPII              │         PHI           │
│ (Identificación)  │      (PII Sensible)          │      (Salud)          │
├───────────────────┼──────────────────────────────┼───────────────────────┤
│ Información para  │ Subconjunto de alto impacto: │ Información médica,   │
│ identificar a un  │ finanzas, biométricos y      │ diagnósticos y estado │
│ individuo.        │ credenciales.                │ de salud.             │
└───────────────────┴──────────────────────────────┴───────────────────────┘
```

### Matriz Comparativa de Datos Protegidos:

| Acrónimo | Denominación Completa | Descripción y Alcance | Ejemplos de Datos | Marco Regulatorio |
| :---: | :--- | :--- | :--- | :--- |
| **PII** | *Personally Identifiable Information* | Información que permite identificar, contactar o ubicar directa o indirectamente a una persona física. | Nombre completo, dirección postal, correo electrónico, número de teléfono. | **GDPR**, CCPA, leyes de privacidad generales. |
| **SPII** | *Sensitive Personally Identifiable Information* | Datos personales cuya divulgación o robo acarrea consecuencias graves (fraude, suplantación). | Número de Seguridad Social (SSN), número de cuenta bancaria, tarjetas de crédito, contraseñas, datos biométricos. | **PCI DSS**, leyes federales de identidad. |
| **PHI** | *Protected Health Information* | Información médica pasada, presente o futura sobre el estado de salud físico o mental, o pagos de servicios sanitarios. | Historiales clínicos, resultados de laboratorio, recetas médicas, números de póliza de seguro médico. | **HIPAA** (EE.UU.), **GDPR** (Art. 9 - Categorías Especiales en la UE). |

## Puntos Clave

> [!IMPORTANT]
> * **Continuidad del Ciclo de Vida:** La seguridad debe operar de extremo a extremo: **Recopilar ➔ Almacenar ➔ Utilizar ➔ Archivar ➔ Destruir**.
> * **Destrucción Segura:** El fin del ciclo de vida exige la sanitización y destrucción irreversible de los medios para evitar ataques de recuperación de datos (*dumpster diving* o análisis forense no autorizado).
> * **Triángulo de Gobierno:** La colaboración entre **Owner** (propiedad), **Custodian** (protección técnica) y **Steward** (cumplimiento diario) es la base del gobierno de la información.
> * **Régimen Regulatorio Estricto:** La manipulación de **PII**, **SPII** y **PHI** conlleva obligaciones legales bajo normativas como **HIPAA** y **GDPR**, acarreando severas penalizaciones financieras en caso de filtración.
