# Pruebas de Penetración (Penetration Testing): Hacking Ético, Dinámicas Red/Blue/Purple y Metodologías de Caja

En esta guía exhaustiva del **Curso 5: Activos, Amenazas y Vulnerabilidades**, se analiza en profundidad la disciplina de las **Pruebas de Penetración** (*Penetration Testing / Pen Testing*), la diferencia entre identificar y explotar vulnerabilidades, las dinámicas de equipos (**Red Team**, **Blue Team** y **Purple Team**), las estrategias de evaluación (**Caja Negra**, **Caja Blanca** y **Caja Gris**), las fases de ejecución metodológica (*PTES / NIST SP 800-115*), los programas de recompensas por errores (**Bug Bounty**), y el perfil profesional del auditor de seguridad ofensiva.

---

## 1. ¿Qué es una Prueba de Penetración (*Pen Test*)?

Una **prueba de penetración** (*Penetration Testing*) es un **ataque cibernético simulado y formalmente autorizado** contra los sistemas, redes, aplicaciones web, APIs, infraestructuras en la nube y personal (ingeniería social) de una organización, ejecutado por especialistas en seguridad (*Penetration Testers* o *Hackers Éticos*) para descubrir y explotar debilidades antes de que lo hagan actores maliciosos.

```
┌──────────────────────────────────────────────────────────────────────────┐
│             EVALUACIÓN DE VULNERABILIDADES VS. PRUEBAS DE PENETRACIÓN    │
├─────────────────────────────────────┬────────────────────────────────────┤
│   EVALUACIÓN DE VULNERABILIDADES    │       PRUEBAS DE PENETRACIÓN       │
│      (Vulnerability Assessment)     │        (Penetration Testing)       │
├─────────────────────────────────────┼────────────────────────────────────┤
│ • IDENTIFICA y cataloga fallos.     │ • EXPLOTA activamente los fallos   │
│ • Proceso no intrusivo.             │   descubiertos para medir el daño. │
│ • "¿Qué puertas están sin llave?"   │ • "¿Hasta dónde puede llegar el    │
│ • Alcance amplio y general.         │   atacante si cruza esa puerta?"   │
│ • Frecuencia: Semanal / Mensual.    │ • Frecuencia: Anual o por cambios. │
└─────────────────────────────────────┴────────────────────────────────────┘
```

> [!NOTE]
> **Obligatoriedad Normativa:** Las pruebas de penetración son un requisito de cumplimiento obligatorio en estándares regulatorios internacionales como **PCI DSS** (Requisito 11.3), **HIPAA**, **ISO 27001** y **SOC 2 Type II**.

## 2. Dinámicas de Equipos de Seguridad: Red, Blue y Purple Team

Para poner a prueba las defensas organizacionales desde múltiples perspectivas, la ciberseguridad moderna organiza sus ejercicios a través de equipos especializados por colores:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    DINÁMICAS DE EQUIPOS DE CIBERSEGURIDAD                    │
└──────────────────────────────────────────────────────────────────────────────┘

 ┌──────────────────────────┐                      ┌──────────────────────────┐
 │    EQUIPO ROJO (Red)     │                      │    EQUIPO AZUL (Blue)    │
 │       (Ofensivo)         │                      │       (Defensivo)        │
 ├──────────────────────────┤                      ├──────────────────────────┤
 │ • Simula a los atacantes │                      │ • Defiende la red y      │
 │   reales del mundo.      │                      │   monitorea eventos.     │
 │ • Emplea tácticas TTPs   │                      │ • Responde a incidentes  │
 │   de cibercriminales.    │                      │   en el SOC / SIEM.      │
 └─────────────┬────────────┘                      └────────────┬─────────────┘
               │                                                │
               └───────────────────────┬────────────────────────┘
                                       ▼
                         ┌───────────────────────────┐
                         │   EQUIPO PÚRPURA (Purple) │
                         │       (Colaborativo)      │
                         ├───────────────────────────┤
                         │ • Ejercicio conjunto.     │
                         │ • El Red Team enseña cómo │
                         │   atacó; el Blue Team     │
                         │   ajusta sus detecciones. │
                         └───────────────────────────┘
```

### Roles y Responsabilidades:

| Equipo | Misión Principal | Actividades Típicas | Perfil de Especialista |
| :--- | :--- | :--- | :--- |
| **Equipo Rojo (*Red Team*)** | Evaluar la efectividad de las defensas simulando un adversario real con objetivos específicos (exfiltrar datos, comprometer el Directorio Activo). | Hacking ético, explotación de vulnerabilidades, movimientos laterales, phishing e ingeniería social dirigida. | Pentesters certificados (OSCP, CEH, GPEN), investigadores de exploits. |
| **Equipo Azul (*Blue Team*)** | Proteger los activos de la empresa, detectar intrusiones en tiempo real, contener brechas y restaurar sistemas. | Análisis de logs en SIEM, caza de amenazas (*Threat Hunting*), administración de EDR, configuración de firewalls e IPS. | Analistas de SOC, ingenieros de seguridad defensiva, especialistas DFIR. |
| **Equipo Púrpura (*Purple Team*)** | Fomentar la colaboración continua entre ataque y defensa para cerrar brechas de visibilidad. | Simulaciones de ataque paso a paso donde el Red Team ejecuta una técnica y el Blue Team valida si sus alertas generaron una detección adecuada. | Coordinadores de seguridad, arquitectos defensivos y auditores avanzados. |

## 3. Estrategias de Pruebas de Penetración según el Nivel de Conocimiento

Antes de iniciar un ejercicio de penetración, se debe pactar el nivel de información y acceso previo concedido al evaluador:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   ESTRATEGIAS SEGÚN EL NIVEL DE ACCESO                   │
├───────────────────┬──────────────────────────────┬───────────────────────┤
│    CAJA NEGRA     │          CAJA GRIS           │      CAJA BLANCA      │
│   (Black-Box)     │          (Gray-Box)          │      (White-Box)      │
├───────────────────┼──────────────────────────────┼───────────────────────┤
│ Cero conocimiento │ Conocimiento y acceso        │ Acceso total a código │
│ previo del sistema│ parcial (usuario estándar    │ fuente, diagramas de  │
│ (simula atacante  │ o credenciales básicas).     │ red y credenciales de │
│ externo).         │ Simula un Insider o cuenta   │ administrador. Máxima │
│                   │ de soporte comprometida.     │ profundidad técnica.  │
└───────────────────┴──────────────────────────────┴───────────────────────┘
```

```
CONOCIMIENTO DEL ENTORNO
◄─────────────────────────────────────────────────────────────────────────────►
CERO CONOCIMIENTO              ACCESO PARCIAL                 ACCESO TOTAL
[ Caja Negra / Black-Box ]     [ Caja Gris / Gray-Box ]       [ Caja Blanca / White-Box ]
• Mayor realismo externo       • Simula Insider / Empleado    • Máxima cobertura de código
• Requiere mucho OSINT         • Enfoque costo-eficiente      • Análisis exhaustivo
```

### Matriz Comparativa de Estrategias:

| Estrategia | Información Entregada al Pentester | Escenario Simulado | Ventajas | Desventajas |
| :--- | :--- | :--- | :--- | :--- |
| **Caja Negra (*Black-Box / Closed-Box*)** | Únicamente el nombre de dominio o rango de IPs públicas; cero credenciales ni diagramas. | Ciberatacante externo no autenticado en Internet. | **Simulación 100% realista** del comportamiento de un hacker real. | Mayor tiempo invertido en reconocimiento; puede pasar por alto vulnerabilidades profundas. |
| **Caja Gris (*Gray-Box / Partial-Knowledge*)** | Credenciales de un usuario estándar, documentación de APIs y acceso a la red interna. | Empleado descontento (*Insider*) o atacante que ya robó una credencial básica. | **Equilibrio óptimo**: enfoca el tiempo en vulnerabilidades de lógica y escalada sin perder semanas en reconocimiento. | Requiere coordinación para el aprovisionamiento de cuentas de prueba. |
| **Caja Blanca (*White-Box / Open-Box*)** | Acceso al código fuente (SAST), esquemas de bases de datos, diagramas de red y roles de administrador. | Desarrollador malicioso o auditoría de seguridad integral en pre-lanzamiento. | **Cobertura máxima**: detecta fallos de arquitectura y errores sutiles de programación ocultos. | Menos realista respecto al tiempo que le tomaría a un atacante externo. |

## 4. Las Fases Metodológicas de una Prueba de Penetración

Los ejercicios profesionales siguen estándares formales de la industria (como el **PTES - *Penetration Testing Execution Standard*** o **NIST SP 800-115**):

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                  FASES DEL CICLO DE PENETRATION TESTING                      │
└──────────────────────────────────────────────────────────────────────────────┘

 1. PRE-COMPROMISO     ➔ Definición del alcance, reglas de combate (RoE) y firma legal.
           │
           ▼
 2. RECONOCIMIENTO     ➔ Recolección de información pasiva y activa (OSINT, DNS, Nmap).
           │
           ▼
 3. ANÁLISIS DE FALLOS ➔ Identificación de puntos de entrada y vulnerabilidades explotables.
           │
           ▼
 4. EXPLOTACIÓN        ➔ Compromiso del sistema y obtención de acceso inicial.
           │
           ▼
 5. POST-EXPLOTACIÓN   ➔ Escalada de privilegios (root/admin), persistencia y mov. lateral.
           │
           ▼
 6. REPORTE Y ACCIÓN   ➔ Informe ejecutivo y técnico detallado con pasos de remediación.
```

## 5. Programas de Recompensas por Errores (*Bug Bounty Programs*)

Los **programas de Bug Bounty** son iniciativas organizacionales donde empresas abren sus aplicaciones a la comunidad global de hackers éticos independientes, ofreciendo **compensaciones económicas (*bounties*)** por reportar vulnerabilidades de forma responsable antes de que sean explotadas.

## 6. Ruta Profesional y Habilidades Clave del Penetration Tester

El perfil del pentester exige una combinación equilibrada de competencias técnicas profundas y habilidades de comunicación:

1. **Fundamentos de Redes y Protocolos:** Comprensión rigurosa del modelo TCP/IP, enrutamiento, DNS, HTTP/S, captura de tráfico con *Wireshark*.
2. **Dominio de Sistemas Operativos:** Administración avanzada de distribuciones Linux (*Kali Linux*, *Parrot OS*) y entornos corporativos Windows (*Active Directory*, *PowerShell*).
3. **Lenguajes de Scripting y Programación:** Desarrollo de scripts en **Python**, **Bash**, **Go** o **C/C++** para automatizar ataques y modificar exploits.
4. **Manejo de Herramientas Ofensivas Estándar:** *Nmap*, *Burp Suite Professional*, *Metasploit Framework*, *Hashcat*, *BloodHound*, *SQLmap*.
5. **Redacción de Informes Técnicos y Ejecutivos:** Capacidad de traducir vulnerabilidades técnicas complejas en impacto de negocio entendible para directores financieros y ejecutivos.

## Puntos Clave para Exámenes y Práctica Profesional

> [!IMPORTANT]
> * **Definición de Pen Test:** Ataque simulado **autorizado** que **explota** vulnerabilidades para evaluar el impacto real en la seguridad.
> * **Equipos de Seguridad:**
>   * **Red Team:** Enfoque ofensivo (simula al atacante).
>   * **Blue Team:** Enfoque defensivo (protege, detecta y responde en el SOC).
>   * **Purple Team:** Ejercicio colaborativo de retroalimentación mutua.
> * **Estrategias de Caja:**
>   * **Caja Negra:** Cero información previa (máximo realismo externo).
>   * **Caja Blanca:** Acceso total a código y diagramas (máxima profundidad).
>   * **Caja Gris:** Acceso limitado (simula insider o credencial comprometida).
> * **Bug Bounty:** Programas crowdsourced en plataformas como **HackerOne** donde se recompensa económicamente el reporte ético de vulnerabilidades.
