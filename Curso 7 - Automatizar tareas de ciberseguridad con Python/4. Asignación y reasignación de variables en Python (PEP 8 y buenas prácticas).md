# Asignación, Reasignación y Buenas Prácticas de Variables en Python

En esta cuarta entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se explora a fondo el funcionamiento de las **variables**, el modelo de referencias en memoria del intérprete, las operaciones de **asignación y reasignación**, y las reglas sintácticas y directrices de estilo del estándar **PEP 8**. Para un analista de seguridad, dominar el manejo de variables es esencial para mantener la trazabilidad de estados en scripts forenses, contadores de detección de fuerza bruta y gestión dinámica de listas de control de acceso.

---

## 1. Naturaleza de las Variables y el Modelo de Memoria en Python

En muchos lenguajes tradicionales (como C o C++), una variable se concibe como una "caja" de memoria estática con un tipo y tamaño predeterminado donde se depositan los datos binarios. 

En **Python**, sin embargo, el modelo conceptual y operativo es diferente: **las variables son etiquetas o referencias con nombre (*names / references*) que apuntan a objetos creados en la memoria dinámica (*Heap*)**.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                    MODELO DE REFERENCIAS Y MEMORIA EN CPYTHON                             │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌──────────────────────────────────────┐     │     ┌──────────────────────────────────────┐
 │       ESPACIO DE NOMBRES (NAMES)     │     │     │        OBJETOS EN MEMORIA (HEAP)     │
 ├──────────────────────────────────────┤     │     ├──────────────────────────────────────┤
 │  username ───────────────────────────┼─────┼───► │ Objeto str: "nzhao"                  │
 │                                      │     │     │ Tipo: <class 'str'> | RefCount: 1    │
 └──────────────────────────────────────┘     │     └──────────────────────────────────────┘
```

* **Operador de Asignación (`=`):** No significa igualdad matemática; representa una orden de **enlace de nombre (*name binding*)**. Evalúa la expresión situada a la derecha del signo igual y vincula el identificador de la izquierda a ese objeto en memoria.
* **Inspección de Identidad con `id()`:** La función integrada `id()` devuelve la dirección de memoria única del objeto al que apunta una variable:
  ```python
  ip_origen = "192.168.1.100"
  print(id(ip_origen)) # Muestra la dirección de memoria (ej. 140238491028)
  ```

## 2. Operaciones de Asignación y Reasignación

### 2.1. Asignación Inicial
Al asignar un valor por primera vez, el intérprete crea el objeto con su tipo correspondiente en memoria e inicializa la variable en la tabla de símbolos:

```python
# Asignación inicial de variables de seguridad
username = "nzhao"           # Asignación de cadena (str)
login_attempts = 1           # Asignación de entero (int)
is_authenticated = False     # Asignación de booleano (bool)
```

---

### 2.2. Reasignación Dinámica
Cuando se reasigna una variable existente, la "etiqueta" se despega del objeto antiguo y se vincula a uno nuevo. El objeto original, si deja de tener referencias activas, es destruido automáticamente por el **Recolector de Basura (*Garbage Collector*)**:

```python
username = "nzhao"   # username apunta a "nzhao"
username = "zhao2"   # username ahora apunta a "zhao2"
```

```
ESTADO TRAS LA REASIGNACIÓN:

  username ────(desvinculado)────► [ Objeto "nzhao" ] ──► (Recolector de Basura)
      │
      └──────────────────────────► [ Objeto "zhao2" ]
```

---

### 2.3. Asignación de Variable a Variable (Múltiples Referencias)
Es posible vincular dos variables al mismo objeto asignando una variable a otra:

```python
username = "nzhao"
old_username = username
```

```
ASIGNACIÓN VARIABLE A VARIABLE:

  username ──────┐
                 ├────────► [ Objeto str: "nzhao" ]  (RefCount = 2)
  old_username ──┘
```

Ambas variables apuntan exactamente a la misma posición de memoria (`id(username) == id(old_username)`).

---

### 2.4. Caso de Uso Forense: Preservación de Estados y Trazabilidad
En tareas de auditoría e investigación de incidentes, reasignar variables sin respaldar el estado previo destruiría la evidencia. El patrón de preservación de estado permite registrar la transición:

```python
# Registro de cambio de identificador de usuario en Directorio Activo
username = "nzhao"
old_username = username  # Preserva el estado anterior para la bitácora
username = "zhao2"       # Actualiza al nuevo estado operativo

print("Identificador anterior:", old_username) # nzhao
print("Identificador actual:  ", username)     # zhao2
```

---

### 2.5. Técnicas Avanzadas de Asignación

#### Asignación Múltiple y Desempaquetado (*Unpacking*):
Permite inicializar múltiples variables en una sola línea limpia y legible:
```python
# Asignación simultánea de telemetría de red
ip_src, port_src, protocol = "10.0.0.15", 53, "UDP"

# Intercambio de valores sin variable temporal intermedia
activo_primario = "Firewall-A"
activo_secundario = "Firewall-B"
activo_primario, activo_secundario = activo_secundario, activo_primario
```

#### Operadores de Asignación Aumentada (*In-Place Operators*):
Abreviaturas que combinan una operación aritmética con la reasignación, indispensables para contadores en bucles de monitoreo:
```python
failed_attempts = 0

failed_attempts += 1  # Equivalente a: failed_attempts = failed_attempts + 1
failed_attempts += 1  # Incrementa a 2
failed_attempts *= 2  # Multiplica y reasigna -> 4
```

## 3. Reglas Sintácticas Obligatorias de Nomenclatura

El intérprete de Python impone restricciones técnicas estrictas. Incumplir estas reglas genera un error de sintaxis (`SyntaxError`) impidiendo la ejecución del script.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                       REGLAS SINTÁCTICAS OBLIGATORIAS EN PYTHON                           │
├──────────────────────────┬────────────────────────────────────────────────────────────────┤
│ Caracteres Válidos       │ Solo letras (a-z, A-Z), dígitos (0-9) y guiones bajos (_).     │
│                          │ Válidos: `date_3`, `username`, `interval2`, `_temp_hash`.      │
├──────────────────────────┼────────────────────────────────────────────────────────────────┤
│ Restricción Inicial      │ **Nunca puede comenzar con un número.**                        │
│                          │ Inválido: `3_date`, `2fa_token` (Provoca SyntaxError).         │
│                          │ Válido:   `date_3`, `token_2fa`.                               │
├──────────────────────────┼────────────────────────────────────────────────────────────────┤
│ Sensibilidad a Mayúsculas│ **Python es Case-Sensitive.**                                  │
│ (*Case-Sensitivity*)     │ `time`, `Time`, `TIME` y `timE` son cuatro variables           │
│                          │ totalmente distintas en el espacio de nombres.                 │
├──────────────────────────┼────────────────────────────────────────────────────────────────┤
│ Palabras Reservadas      │ **No se pueden usar palabras clave del lenguaje.**             │
│ (*Keywords*)             │ Términos como `True`, `False`, `if`, `while`, `for`, `def`.   │
└──────────────────────────┴────────────────────────────────────────────────────────────────┘
```

### 3.1. Lista de Palabras Reservadas (*Keywords*)
Python reserva palabras clave para su propia gramática. La biblioteca estándar `keyword` permite inspeccionarlas:

```python
import keyword
print(keyword.kwlist)
```

```text
['False', 'None', 'True', 'and', 'as', 'assert', 'async', 'await', 
 'break', 'class', 'continue', 'def', 'del', 'elif', 'else', 'except', 
 'finally', 'for', 'from', 'global', 'if', 'import', 'in', 'is', 
 'lambda', 'nonlocal', 'not', 'or', 'pass', 'raise', 'return', 
 'try', 'while', 'with', 'yield']
```

> [!CAUTION]
> **El Peligro de Sombrear Funciones Integradas (*Built-in Shadowing*):**
> Python permite sintácticamente asignar variables con nombres de funciones nativas (como `print = 5` o `str = "texto"`). Aunque el intérprete no arroja un error inmediato, **sobrescribe la función en el espacio de nombres global**, provocando que llamadas posteriores como `print("hola")` fallen con `TypeError: 'int' object is not callable`. Jamás use nombres como: `print`, `type`, `id`, `input`, `list`, `dict`, `set`, `max`, `min`.

## 4. Convenciones de Estilo y Guía Oficial PEP 8

Más allá de lo que el intérprete tolera, la comunidad de seguridad y desarrollo sigue la guía de estilo oficial **PEP 8 (*Python Enhancement Proposal 8*)** para garantizar código legible, mantenible y profesional.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                    CONVENCIONES DE NOMENCLATURA: PEP 8 vs. OTRAS GUÍAS                    │
├──────────────────────┬────────────────────────┬───────────────────────────────────────────┤
│ Convención           │ Formato / Ejemplo      │ Uso Estándar en Python (PEP 8)            │
├──────────────────────┼────────────────────────┼───────────────────────────────────────────┤
│ **snake_case**       │ `num_login_attempts`   │ **Obligatorio para variables y funciones**│
│                      │ `device_id`            │ Palabras en minúsculas separadas por `_`. │
├──────────────────────┼────────────────────────┼───────────────────────────────────────────┤
│ **SCREAMING_SNAKE**  │ `MAX_RETRIES = 5`      │ **Constantes globales inmutables**        │
│                      │ `DEFAULT_PORT = 443`   │ Valores fijos de configuración del SOC.   │
├──────────────────────┼────────────────────────┼───────────────────────────────────────────┤
│ **camelCase**        │ `loginAttempt`         │ Común en Java/JavaScript; **desaconsejado │
│                      │ `statusUpdate`         │ en variables de Python** por PEP 8.       │
├──────────────────────┼────────────────────────┼───────────────────────────────────────────┤
│ **PascalCase**       │ `SecurityIncident`     │ Reservado exclusivamente para **Clases**. │
└──────────────────────┴────────────────────────┴───────────────────────────────────────────┘
```

### 4.1. Principios de Legibilidad y Claridad
1. **Nombres Significativos y Descriptivos:**
   * ❌ Inadecuado: `x = 5`, `data = "10.0.0.1"`, `variable_that_equals_3 = 3`
   * ✔️ Adecuado: `max_failed_logins = 5`, `target_ip = "10.0.0.1"`
2. **Evitar Ambigüedad y Nombres Similares:**
   Variables como `start_time`, `starting_time` y `time_starting` en el mismo script generan confusiones graves durante el análisis bajo presión en incidentes.
3. **Equilibrio de Longitud:** El nombre debe ser tan corto como sea posible y tan largo como sea necesario para explicar su función sin rodeos.

## 5. Casos Prácticos en Operaciones de Seguridad (SOC)

### Caso 1: Detección de Ataque de Fuerza Bruta con Umbral de Alerta

```python
# Configuración global de umbrales defensivos (Constantes en SCREAMING_SNAKE_CASE)
MAX_LOGIN_THRESHOLD = 3
TARGET_SERVICE = "SSH"

# Variables de seguimiento de estado (snake_case)
user_account = "root"
attacker_ip = "203.0.113.42"
failed_attempt_count = 0

# Simulación de intentos de intrusión detectados en /var/log/auth.log
failed_attempt_count += 1
failed_attempt_count += 1
failed_attempt_count += 1

# Evaluación lógica del estado
if failed_attempt_count >= MAX_LOGIN_THRESHOLD:
    alert_triggered = True
    print(f"[ALERTA CRÍTICA] Ataque contra {user_account} desde {attacker_ip}.")
    print(f"Total de intentos fallidos: {failed_attempt_count} en servicio {TARGET_SERVICE}.")
```

---

### Caso 2: Auditoría de Cambio de Regla de Cortafuegos

```python
# Estado original de la lista blanca de acceso
firewall_policy_id = "POL-9921"
active_allowed_cidr = "192.168.1.0/24"

# Se requiere modificar la subred debido a una migración de red
previous_allowed_cidr = active_allowed_cidr # Preservar evidencia forense
active_allowed_cidr = "10.240.0.0/16"       # Reasignación operativa

# Generar traza de auditoría para el SIEM
print(f"Auditoría de Póliza {firewall_policy_id}:")
print(f"  Regla previa contenía:  {previous_allowed_cidr}")
print(f"  Regla actual modificada: {active_allowed_cidr}")
```

## 6. Puntos Clave para el Analista de Ciberseguridad

* **Variables como Referencias:** Las variables no son cajas fijas, sino nombres que apuntan a objetos en memoria dinámica. Asignar `b = a` hace que ambas variables apunten al mismo objeto.
* **Reasignación Limpia:** Al reasignar una variable, se enlaza a un nuevo objeto. Si se requiere trazabilidad forense, se debe respaldar el valor en una variable previa (`old_value = current_value`) antes de modificarla.
* **Sintaxis Estricta:** Las variables deben iniciar con letra o guión bajo, jamás con un número, y distinguen rigurosamente entre mayúsculas y minúsculas (*case-sensitive*).
* **Guía PEP 8:** Utilizar siempre `snake_case` para variables y funciones (`failed_attempts`), y `SCREAMING_SNAKE_CASE` para constantes operativas del SOC (`MAX_THRESHOLD`).
* **Protección contra Shadowing:** Evitar utilizar palabras reservadas o nombres de funciones nativas (`print`, `str`, `list`, `id`) como nombres de variables para prevenir comportamientos anómalos en el script.
