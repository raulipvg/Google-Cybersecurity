# Estructuras Condicionales y Operadores Lógicos en Python: Control de Flujo para Ciberseguridad

En esta quinta entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se analizan en profundidad las **estructuras condicionales** (`if`, `elif`, `else`), los **operadores relacionales** y los **operadores lógicos compuestos** (`and`, `or`, `not`). El control de flujo es el núcleo computacional de la ciberseguridad: permite que los scripts del SOC tomen decisiones dinámicas para clasificar eventos de tráfico web, bloquear ataques de fuerza bruta en tiempo real, filtrar alertas de SIEM y verificar niveles de privilegio y autenticación multifactor (MFA).

---

## 1. Fundamentos del Control de Flujo y Toma de Decisiones

Por defecto, un programa en Python se ejecuta de forma estrictamente secuencial, de arriba hacia abajo. Las **sentencias condicionales** introducen bifurcaciones en el camino de ejecución evaluando una expresión lógica:
* Si la condición evalúa a **`True`**, el intérprete ingresa y ejecuta el bloque de código asociado.
* Si la condición evalúa a **`False`**, el intérprete salta ese bloque y evalúa la siguiente instrucción o alternativa.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                          BIFURCACIÓN CONDICIONAL EN TIEMPO DE EJECUCIÓN                   │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
                                              ▼
                                    /───────────────────\
                                   <  ¿Condición Verdad? >
                                    \───────────────────/
                                      │               │
                             [ True ] │               │ [ False ]
                                      ▼               ▼
                        ┌──────────────────┐    ┌──────────────────┐
                        │ Ejecutar Bloque  │    │ Saltar o Evaluar │
                        │   de Acción      │    │  Rama Alternativa│
                        └─────────┬────────┘    └─────────┬────────┘
                                  │                       │
                                  └───────────┬───────────┘
                                              ▼
                                    Continuar Ejecución
```

## 2. Operadores de Comparación (Relacionales)

Las condiciones se construyen primordialmente comparando dos o más operandos mediante **operadores relacionales**. El resultado de cualquier comparación es siempre un valor booleano puro (`True` o `False`).

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                    OPERADORES DE COMPARACIÓN EN PYTHON PARA EL SOC                        │
├───────────┬──────────────────────┬────────────────────────────────────────────────────────┤
│ Operador  │ Significado Lógico   │ Ejemplo Operativo en Ciberseguridad                    │
├───────────┼──────────────────────┼────────────────────────────────────────────────────────┤
│ `==`      │ Igual a              │ `status == 200` (Verifica código de éxito HTTP)        │
│ `!=`      │ No igual a / Diferente│ `protocol != "HTTPS"` (Detecta tráfico no cifrado)     │
│ `>`       │ Mayor que            │ `failed_logins > 5` (Alerta de ataque de fuerza bruta) │
│ `<`       │ Menor que            │ `port < 1024` (Identifica puertos bien conocidos/root) │
│ `>=`      │ Mayor o igual que    │ `cvss_score >= 7.0` (Clasifica vulnerabilidad alta)    │
│ `<=`      │ Menor o igual que    │ `packet_size <= 64` (Detecta paquetes anómalos o vacíos│
└───────────┴──────────────────────┴────────────────────────────────────────────────────────┘
```

### Comparación de Cadenas de Texto
Los operadores `==` y `!=` también comparan cadenas de caracteres caracter por caracter (sensible a mayúsculas y minúsculas):

```python
user_role = "analyst_l1"
request_method = "POST"

print(user_role == "admin")       # False
print(request_method != "GET")    # True
print("root" == "Root")           # False (Case-sensitive)
```

> [!IMPORTANT]
> **Igualdad de Valor (`==`) vs. Identidad de Memoria (`is`):**
> * El operador `==` compara si dos objetos contienen el **mismo valor**.
> * El operador `is` comprueba si dos variables apuntan al **mismo objeto físico en memoria RAM** (`id(a) == id(b)`).
> En condicionales de seguridad, use `==` para comparar datos (`ip == "10.0.0.1"`) y reserve `is` únicamente para comparaciones con el singleton nulo (`if response is None:`) o banderas booleanas (`if is_active is True:`).

## 3. Anatomía de la Sentencia `if`

La sentencia `if` es la estructura condicional fundamental e irreductible. Se compone de dos partes críticas: el **encabezado (*header*)** y el **cuerpo (*body*)**.

```python
if status == 200:
    print("OK")
```

### 3.1. El Encabezado (*Header*)
* Comienza obligatoriamente con la palabra reservada `if`, seguida de la condición a evaluar.
* **Los Dos Puntos (`:`):** Debe terminar estrictamente con dos puntos `:`. Omitir este carácter provoca un error inmediato de sintaxis (`SyntaxError: invalid syntax`).
* **Paréntesis Opcionales:** En condiciones simples, envolver la condición entre paréntesis es opcional (`if (status == 200):`). Se procesa de forma idéntica sin ellos.

### 3.2. El Cuerpo (*Body*) y la Sangría (*Indentation*)
A diferencia de lenguajes derivados de C que usan llaves `{ }`, Python delimita los bloques de código mediante **sangría (*indentation*)**:
* El estándar oficial PEP 8 establece el uso de **4 espacios en blanco** por nivel de sangría (evitando tabuladores).
* Todas las líneas dentro del cuerpo del `if` deben compartir exactamente el mismo nivel de sangría. Si la sangría es inconsistente o se omite, Python arrojará un `IndentationError`.

## 4. Ramificaciones Alternativas: `else` y `elif`

Cuando una condición resulta falsa, un script a menudo debe ejecutar caminos alternativos.

### 4.1. La Sentencia `else` (Captura por Defecto)
La cláusula `else` define un bloque de contingencia que se ejecuta **únicamente cuando todas las condiciones precedentes han resultado falsas**:

```python
status = 404

if status == 200:
    print("OK")
else:
    print("check other status") # Se ejecuta porque status != 200
```

* `else` no acepta ninguna condición directa (no se puede escribir `else status == 404:`).
* Lleva dos puntos `:` al final y requiere sangría idéntica en su cuerpo.

---

### 4.2. La Escalera `elif` (*Else-If*)
Cuando existen múltiples alternativas mutuamente excluyentes, se utiliza `elif`. Permite encadenar nuevas comprobaciones que solo se evalúan si las condiciones anteriores fallaron:

```python
status = 500

if status == 200:
    print("OK")
elif status == 400:
    print("Bad Request")
elif status == 500:
    print("Internal Server Error")
else:
    print("check other status")
```

```
FLUJO DE EVALUACIÓN SECUENCIAL EN LA ESCALERA ELIF:

  ¿status == 200? ────[ True ]────► print("OK") ─────────────────────────┐
        │ [ False ]                                                       │
        ▼                                                                 │
  ¿status == 400? ────[ True ]────► print("Bad Request") ────────────────┤
        │ [ False ]                                                       │
        ▼                                                                 │
  ¿status == 500? ────[ True ]────► print("Internal Server Error") ──────┤
        │ [ False ]                                                       │
        ▼                                                                 │
      else: ──────────────────────► print("check other status") ─────────┤
                                                                          ▼
                                                                  Fin de Evaluación
```

### 4.3. Diferencia Crítica: `if-elif-else` vs. Múltiples `if` Independientes

Este es uno de los conceptos más importantes para evitar fallos de lógica y optimizar el rendimiento en análisis de eventos masivos:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    COMPARATIVA DE ARQUITECTURA DE EVALUACIÓN                 │
├──────────────────────────────────────┬───────────────────────────────────────┤
│ ESCALERA `if-elif-else`              │ MÚLTIPLES SENTENCIAS `if` SEPARADAS   │
├──────────────────────────────────────┼───────────────────────────────────────┤
│ • Evaluación mutuamente excluyente.  │ • Evaluación exhaustiva independiente.│
│ • En cuanto una rama evalúa a `True`,│ • Python evalúa CADA sentencia `if`,  │
│   el intérprete ejecuta su cuerpo y  │   incluso si la anterior fue `True`.  │
│   **ignora todas las restantes**.    │ • Más de un bloque puede ejecutarse.  │
│ • Mayor velocidad de procesamiento.  │ • Útil si varias alertas independientes│
│ • Ideal para estados únicos (HTTP).  │   pueden dispararse al mismo tiempo.  │
└──────────────────────────────────────┴───────────────────────────────────────┘
```

#### Demostración Práctica del Comportamiento:

```python
score = 85

# CASO A: Múltiples if independientes (ERROR LÓGICO FRECUENTE)
if score >= 50:
    print("Alerta Media")  # Se imprime
if score >= 80:
    print("Alerta Alta")   # ¡También se imprime!

# CASO B: Escalera if-elif mutuamente excluyente (CORRECTO)
if score >= 80:
    print("Alerta Alta")   # Se imprime y finaliza el bloque
elif score >= 50:
    print("Alerta Media")  # Se ignora
```

## 5. Operadores Lógicos Compuestos (`and`, `or`, `not`)

Para modelar reglas complejas de detección en el SOC, las condiciones atómicas se combinan mediante **operadores lógicos booleanos**.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                       TABLAS DE VERDAD EN PYTHON                             │
├─────────┬─────────┬──────────────────┬─────────────────┬─────────────────────┤
│ Cond. A │ Cond. B │ A and B (Y)      │ A or B (O)      │ not A (Negación)    │
├─────────┼─────────┼──────────────────┼─────────────────┼─────────────────────┤
│ True    │ True    │ **True**         │ **True**        │ False               │
│ True    │ False   │ False            │ **True**        │ False               │
│ False   │ True    │ False            │ **True**        │ True                │
│ False   │ False   │ False            │ False           │ True                │
└─────────┴─────────┴──────────────────┴─────────────────┴─────────────────────┘
```

### 5.1. El Operador `and` (Conjunción)
Exige que **ambas** condiciones sean estrictamente verdaderas para que la expresión completa sea `True`.
* **Ejemplo: Rango de Códigos HTTP Exitosos (200 - 226):**
  ```python
  status = 204
  if status >= 200 and status <= 226:
      print("successful response")
  ```

---

### 5.2. El Operador `or` (Disyunción Inclusiva)
Basta con que **al menos una** de las condiciones sea verdadera para que la expresión sea `True`.
* **Ejemplo: Detección de Respuestas Informativas (100 o 102):**
  ```python
  status = 100
  if status == 100 or status == 102:
      print("informational response")
  ```

---

### 5.3. El Operador `not` (Inversión Lógica)
Invierte el valor de verdad: convierte `True` en `False` y `False` en `True`.
* **Ejemplo: Detección de Códigos fuera del Rango de Éxito:**
  ```python
  status = 503
  if not (status >= 200 and status <= 226):
      print("check status") # Se imprime porque 503 no está entre 200 y 226
  ```

---

### 5.4. Precedencia de Operadores y Leyes de De Morgan

El intérprete de Python evalúa las expresiones lógicas siguiendo un orden de precedencia estricto:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                  JERARQUÍA DE PRECEDENCIA DE OPERADORES                      │
├──────────────────────────────────────────────────────────────────────────────┤
│ 1. Paréntesis `( )`              ──► Máxima prioridad (evaluación forzada)   │
│ 2. Operadores Aritméticos        ──► `+`, `-`, `*`, `/`, `//`                │
│ 3. Operadores de Comparación     ──► `==`, `!=`, `<`, `>`, `<=`, `>=`        │
│ 4. Operador Lógico `not`         ──► Negación unaria                         │
│ 5. Operador Lógico `and`         ──► Conjunción                              │
│ 6. Operador Lógico `or`          ──► Disyunción (mínima prioridad)           │
└──────────────────────────────────────────────────────────────────────────────┘
```

> [!WARNING]
> **El Papel Crítico de los Paréntesis con `not`:**
> Escribir `if not status >= 200 and status <= 226:` evalúa por precedencia como `(not (status >= 200)) and (status <= 226)`, lo cual es matemáticamente diferente a `not (status >= 200 and status <= 226)`. Según las **Leyes de De Morgan**:
> `not (A and B)` es lógicamente equivalente a `(not A) or (not B)`.
> Es decir: `not (status >= 200 and status <= 226)` equivale a `status < 200 or status > 226`.

---

### 5.5. Evaluación de Cortocircuito (*Short-Circuit Evaluation*)

Python evalúa las expresiones lógicas de izquierda a derecha y **se detiene en cuanto el resultado final es predecible**:
* En un **`and`**: Si el primer operando es `False`, el resultado será inevitablemente `False`; Python **no evalúa el segundo operando**.
* En un **`or`**: Si el primer operando es `True`, el resultado será inevitablemente `True`; Python **no evalúa el segundo operando**.

#### Aplicación Defensiva para Evitar Errores de Ejecución:
El cortocircuito protege contra errores fatales como accesos a listas vacías o división por cero:

```python
lista_iocs = []

# Si lista_iocs está vacía, len > 0 es False y Python NUNCA evalúa lista_iocs[0],
# evitando que el programa colapse con IndexError: list index out of range.
if len(lista_iocs) > 0 and lista_iocs[0] == "malware.exe":
    print("IoC crítico detectado.")
```

## 6. Concepto Avanzado: Valores "Truthy" y "Falsy" en Python

En Python, cualquier tipo de dato puede evaluarse implícitamente en una condición booleana sin necesidad de usar operadores de comparación explícitos:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    EVALUACIÓN DE VERDAD IMPLÍCITA EN PYTHON                  │
├──────────────────────────────────────┬───────────────────────────────────────┤
│ VALORES FALSY (Evalúan a False)      │ VALORES TRUTHY (Evalúan a True)       │
├──────────────────────────────────────┼───────────────────────────────────────┤
│ • Constante `None`                   │ • Cualquier número distinto de 0      │
│ • Número entero `0` y flotante `0.0` │ • Cadenas con texto (`"admin"`)       │
│ • Cadena vacía `""`                  │ • Listas con elementos (`[1, 2]`)     │
│ • Lista vacía `[]`, tupla vacía `()` │ • Diccionarios con claves (`{"a": 1}`)|
│ • Diccionario vacío `{}`             │ • Conjuntos con datos (`{10.0.0.1}`)  │
└──────────────────────────────────────┴───────────────────────────────────────┘
```

```python
# Validación limpia y pythónica en el SOC
raw_payload = ""

if not raw_payload:
    print("[INFO] El paquete no contiene carga útil de datos.")
```

## 7. Casos Prácticos en Operaciones de Ciberseguridad (SOC)

### Caso 1: Triage Automatizado de Códigos de Respuesta HTTP en Logs de Servidor

```python
# Script de clasificación para eventos interceptados en un Reverse Proxy
http_code = 403

if http_code >= 200 and http_code < 300:
    log_category = "SUCCESSFUL_TRAFFIC"
elif http_code == 401 or http_code == 403:
    log_category = "UNAUTHORIZED_ACCESS_ATTEMPT"
elif http_code == 404:
    log_category = "RECONNAISSANCE_OR_DIR_BUSTING"
elif http_code >= 500 and http_code < 600:
    log_category = "SERVER_FAULT_OR_EXPLOIT_CRASH"
else:
    log_category = "UNKNOWN_CODE"

print(f"Código {http_code} categorizado en el SOC como: {log_category}")
```

---

### Caso 2: Motor de Control de Acceso y Verificación de Autenticación MFA

```python
# Parámetros del intento de conexión a la consola de administración
user = "jrodriguez"
role = "Security_Analyst"
mfa_verified = True
is_ip_whitelisted = False
failed_attempts = 1

# Regla: Requiere rol de analista, MFA activo y menos de 3 intentos fallidos,
# O bien pertenecer a la red interna confiable (whitelist).
if (role == "Security_Analyst" and mfa_verified and failed_attempts < 3) or is_ip_whitelisted:
    access_granted = True
    print(f"[ACCESO CONCEDIDO] Sesión iniciada para el usuario: {user}")
else:
    access_granted = False
    print(f"[ACCESO DENEGADO] Intento sospechoso bloqueado para: {user}")
```

## 8. Puntos Clave para el Analista de Ciberseguridad

* **Estructura Indentada:** Python utiliza la sangría de 4 espacios (PEP 8) para delimitar los bloques de código tras los dos puntos `:` en sentencias `if`, `elif` y `else`.
* **Evaluación Excluyente con `elif`:** La escalera `if-elif-else` se detiene tan pronto como encuentra una condición verdadera, a diferencia de múltiples sentencias `if` que evalúan todas las condiciones independientemente.
* **Operadores Lógicos Compuestos:**
  * `and`: Requiere que todas las condiciones se cumplan.
  * `or`: Exige que al menos una condición sea verdadera.
  * `not`: Invierte el valor lógico de la condición.
* **Uso Obligatorio de Paréntesis:** Al combinar `not` con operadores relacionales y `and`/`or`, los paréntesis son obligatorios para garantizar la precedencia correcta según las leyes de De Morgan.
* **Evaluación de Cortocircuito:** Python detiene la evaluación tan pronto como el resultado es seguro, lo que se aprovecha para blindar scripts contra excepciones en tiempo de ejecución.
