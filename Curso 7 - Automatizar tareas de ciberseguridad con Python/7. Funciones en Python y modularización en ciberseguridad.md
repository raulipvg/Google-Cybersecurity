# Funciones en Python y Modularización en Ciberseguridad: Principio DRY y Automatización en el SOC

En esta séptima entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se aborda el diseño, la definición y la invocación de **funciones**. En las operaciones diarias de un SOC, los analistas procesan cientos de eventos similares provenientes de múltiples orígenes (cortafuegos, autenticación, proxies y correo electrónico). Escribir la misma lógica de inspección una y otra vez genera código propenso a errores e inmantenible. Las funciones permiten implementar el principio fundamental de ingeniería **DRY (*Don't Repeat Yourself*)**, encapsulando algoritmos de detección, cálculo de hashes y normalización de alertas en componentes modulares, testeables y reutilizables.

---

## 1. El Principio DRY y el Rol de las Funciones en Ciberseguridad

Una **función** es un bloque autónomo de código estructurado que ejecuta una tarea específica y que puede ser invocado múltiples veces desde cualquier punto del programa.

### 1.1. El Problema del Código Redundante vs. Enfoque Modular
Imagine que debe inspeccionar tres registros de seguridad distintos: `auth.log`, `application.log` y `vpn.log`. Si no se utilizan funciones, el analista debe copiar y pegar 30 líneas de código de validación tres veces. Si el criterio de detección cambia, deberá corregir el código en tres lugares diferentes, multiplicando la probabilidad de introducir vulnerabilidades o falsos negativos.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                          FLUJO DE EJECUCIÓN Y PILA DE LLAMADAS (CALL STACK)               │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌──────────────────────────────────────┐     │     ┌──────────────────────────────────────┐
 │          PROGRAMA PRINCIPAL          │     │     │        DEFINICIÓN DE LA FUNCIÓN      │
 ├──────────────────────────────────────┤     │     ├──────────────────────────────────────┤
 │ 1. app_status = "potential concern"  │     │     │ def display_investigation_message(): │
 │ 2. if app_status == "...":           │     │     │     print("investigate activity")    │
 │ 3.     display_investigation_message()─────┼────►│     # Ejecuta cuerpo                 │
 │ 4. [Pausa: espera retorno]           │◄────┼─────│     # Retorna control al llamador    │
 │ 5. email_status = "okay"             │     │     └──────────────────────────────────────┘
 └──────────────────────────────────────┘     │
```

## 3. Anatomía de la Definición de una Función

Toda función en Python se compone de dos secciones obligatorias: el **encabezado (*header*)** y el **cuerpo (*body*)**.

```python
def display_investigation_message():
    """Muestra un mensaje estandarizado de triaje ante eventos anómalos."""
    print("investigate activity")
```

### 3.1. El Encabezado (*Header*)
Indica formalmente al intérprete que se está declarando una nueva rutina:
1. **Palabra reservada `def`:** Abreviatura de *define*.
2. **Nombre de la Función:** Identificador único en el espacio de nombres. Debe seguir la convención **`snake_case`** (palabras en minúsculas separadas por guiones bajos) y comenzar con un verbo descriptivo (`display_...`, `check_...`, `parse_...`).
3. **Paréntesis `()`:** Delimitan la lista de parámetros que la función acepta (pueden estar vacíos si no requiere entradas externas).
4. **Dos puntos (`:`):** Delimitador sintáctico obligatorio que finaliza el encabezado.

### 3.2. El Cuerpo (*Body*) y la Sangría (*Indentation*)
* Bloque de código con sangría de **4 espacios en blanco** (estándar PEP 8) situado inmediatamente debajo del encabezado.
* Todo lo que mantenga esa sangría forma parte de la función; en cuanto la sangría regresa al nivel superior, la definición concluye.
* **Docstrings (PEP 257):** Cadena literal entre comillas triples `""" ... """` colocada en la primera línea del cuerpo para documentar el propósito, entradas y salidas de la función.

## 4. Invocación y Llamada a Funciones (*Function Calls*)

Definir una función solo almacena las instrucciones en la memoria del intérprete; el código **no se ejecuta** hasta que la función es explícitamente **llamada (*called / invoked*)**.

```python
# 1. Declaración de la función (el intérprete la registra, pero NO la ejecuta)
def display_investigation_message():
    print("investigate activity")

# 2. Variables de estado operativo del SOC
application_status = "potential concern"
email_status = "okay"

# 3. Llamadas condicionales a la función
if application_status == "potential concern":
    print("application_log:")
    display_investigation_message() # Primera llamada

if email_status == "potential concern":
    print("email_log:")
    display_investigation_message() # No se ejecuta porque la condición es False
```

```text
Salida del programa:
application_log:
investigate activity
```

## 5. Parámetros, Argumentos y la Sentencia `return`

Para que una función sea verdaderamente potente, debe procesar datos variables mediante **parámetros** y devolver resultados mediante **`return`**.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                         PARÁMETROS vs. ARGUMENTOS: DISTINCIÓN FORMAL                      │
├──────────────────────────────────────┬────────────────────────────────────────────────────┤
│ Parámetro (Formal)                  │ Argumento (Real / Efectivo)                        │
├──────────────────────────────────────┼────────────────────────────────────────────────────┤
│ Variable definida en el encabezado   │ Valor concreto transmitido a la función durante la │
│ de la función al momento de crearla. │ llamada en tiempo de ejecución.                    │
│ Ej: `def check_status(log_name):`    │ Ej: `check_status("auth.log")`                     │
└──────────────────────────────────────┴────────────────────────────────────────────────────┘
```

### 5.1. Parámetros con Valores por Defecto
Permiten definir argumentos opcionales, útiles para umbrales de seguridad predeterminados:

```python
def evaluate_brute_force(failed_count, threshold=5):
    """Evalúa si los fallos superan el umbral (por defecto: 5)."""
    if failed_count >= threshold:
        return True
    return False

# Llamada usando el umbral por defecto (5)
print(evaluate_brute_force(6))            # True

# Llamada sobrescribiendo el umbral para servicios críticos (SSH = 3)
print(evaluate_brute_force(4, threshold=3)) # True
```

### 5.2. `print()` vs. `return`: Diferencia Fundamental en Ingeniería

Uno de los errores conceptuales más frecuentes es confundir imprimir un valor con retornarlo:

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                           TABLA COMPARATIVA: PRINT() vs. RETURN                           │
├────────────────────────────┬─────────────────────────────┬────────────────────────────────┤
│ Característica             │ Sentencia `print()`         │ Sentencia `return`             │
├────────────────────────────┼─────────────────────────────┼────────────────────────────────┤
│ **Propósito**              │ Efecto secundario: muestra  │ Devuelve un resultado a la     │
│                            │ texto legible en pantalla.  │ instrucción que llamó la rutina│
├────────────────────────────┼─────────────────────────────┼────────────────────────────────┤
│ **Reutilización del Dato** │ Nula. El valor se pierde en │ Total. El valor retornado se   │
│                            │ la consola; no se captura.  │ asigna a variables o pipelines.│
├────────────────────────────┼─────────────────────────────┼────────────────────────────────┤
│ **Finalización de Función**│ Continúa ejecutando las     │ **Finaliza inmediatamente** la │
│                            │ líneas siguientes.          │ ejecución de la función.       │
└────────────────────────────┴─────────────────────────────┴────────────────────────────────┘
```

#### Demostración Práctica:
```python
def obtener_severidad_print(cvss):
    if cvss >= 9.0:
        print("CRITICAL")

def obtener_severidad_return(cvss):
    if cvss >= 9.0:
        return "CRITICAL"
    return "LOW"

# Caso A: print() no permite reutilizar el dato
resultado_a = obtener_severidad_print(9.8) # Imprime "CRITICAL" en pantalla
print(resultado_a)                        # Imprime None (no devolvió nada)

# Caso B: return permite alimentar otras decisiones lógicas en el SIEM
severidad = obtener_severidad_return(9.8)
if severidad == "CRITICAL":
    print(f"[ACCION REQUERIDA] Enviar SMS de emergencia al guardia CISO.")
```

## 6. Ámbito de las Variables (*Scope* y Regla LEGB)

Las variables declaradas dentro del cuerpo de una función poseen un **ámbito local (*local scope*)**: nacen cuando la función se ejecuta y se destruyen en cuanto la función retorna.

```python
def analizar_paquete():
    payload_size = 1500 # Variable LOCAL
    print("Tamaño dentro de la función:", payload_size)

analizar_paquete()
# print(payload_size) # Genera NameError: name 'payload_size' is not defined
```

> [!TIP]
> **Aislamiento de Seguridad:** El ámbito local previene que funciones distintas sobrescriban accidentalmente variables con nombres comunes (como `ip`, `i`, `status`), garantizando la independencia y modularidad del software defensivo.

## 7. Recursividad y el Peligro del Bucle Infinito en la Pila (*Stack Overflow*)

Una función puede llamarse a sí misma; este mecanismo se denomina **recursividad**. Sin embargo, si una función se invoca a sí misma sin una **condición base de parada**, genera un ciclo infinito que agota la memoria de la pila:

```python
# EJEMPLO DE ERROR CRÍTICO: Bucle infinito por recursión sin condición base
def func1():
    func1()

# func1() # Al ejecutarse, satura la pila de llamadas
```

### 7.1. El Límite de Recursión en Python
A diferencia de un bucle `while True:` (que puede correr indefinidamente en memoria RAM si no consume pila), cada llamada a una función agrega un nuevo marco (*frame*) a la **Pila de Llamadas (*Call Stack*)**.

Para evitar que el intérprete bloquee todo el sistema operativo por agotamiento de memoria, Python impone un límite de seguridad estricto (comúnmente 1.000 llamadas). Al alcanzarse, el intérprete aborta inmediatamente arrojando una excepción:

```text
RecursionError: maximum recursion depth exceeded
```

> [!WARNING]
> **Regla de Oro en Funciones Recursivas:** Toda rutina recursiva (por ejemplo, para recorrer directorios anidados en busca de archivos cifrados por ransomware) debe contar con una **condición base (*base case*)** claramente definida que detenga las llamadas sucesivas.

## 8. Casos Prácticos en Operaciones de Ciberseguridad (SOC)

### Caso 1: Triage Automatizado y Enriquecimiento de Alertas de Red

```python
def clasificar_puerto(puerto):
    """Categoriza el puerto de destino en servicios conocidos o sospechosos."""
    if puerto == 22:
        return "SSH_ADMIN"
    elif puerto == 80 or puerto == 443:
        return "WEB_TRAFFIC"
    elif puerto == 3389:
        return "RDP_REMOTE_DESKTOP"
    else:
        return "UNCOMMON_HIGH_PORT"

# Simulación de eventos recibidos de un sensor Suricata
conexiones = [80, 3389, 443, 4444, 22]

for conn_port in conexiones:
    etiqueta = clasificar_puerto(conn_port)
    if etiqueta in ["RDP_REMOTE_DESKTOP", "UNCOMMON_HIGH_PORT"]:
        print(f"[ALERTA SOC] Tráfico potencialmente riesgoso detectado en puerto {conn_port} ({etiqueta})")
```

### Caso 2: Validador de Formato y Aislamiento de Direcciones IP Privadas (RFC 1918)

```python
def es_ip_privada(direccion_ip):
    """Determina si una dirección IPv4 pertenece a rangos locales RFC 1918."""
    if direccion_ip.startswith("10."):
        return True
    elif direccion_ip.startswith("172.16.") or direccion_ip.startswith("172.31."):
        return True
    elif direccion_ip.startswith("192.168."):
        return True
    return False

ips_sospechosas = ["192.168.1.50", "203.0.113.195", "10.0.4.2", "198.51.100.4"]

for ip in ips_sospechosas:
    if not es_ip_privada(ip):
        print(f"[ENRUTAMIENTO PÚBLICO] La IP {ip} proviene de Internet. Consultando Threat Intelligence.")
```

## 9. Puntos Clave para el Analista de Ciberseguridad

* **Principio DRY (*Don't Repeat Yourself*):** Empaquetar la lógica repetitiva en funciones centraliza el mantenimiento de reglas de detección y elimina errores de copia y pega.
* **Componentes Sintácticos:** El encabezado requiere `def`, nombre descriptivo en `snake_case`, paréntesis `()` y dos puntos finales `:`. El cuerpo debe estar rigurosamente indentado con 4 espacios.
* **`print()` vs. `return`:** `print()` solo muestra texto en consola; `return` entrega el dato computado de vuelta al programa para continuar procesándolo en otras etapas del script.
* **Ámbito Local Protegido:** Las variables creadas dentro de una función no contaminan el espacio de nombres global, protegiendo la integridad del script.
* **Prevención de `RecursionError`:** Llamar a una función dentro de sí misma sin una condición base de salida agota la pila de llamadas (*call stack*) y provoca el colapso del script.
