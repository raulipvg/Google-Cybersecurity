## 1. El Rol Crítico de la Automatización en Ciberseguridad

La automatización es la aplicación de software y lógica programable para ejecutar tareas sistemáticas sin intervención humana directa. En el ecosistema del SOC contemporáneo, los analistas se enfrentan a volúmenes masivos de telemetría (cientos de miles de eventos por segundo). Realizar investigaciones de accesos, actualizaciones de listas de control de acceso (ACL) o auditorías de cumplimiento de forma manual no solo resulta inviable temporalmente, sino que introduce un alto riesgo de error humano y fatiga por alertas (*alert fatigue*).

## 2. Desglose Anatómico de los 6 Componentes Esenciales de Python

Para construir pipelines de automatización robustos, el analista debe articular seis bloques fundamentales del lenguaje:

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│                            LOS 6 PILARES DE PYTHON PARA EL SOC                           │
├────────────────────┬──────────────────────────────────┬──────────────────────────────────┤
│ Componente         │ Rol en la Automatización         │ Aplicación en Ciberseguridad     │
├────────────────────┼──────────────────────────────────┼──────────────────────────────────┤
│ 1. Variables       │ Almacenamiento de estado en RAM  │ Contadores de fallos, IPs, flags │
│ 2. Condicionales   │ Lógica de decisión determinista  │ Reglas de firewall, alertas SIEM │
│ 3. Iteraciones     │ Repetición controlada de tareas  │ Barrido de logs, ping sweeps     │
│ 4. Funciones       │ Modularización y principio DRY   │ Parsers de eventos reutilizables │
│ 5. Cadenas (str)   │ Telemetría de texto inmutable    │ Extracción de URLs, dominios, IPs│
│ 6. Listas (list)   │ Colecciones dinámicas mutables   │ Listas de bloqueo, colas de IoCs │
└────────────────────┴──────────────────────────────────┴──────────────────────────────────┘
```

### 2.1. Variables: Preservación de Estado Dinámico
Las variables actúan como contenedores en la memoria del sistema que etiquetan y preservan datos dinámicos durante la ejecución de un script.
* **Sin variables:** El analista tendría que fijar valores literales de forma estática en cada instrucción, impidiendo que el código se adapte a distintas fuentes de telemetría.
* **En el SOC:** Se utilizan para acumular conteos de intentos fallidos de autenticación, registrar marcas de tiempo (*timestamps*), almacenar tokens de sesión de APIs y mantener banderas booleanas de compromiso (`is_compromised = True`).

---

### 2.2. Sentencias Condicionales: Lógica de Decisión Determinista
Las estructuras condicionales (`if`, `elif`, `else`) evalúan expresiones lógicas y ejecutan bloques de código únicamente cuando las condiciones se satisfacen (`True`).
* **Eficiencia Operativa:** Permiten filtrar millones de eventos irrelevantes y aislar exclusivamente aquellos que coinciden con criterios de riesgo o firmas de ataque.
* **En el SOC:** Evaluar si un código de respuesta HTTP corresponde a un error del servidor (`status_code >= 500`), comprobar si una dirección IP pertenece a un segmento interno o evaluar si el total de inicios de sesión fallidos supera un umbral de fuerza bruta.

---

### 2.3. Sentencias Iterativas: Ejecución Repetitiva Escalable
Los bucles automatizan la repetición de instrucciones sin requerir la duplicación de código.
* **Bucles `for` (Secuencias Finitas):** Ideales para iterar a través de colecciones de tamaño conocido o determinado, como una lista de nombres de usuario extraída de un archivo de auditoría, una colección de puertos de red o las líneas de un registro.
* **Bucles `while` (Basados en Condición):** Ideales para tareas que deben continuar ejecutándose mientras una condición siga siendo verdadera. Por ejemplo, un daemon de monitoreo que consulta la API de un cortafuegos cada 60 segundos hasta recibir una señal de apagado, o un bucle de reintento de conexión con límite de intentos (*retry loop*).

---

### 2.4. Funciones: Modularidad, Principio DRY y Encapsulación
Una función es un bloque de código autónomo y parametrizado diseñado para resolver una subtarea específica.
* **Principio DRY (*Don't Repeat Yourself*):** Evita la redundancia de código. Si una rutina de parsing de logs se necesita en cinco puntos distintos de un script, se define una vez y se invoca según sea necesario.
* **Aislamiento de Memoria:** Los parámetros y variables creados dentro de la función pertenecen a su marco de pila local (*local stack frame*), evitando la contaminación colateral de variables globales.
* **Funciones Integradas (*Built-ins*):** Utilidades nativas altamente optimizadas en C (`len()`, `sorted()`, `max()`, `min()`, `type()`, `print()`) que resuelven operaciones comunes sin costo de desarrollo.

---

### 2.5. Técnicas para Cadenas de Texto (`str`)
Los registros de seguridad y la telemetría se presentan fundamentalmente como cadenas de texto.
* **Inmutabilidad:** Garantiza la integridad forense; una cadena de log no puede ser alterada accidentalmente *in-situ*.
* **Operaciones Clave:**
  * Indexación y Rebanado (`log_entry[0:15]` para aislar la fecha y hora).
  * Búsqueda y Localización (`.index()`, `.find()`).
  * Normalización (`.lower()`, `.upper()` para neutralizar técnicas de evasión de mayúsculas/minúsculas).
  * Limpieza y Tokenización (`.strip()` para eliminar retornos de carro, `.split()` para segmentar columnas).

---

### 2.6. Técnicas para Listas (`list`)
A diferencia de las cadenas, las listas son estructuras de datos dinámicas y mutables.
* **Gestión de Colecciones en Memoria:** Permiten mantener inventarios de endpoints comprometidos, listas negras de IPs y colas de alertas pendientes de triaje.
* **Métodos Estructurales:**
  * `.append()`: Inserción al final en $O(1)$ amortizado para poblar listas dinámicamente desde flujos de eventos.
  * `.insert()`: Inserción en posición arbitraria ($O(N)$).
  * `.remove()`: Retiro de elementos específicos (ej. liberar una IP de la cuarentena) ($O(N)$).
  * `.index()`: Localización de la primera aparición de un valor ($O(N)$).

## 3. Caso de Estudio Práctico: Investigación Forense de un Usuario Marcado

### 3.1. Planteamiento del Incidente
Un analista del SOC recibe una alerta del sistema SIEM: la cuenta del usuario `jdoe` ha sido marcada (*flagged*) debido a una anomalía detectada por el motor de análisis de comportamiento de usuarios y entidades (UEBA). La tarea asignada consiste en auditar el registro completo de inicios de sesión del día y **contabilizar con exactitud cuántas veces este usuario específico intentó autenticarse**.

```
Entrada:
  Lista de auditoría diaria = ["elarson", "jdoe", "bmoreno", "jdoe", "tshah", "jdoe", "sgilmore"]
  Usuario marcado = "jdoe"

Proceso Automatizado:
  1. Inicializar contador a 0
  2. Para cada usuario en la lista:
       ¿Usuario == "jdoe"?
         SÍ ──► Incrementar contador en 1
         NO ──► Continuar iteración
  3. Retornar total acumulado
```

### 3.2. Implementación Paso a Paso en Python
A continuación se muestra la integración secuencial de los conceptos estudiados:

```python
# 1. Variables: Definición de la lista de eventos y el objetivo de investigación
daily_logins = ["elarson", "jdoe", "bmoreno", "jdoe", "tshah", "jdoe", "sgilmore", "jdoe"]
flagged_user = "jdoe"

# 2. Variable Acumuladora (Contador)
login_counter = 0

# 3. Sentencia Iterativa: Bucle for para recorrer toda la secuencia
for user in daily_logins:
    # 4. Sentencia Condicional: Comparación booleana de identidad
    if user == flagged_user:
        # Incremento de la variable acumuladora
        login_counter += 1

print(f"Investigación completada. El usuario '{flagged_user}' registró {login_counter} inicios de sesión.")
```

---

### 3.3. Modularización Profesional Mediante una Función Reutilizable
Para que este procedimiento pueda integrarse en un flujo de trabajo mayor o ser ejecutado sobre múltiples usuarios sospechosos, se encapsula la lógica en una función con anotaciones de tipo (*type hints*) y documentación estructurada:

```python
from typing import List, Tuple

def audit_flagged_user(flagged_username: str, login_events: List[str], alert_threshold: int = 3) -> Tuple[int, bool]:
    """
    Audita los eventos de inicio de sesión de un usuario marcado y evalúa si supera un umbral de riesgo.

    Parámetros:
        flagged_username (str): Identificador del usuario investigado.
        login_events (List[str]): Lista secuencial de intentos de autenticación registrados.
        alert_threshold (int): Límite de intentos permitidos antes de activar una alerta crítica.

    Retorna:
        Tuple[int, bool]: (Total de inicios de sesión detectados, Bandera de superación de umbral).
    """
    # Variable de estado local (aislada en el stack frame de la función)
    counter = 0

    # Iteración exhaustiva
    for current_user in login_events:
        if current_user.lower() == flagged_username.lower():
            counter += 1

    # Evaluación de riesgo
    requires_containment = counter >= alert_threshold

    return counter, requires_containment


# Simulación de eventos del SOC
audit_log = [
    "admin", "bmoreno", "jdoe", "cvelasquez", "jdoe",
    "tshah", "jdoe", "elarson", "jdoe", "wjaffrey"
]

target = "jdoe"
total_logins, trigger_alarm = audit_flagged_user(target, audit_log, alert_threshold=4)

print(f"[AUDITORÍA] Usuario analizado: {target}")
print(f"[AUDITORÍA] Intentos detectados: {total_logins}")
if trigger_alarm:
    print(f"[ALERTA CRÍTICA] El usuario '{target}' ha alcanzado el umbral de contención. Proceder al bloqueo de cuenta.")
else:
    print(f"[INFO] Actividad dentro de parámetros tolerados.")
```

## 4. Fundamentos del Manejo de Archivos en Python

Hasta este punto, los datos se han manejado en memoria mediante variables y listas estáticas predefinidas. Sin embargo, en el mundo real, la telemetría de ciberseguridad se almacena y transporta persistentemente en **archivos de registro (*log files*)**.

### 4.1. ¿Qué es un Archivo de Registro (*Log File*)?
Un **registro (*log*)** es un archivo cronológico generado automáticamente por sistemas operativos, aplicaciones, cortafuegos y dispositivos de red que documenta las actividades, eventos, errores y accesos ocurridos en el sistema.
* **Naturaleza *Append-Only*:** Por principios de integridad y auditoría, los sistemas de seguridad añaden nuevas líneas al final del archivo conforme transcurre el tiempo, sin sobrescribir las entradas históricas.
* **Propiedades Forenses:** Constituyen la principal fuente de evidencia durante un análisis forense digital y la respuesta a incidentes (DFIR).

---

### 4.2. Formatos de Archivo Predominantes: `.txt` vs `.csv`

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│                             COMPARATIVA TÉCNICA DE FORMATOS                              │
├────────────────────────────┬─────────────────────────────┬───────────────────────────────┤
│ Propiedad                  │ Archivos de Texto (.txt)    │ Valores Separados por Comas   │
│                            │                             │ (.csv)                        │
├────────────────────────────┼─────────────────────────────┼───────────────────────────────┤
│ Naturaleza                 │ Texto plano no estructurado │ Texto plano semi-estructurado │
│ Delimitación               │ Libre (espacios, tabs, libre)│ Comas (`,`), puntos y comas(;)│
│ Estructura interna         │ Líneas de formato arbitrario │ Formato tabular (Filas/Cols) │
│ Encabezados                │ Usualmente ausentes         │ Usualmente en la primera fila │

```

## 5. El Paradigma de Acceso a Archivos en Python

Python interactúa con el sistema de archivos del sistema operativo mediante la función integrada `open()` y descriptores de archivo (*file handles*).

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                          CICLO DE VIDA DE UN ARCHIVO EN PYTHON                            │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌──────────────────────┐         ┌───────────▼───────────┐         ┌──────────────────────┐
 │    1. APERTURA       │────────►│ 2. LECTURA/ESCRITURA  │────────►│      3. CIERRE       │
 │ open(path, mode)     │         │ .read() / .readline() │         │ .close() o automático│
 │ Asigna File Handle   │         │ Procesa en memoria    │         │ Libera descriptor SO │
 └──────────────────────┘         └───────────────────────┘         └──────────────────────┘
```

### 5.1. El Administrador de Contexto (`with open`)
En scripts de ciberseguridad, **siempre** se debe utilizar la cláusula `with`:

```python
with open("auth.log", "r", encoding="utf-8") as file:
    content = file.read()
# El archivo se cierra automáticamente al salir de este bloque, incluso si ocurre un error fatal.
```

> [!IMPORTANT]
> **Gestión Segura de Recursos y Fuga de Descriptores (*Resource Leak*):**
> Si un analista abre un archivo mediante `file = open(...)` y el script arroja una excepción no controlada antes de llamar a `file.close()`, el descriptor de archivo permanece bloqueado por el sistema operativo. En procesos que analizan miles de logs de forma continua, esto produce un agotamiento de descriptores de archivo (*file descriptor exhaustion*), provocando la caída del sistema. La instrucción `with open(...)` garantiza la liberación determinista del recurso.

---

### 5.2. Modos de Apertura Fundamentales
* **`'r'` (Read / Lectura):** Modo por defecto. Abre el archivo exclusivamente para lectura. Si el archivo no existe, arroja `FileNotFoundError`.
* **`'w'` (Write / Escritura):** Abre el archivo para escritura. **Sobrescribe y trunca a cero** el archivo si ya existía; si no existe, lo crea.
* **`'a'` (Append / Anexado):** Abre el archivo para escribir al final del mismo, preservando todo el contenido existente. Modo idóneo para generar registros de auditoría forense.

---

### 5.3. Estrategias de Lectura: Memoria vs Escalabilidad
1. **`.read()`:** Lee todo el archivo en una única cadena `str`. Adecuado solo para archivos pequeños (menores a decenas de megabytes).
2. **`.readlines()`:** Lee todas las líneas y las almacena en una lista de cadenas `List[str]`.
3. **Iteración Directa sobre el Objeto Archivo (*Streaming*):**
   ```python
   # Método óptimo para logs masivos de varios gigabytes: consume una sola línea en RAM a la vez
   with open("massive_security_event.log", "r", encoding="utf-8") as log_file:
       for line in log_file:
           process_line(line)
   ```

## 6. Laboratorio Integrador: Parser de Auditoría Multi-Formato en Python

El siguiente script unifica todos los componentes estudiados (variables, condicionales, bucles, funciones, manipulación de cadenas, listas y lectura básica de archivos) para procesar un registro de auditoría y generar un reporte de incidentes:

```python
import os
from typing import Dict, List

# Simulación de creación de un archivo de log de seguridad en formato .txt
LOG_FILENAME = "daily_security_events.txt"
SAMPLE_DATA = """2026-09-21 10:01:15 USER:bmoreno STATUS:success
2026-09-21 10:05:22 USER:tshah STATUS:failed
2026-09-21 10:05:28 USER:tshah STATUS:failed
2026-09-21 10:05:35 USER:tshah STATUS:failed
2026-09-21 10:05:42 USER:tshah STATUS:failed
2026-09-21 10:12:01 USER:elarson STATUS:success
2026-09-21 10:25:40 USER:sgilmore STATUS:success
"""

with open(LOG_FILENAME, "w", encoding="utf-8") as f:
    f.write(SAMPLE_DATA)


def analyze_log_file(filepath: str, threshold: int = 3) -> Dict[str, any]:
    """
    Lee un archivo de registro .txt, contabiliza fallos por usuario mediante
    cadenas y listas, y reporta cuentas comprometidas.
    """
    if not os.path.exists(filepath):
        raise FileNotFoundError(f"El archivo {filepath} no existe en el sistema.")

    total_lines = 0
    failed_attempts_by_user: Dict[str, int] = {}
    quarantined_users: List[str] = []

    # Uso de administrador de contexto y lectura segura línea a línea
    with open(filepath, "r", encoding="utf-8") as log_stream:
        for raw_line in log_stream:
            clean_line = raw_line.strip()
            if not clean_line:
                continue

            total_lines += 1
            tokens = clean_line.split()  # Segmentación por espacios: [fecha, hora, USER:..., STATUS:...]
            
            username = ""
            status = ""

            # Extracción basada en prefijos de cadena
            for token in tokens:
                if token.startswith("USER:"):
                    username = token.replace("USER:", "")
                elif token.startswith("STATUS:"):
                    status = token.replace("STATUS:", "")

            # Lógica condicional de acumulación de fallos
            if status == "failed" and username:
                failed_attempts_by_user[username] = failed_attempts_by_user.get(username, 0) + 1
                
                # Evaluación de umbral de riesgo
                if failed_attempts_by_user[username] >= threshold:
                    if username not in quarantined_users:
                        quarantined_users.append(username)

    return {
        "events_processed": total_lines,
        "failed_counts": failed_attempts_by_user,
        "quarantined_accounts": quarantined_users
    }


# Ejecución del motor forense
audit_report = analyze_log_file(LOG_FILENAME, threshold=3)

print("=" * 60)
print("          INFORME DE ANÁLISIS FORENSE DE REGISTROS          ")
print("=" * 60)
print(f"Total de registros procesados : {audit_report['events_processed']}")
print(f"Métricas de intentos fallidos : {audit_report['failed_counts']}")
print(f"Cuentas bloqueadas/cuarentena : {audit_report['quarantined_accounts']}")
print("=" * 60)

# Limpieza del entorno de pruebas
if os.path.exists(LOG_FILENAME):
    os.remove(LOG_FILENAME)
```

## 7. Resumen y Puntos Clave

1. **Propósito de la Automatización:** Reducir el tiempo medio de respuesta (MTTR), eliminar la variabilidad del error humano y escalar la capacidad de análisis del SOC frente a volúmenes masivos de datos.
2. **Sinergia de Componentes:** Las **variables** gestionan el estado, los **condicionales** toman decisiones basadas en reglas, los **bucles** escalan la repetición, las **funciones** modularizan y aíslan responsabilidades, mientras que las **cadenas** y **listas** modelan la telemetría.
3. **Manejo de Archivos:** La mayoría de los datos forenses residen en archivos persistentes de registro (*logs*).
4. **Formatos Predominantes:**
   * Archivos `.txt`: Texto plano no estructurado (logs del sistema operativo y servidores web).
   * Archivos `.csv`: Texto plano tabular estructurado por comas (exportaciones de bases de datos y consolas SIEM).
5. **Buenas Prácticas con Archivos:** Utilizar siempre el administrador de contexto `with open(...)` para garantizar el cierre del descriptor y procesar flujos línea por línea para evitar sobrecargas de memoria RAM.
