# Análisis Sintáctico y Estructuración de Datos de Archivos en Python (Métodos `.split()` y `.join()`)

En esta decimoctava entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se aborda el procesamiento bidireccional de datos entre el sistema de archivos y las estructuras de datos en memoria: el **análisis sintáctico (*parsing*)** y la **serialización**. En las operaciones de seguridad, la telemetría cruda almacenada en archivos de texto carece de utilidad operativa si el analista no puede segmentarla, limpiarla, filtrarla y reconstruirla. Se profundiza en el funcionamiento técnico de los métodos **`.split()`** y **`.join()`**, su asimetría sintáctica, el manejo de espacios en blanco y delimitadores arbitrarios, y la arquitectura de un ciclo completo de actualización de listas de control de acceso (ACL) en el SOC (*Read $\rightarrow$ Split $\rightarrow$ Filter $\rightarrow$ Join $\rightarrow$ Write*).

## 1. El Concepto de Análisis Sintáctico (*Parsing*) en Seguridad

El **análisis sintáctico (*parsing*)** es el proceso computacional de transformar datos en bruto (generalmente cadenas de texto no estructuradas o semi-estructuradas) en una estructura de datos organizada (como listas o diccionarios) que un programa pueda interpretar, validar y manipular eficientemente.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                        CICLO BIDIRECCIONAL DE PARSING Y SERIALIZACIÓN                     │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
      ARCHIVO EN DISCO                        │               MEMORIA DE PYTHON
   ┌─────────────────────┐                    │             ┌─────────────────────┐
   │ "user1,user2,user3" │ ─── .read() ───────┼───────────► │ "user1,user2,user3" │ (str)
   └─────────────────────┘                    │             └──────────┬──────────┘
                                              │                        │
                                              │                 .split(",")  [PARSING]
                                              │                        ▼
   ┌─────────────────────┐                    │             ┌─────────────────────┐
   │ "user1,user3"       │ ◄── .write() ──────┼──────────── │ ['user1', 'user3']  │ (list)
   └─────────────────────┘                    │             └──────────▲──────────┘
      ARCHIVO ACTUALIZADO                     │                        │
                                              │                 .join(",")   [SERIALIZACIÓN]
                                              │                        │
                                              │             ┌──────────┴──────────┐
                                              │             │ "user1,user3"       │ (str)
                                              │             └─────────────────────┘
```

### Necesidad Operativa en Ciberseguridad:
1. **Legibilidad Humana y Máquina:** Los logs procedentes de firewalls, servidores web o SIEMs llegan en cadenas monolíticas. El parsing permite a los analistas aislar campos clave (direcciones IP, nombres de usuario, códigos de estado) para su inspección.
2. **Capacidad de Cómputo:** Las cadenas en Python son inmutables; no es posible eliminar o insertar elementos directamente en una cadena de log sin recrearla. Al convertir la cadena en una **lista** (`list`), se obtienen las ventajas de la mutabilidad (aplicar `.remove()`, `.append()`, o filtrado por comprensión).
3. **Persistencia de Reglas:** Una vez modificada la lista en memoria, el método `.write()` exige recibir un objeto `str`, requiriendo el proceso inverso: transformar la lista depurada nuevamente en texto.

## 2. El Método `.split()`: Descomposición de Cadenas en Listas

El método `.split()` evalúa una cadena de texto y la divide en subcadenas basadas en un delimitador, devolviendo una **nueva lista de cadenas**.

```python
cadena.split(sep=None, maxsplit=-1)
```
* **`sep`** *(delimitador)*: Carácter o subcadena utilizada para determinar dónde realizar las divisiones.
* **`maxsplit`** *(opcional)*: Número máximo de divisiones a ejecutar (por defecto `-1`, lo que significa divisiones ilimitadas).

---

### 2.1. Segmentación con Delimitador Explícito
Cuando se conoce el delimitador exacto de los datos (por ejemplo, una coma `,` en registros CSV o dos puntos `:` en el archivo `/etc/passwd`), se pasa dicho carácter como argumento:

```python
approved_users = "elarson,bmoreno,tshah,sgilmore,eraab"
print("Antes de .split():", approved_users)
print("Tipo:", type(approved_users)) # <class 'str'>

# Conversión a lista utilizando la coma como separador
approved_users_list = approved_users.split(",")

print("\nDespués de .split(','):", approved_users_list)
print("Tipo:", type(approved_users_list)) # <class 'list'>
# Salida: ['elarson', 'bmoreno', 'tshah', 'sgilmore', 'eraab']
```

---

### 2.2. Segmentación por Defecto (Espacios en Blanco)
Si se invoca `.split()` **sin ningún argumento**, Python activa un comportamiento inteligente de división por espacios en blanco:

```python
removed_users = "wjaffrey   jsoto\tabernard\njhill   awilliam"
print("Cadena cruda:", repr(removed_users))

# División sin argumentos
parsed_removed = removed_users.split()
print("Lista parseada:", parsed_removed)
# Salida: ['wjaffrey', 'jsoto', 'abernard', 'jhill', 'awilliam']
```

> [!NOTE]
> **Comportamiento del Delimitador por Defecto (`sep=None`):**
> A diferencia de `.split(" ")` (que busca exactamente un espacio individual y genera elementos vacíos ante dobles espacios), `.split()` sin argumentos agrupa secuencias continuas de cualquier carácter de espacio en blanco:
> * Espacios estándar (`' '`)
> * Tabulaciones (`\t`)
> * Saltos de línea (`\n`)
> * Retornos de carro (`\r`)
> * Saltos de página (`\f`)
> Además, descarta automáticamente cualquier espacio en blanco al inicio o al final de la cadena, eliminando la necesidad de llamar a `.strip()`.

---

### 2.3. Aplicación de `.split()` a Flujos de Archivos
En los flujos de trabajo del SOC, la lectura del archivo y la transformación con `.split()` deben ejecutarse con un diseño desacoplado:

```python
# 1. Apertura, lectura y cierre automático del archivo
with open("update_log.txt", "r", encoding="utf-8") as file:
    updates_data = file.read()

# 2. Parsing fuera del bloque with (el descriptor del archivo ya fue liberado)
updates_list = updates_data.split()

print(f"Total de tokens leídos: {len(updates_list)}")
print("Primeros 3 elementos:", updates_list[:3])
```

> [!TIP]
> **Buenas Prácticas de Rendimiento (Ámbito del Context Manager):**
> La operación `updates = updates.split()` se coloca **fuera** de la indentación de la sentencia `with`. Esto garantiza que el archivo en disco se cierre inmediatamente tras finalizar la lectura (`.read()`), liberando el *File Descriptor* en el kernel antes de consumir ciclos de CPU en el análisis sintáctico en memoria.

## 3. El Método `.join()`: Serialización de Listas en Cadenas

El método `.join()` realiza la operación matemáticamente inversa a `.split()`: toma los elementos de un iterable (típicamente una lista) y los concatena en una única cadena, intercalando un delimitador fijo entre cada elemento.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                             ASIMETRÍA SINTÁCTICA DE .join()                               │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
              "delimitador" . join ( lista_de_cadenas )
                   │                      │
                   ▼                      ▼
         Objeto Invocador (str)     Argumento Entrada (Iterable)
```

### 3.1. Asimetría Sintáctica: ¿Por qué `"delimitador".join(lista)`?
En la mayoría de los métodos de listas (como `.append()` o `.index()`), el método se invoca directamente sobre la lista: `lista.append(x)`. Sin embargo, `.join()` es un **método de la clase `str`**, no de la clase `list`.
* **Motivo de Diseño:** En Python, cualquier iterable que contenga cadenas (listas, tuplas, conjuntos) puede ser unido. Al definir el método sobre el delimitador de tipo cadena, Python desacopla la operación del tipo de contenedor específico.

```python
approved_users = ["elarson", "bmoreno", "tshah", "sgilmore", "eraab"]
print("Lista original:", approved_users)

# 1. Unión mediante coma (formato CSV en línea)
csv_string = ",".join(approved_users)
print("\nFormato CSV:',':", csv_string)
# 'elarson,bmoreno,tshah,sgilmore,eraab'

# 2. Unión mediante salto de línea (un registro por línea)
multiline_string = "\n".join(approved_users)
print("\nFormato Multilínea '\\n':\n" + multiline_string)

# 3. Unión mediante espacio (formato de tokens planos)
space_string = " ".join(approved_users)
print("\nFormato Espacio ' ':", space_string)
```

> [!WARNING]
> **Excepción `TypeError` por Tipos no String en `.join()`:**
> Todos los elementos de la lista deben ser obligatoriamente de tipo cadena (`str`). Si la lista contiene enteros (como puertos de red o códigos de error numéricos), `.join()` fallará con un error crítico:
> ```python
> ports = [80, 443, 8080]
> # ",".join(ports) -> TypeError: sequence item 0: expected str instance, int found
> # Solución con comprensión de listas:
> safe_ports = ",".join([str(p) for p in ports]) # '80,443,8080'
> ```

## 4. El Ciclo Completo de Ingeniería: Read $\rightarrow$ Split $\rightarrow$ Filter $\rightarrow$ Join $\rightarrow$ Write

Cuando un analista necesita modificar un archivo de configuración o una lista de control en disco, no existe un método que "borre una línea directamente en disco". El procedimiento estándar de la industria consiste en un pipeline de 5 fases:

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   1. READ    │ ──► │   2. SPLIT   │ ──► │  3. FILTER   │ ──► │   4. JOIN    │ ──► │   5. WRITE   │
│ with open('r'│     │ updates.split│     │ .remove()    │     │ " ".join()   │     │ with open('w'│
│ .read()      │     │ Cadena->Lista│     │ Depuración   │     │ Lista->Cadena│     │ .write()     │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

### Demostración Paso a Paso:
```python
# Fase 1: Lectura de update_log.txt
with open("update_log.txt", "r", encoding="utf-8") as file:
    updates = file.read()

# Fase 2: Parsing de la cadena a lista
updates = updates.split()

# Fase 3: Filtrado y depuración (Eliminar componentes no deseados)
target_entry = "Patch_KB4015"
if target_entry in updates:
    updates.remove(target_entry)

# Fase 4: Serialización de la lista nuevamente a cadena de texto
updates = " ".join(updates)

# Fase 5: Sobreescritura persistente en el archivo
with open("update_log.txt", "w", encoding="utf-8") as file:
    file.write(updates)
```

## 5. Comparativa Técnica entre `.split()` y `.join()`

| Parámetro | Método `.split()` | Método `.join()` |
| :--- | :--- | :--- |
| **Clase a la que pertenece** | `str` | `str` |
| **Entrada (Invocador)** | Cadena de texto (`str`) | Delimitador (`str`) |
| **Argumento principal** | Delimitador opcional (`sep`) | Iterable de cadenas (`list`, `tuple`) |
| **Tipo de dato retornado** | Lista de cadenas (`list[str]`) | Cadena de texto (`str`) |
| **Objetivo en el SOC** | Ingestión y estructuración de logs | Generación y persistencia de reportes |
| **Comportamiento ante espacios** | Agrupa múltiples espacios si no hay argumento | Inserta el delimitador exacto entre elementos |
| **Manejo de elementos nulos** | Puede generar `""` si hay delimitadores contiguos | Inserta delimitador entre cadenas vacías |

## 6. Laboratorio Práctico: Módulo de Revocación de Accesos en el SOC

El siguiente script implementa un caso de uso real de un Centro de Ciberseguridad: un sistema automatizado para depurar la lista de acceso de empleados (`allow_list.txt`), revocando permisos a cuentas marcadas como comprometidas (`compromised_users.txt`) y reconstruyendo la lista de control de forma persistente:

```python
import os
from typing import List

# Rutas de los artefactos
ALLOW_LIST_FILE = "allow_list.txt"
REVOKED_USERS_FILE = "compromised_users.txt"

# 1. Preparación de datos simulados
initial_allow_list = "elarson\nbmoreno\ntshah\nsgilmore\neraab\nwjaffrey\njsoto\n"
revoked_candidates = "tshah\njsoto\nunknown_user\n"

with open(ALLOW_LIST_FILE, "w", encoding="utf-8") as f:
    f.write(initial_allow_list)

with open(REVOKED_USERS_FILE, "w", encoding="utf-8") as f:
    f.write(revoked_candidates)


def update_access_control(allowlist_path: str, revokelist_path: str) -> List[str]:
    """
    Lee la lista de permitidos, parsea los datos con .split(), elimina
    los usuarios comprometidos y reescribe el archivo con .join().
    """
    # FASE 1: Lectura de archivos
    with open(allowlist_path, "r", encoding="utf-8") as file:
        current_content = file.read()

    with open(revokelist_path, "r", encoding="utf-8") as file:
        revoked_content = file.read()

    # FASE 2: Parsing mediante .split() (usando saltos de línea y espacios)
    current_users: List[str] = current_content.split()
    revoked_users: List[str] = revoked_content.split()

    print(f"[*] Usuarios activos iniciales ({len(current_users)}): {current_users}")
    print(f"[*] Cuentas marcadas para revocación ({len(revoked_users)}): {revoked_users}")

    # FASE 3: Filtrado forense
    removed_records: List[str] = []
    for user in revoked_users:
        if user in current_users:
            current_users.remove(user)
            removed_records.append(user)
        else:
            print(f"[i] Aviso: La cuenta '{user}' no estaba presente en la lista activa.")

    # FASE 4: Serialización mediante .join() con saltos de línea
    # Aseguramos que termine con salto de línea estándar POSIX
    updated_content = "\n".join(current_users) + "\n"

    # FASE 5: Sobreescritura atómica del archivo de control
    with open(allowlist_path, "w", encoding="utf-8") as file:
        file.write(updated_content)

    return removed_records


# Ejecución de la rutina de mitigación
expelled_accounts = update_access_control(ALLOW_LIST_FILE, REVOKED_USERS_FILE)

print("\n" + "=" * 60)
print("             REPORTE DE MITIGACIÓN DE ACCESOS               ")
print("=" * 60)
print(f"[+] Total de cuentas revocadas exitosamente: {len(expelled_accounts)}")
print(f"[+] Cuentas eliminadas del archivo: {expelled_accounts}")

# Verificación de la integridad del archivo modificado
with open(ALLOW_LIST_FILE, "r", encoding="utf-8") as f:
    final_verification = f.read()

print("\n[*] Contenido final de allow_list.txt:")
print(final_verification.strip())
print("=" * 60)

# Limpieza del laboratorio
for path in [ALLOW_LIST_FILE, REVOKED_USERS_FILE]:
    if os.path.exists(path):
        os.remove(path)
```

## 7. Resumen y Puntos Clave

1. **Definición de Parsing:** Descomposición y reestructuración de telemetría de texto no estructurada en tipos de datos manipulables por el código (`list`).
2. **Método `.split()`:** Convierte una cadena (`str`) en una lista (`list`).
   * Sin argumentos (`.split()`): Delimita por cualquier agrupación contigua de espacios en blanco (`' '`, `\t`, `\n`), eliminando espacios vacíos en los extremos.
   * Con argumento (`.split(",")`): Segmenta estrictamente por el delimitador exacto proporcionado.
3. **Método `.join()`:** Concatena un iterable de cadenas en un único `str`, intercalando el delimitador invocador (`"delimitador".join(lista)`).
4. **Ciclo de Modificación de Archivos:**
   1. Leer con `open("r")` y `.read()`.
   2. Parsear a lista con `.split()`.
   3. Manipular o depurar la lista con métodos de listas o bucles.
   4. Serializar nuevamente a texto con `.join()`.
   5. Sobrescribir en disco con `open("w")` y `.write()`.
5. **Aislamiento de I/O:** Es una buena práctica ejecutar `.split()` y `.join()` fuera de los bloques `with`, manteniendo los archivos abiertos únicamente durante las operaciones de lectura o escritura física en disco.
