# Importación, Lectura y Escritura de Archivos en Python para Operaciones de Ciberseguridad

En esta decimoséptima entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se profundiza en las operaciones fundamentales de Entrada/Salida (I/O) sobre el sistema de archivos: **apertura segura**, **lectura estructural** y **escritura persistente**. En las operaciones diarias de un Centro de Operaciones de Seguridad (SOC) y en los flujos de Respuesta a Incidentes (IR), la evidencia digital, las configuraciones de red y las listas de control residen en archivos físicos. Dominar el uso del administrador de contexto `with open(...) as file:`, diferenciar rutas relativas y absolutas, controlar los modos de acceso (`'r'`, `'w'`, `'a'`) y comprender los métodos `.read()` y `.write()` es indispensable para manipular archivos de registro como `update_log.txt` y `access_log.txt` sin poner en riesgo la integridad de los datos.

---

## 1. El Rol de los Archivos en las Operaciones de Ciberseguridad

En un entorno corporativo, la memoria RAM es volátil; cualquier análisis forense que requiera persistencia o auditoría a largo plazo depende de archivos almacenados en disco.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                       FLUJO DE I/O DE ARCHIVOS EN EL PIPELINE DEL SOC                     │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌──────────────────────────────────────┐     │     ┌──────────────────────────────────────┐
 │     FUENTES DE TELEMETRÍA (ENTRADA)  │     │     │      ARTEFACTOS DE SALIDA (DESTINO)  │
 │ - update_log.txt (Parches aplicados) │     │     │ - allowlist.txt (IPs/Usuarios OK)    │
 │ - access_log.txt (Inicios de sesión) │     │     │ - quarantined_hosts.txt (Bloqueos)   │
 │ - error_log.txt (Fallas en apps)     │     │     │ - incident_report.txt (Evidencia)    │
 └──────────────────┬───────────────────┘     │     └──────────────────▲───────────────────┘
                    │                         │                        │
                    ▼                         │                        │
        ┌───────────────────────┐             │            ┌───────────┴───────────┐
        │ LECTURA: with open()  │             │            │ ESCRITURA: with open()│
        │ Modo 'r'              ├─────────────┼───────────►│ Modo 'w' / 'a'        │
        │ file.read()           │             │            │ file.write()          │
        └───────────────────────┘             │            └───────────────────────┘
                                              │
```

### Casos de Uso Críticos en Seguridad:
1. **Auditoría de Inicios de Sesión (`access_log.txt`):** Detección de patrones anómalos de autenticación (fuerza bruta, horarios no laborales, IPs externas no autorizadas).
2. **Monitoreo de Aplicaciones y Actualizaciones (`update_log.txt`):** Verificación de despliegues de parches de seguridad y detección de software en versiones obsoletas o vulnerables.
3. **Gestión Dinámica de Controles de Acceso:** Generación y actualización automatizada de listas de permitidos (*allowlists*) y listas de bloqueo (*denylists/blocklists*).

## 2. Anatomía de la Sentencia `with open(...) as file:`

La sintaxis estándar para interactuar con archivos en Python moderno combina la función `open()` con la estructura de control `with`:

```python
with open("update_log.txt", "r", encoding="utf-8") as file:
    # Bloque de operaciones de I/O indentado
    content = file.read()
```

```
┌───────────┐     ┌────────────────────────────────────────────────┐     ┌────────┐     ┌───────────┐
│ with      │ ──► │ open("update_log.txt", "r", encoding="utf-8")  │ ──► │ as     │ ──► │ file:     │
└───────────┘     └────────────────────────────────────────────────┘     └────────┘     └───────────┘
 Context Manager       Función Built-in (Ruta, Modo, Encoding)            Alias Bind     File Handle
```

### 2.1. La Palabra Clave `with` (Protocolo de Administrador de Contexto)
La instrucción `with` encapsula la ejecución del bloque de código dentro de los métodos del protocolo de contexto (`__enter__` y `__exit__`).
* Al entrar en el bloque, se invoca `__enter__()`, abriendo el archivo y asignando el recurso.
* Al salir del bloque (ya sea por finalización natural o debido a una excepción fatal como `ValueError` o `KeyboardInterrupt`), se invoca de forma automática e inapelable `__exit__()`, que ejecuta internamente `file.close()`.

> [!IMPORTANT]
> **Prevención de Fuga de Descriptores (*Resource Leak*):**
> En sistemas Unix y Windows, el kernel asigna un **Descriptor de Archivo (*File Descriptor* - FD)** por cada archivo abierto. Si un analista usa la forma obsoleta `file = open(...)` sin `with` y el programa falla antes de ejecutar `file.close()`, el FD permanece bloqueado en la tabla del sistema operativo. Un script del SOC que analice miles de archivos de registro puede agotar la tabla de FDs del sistema (*file descriptor exhaustion*), provocando el colapso de servicios críticos.

---

### 2.2. La Función `open()` y sus Parámetros
La función integrada `open()` solicita al sistema operativo el acceso al archivo en disco.

#### Parámetro 1: Ubicación del Archivo (Rutas Relativas vs. Absolutas)
* **Ruta Relativa:** Hace referencia a la ubicación del archivo respecto al **directorio de trabajo actual (*Current Working Directory* - CWD)** desde donde se ejecuta el script.
  * Si el script `log_parser.py` y el archivo `update_log.txt` residen en el mismo directorio:
    ```python
    with open("update_log.txt", "r") as file:
    ```
* **Ruta Absoluta:** Especifica la ruta completa e inequívoca desde la raíz del sistema de archivos (*root* `/` en Linux o unidad `C:\` en Windows). Es obligatoria cuando el archivo reside en otro directorio del sistema:
  * Linux / macOS:
    ```python
    with open("/home/analyst/logs/access_log.txt", "r") as file:
    ```
  * Windows:
    ```python
    with open("C:/Users/analyst/logs/access_log.txt", "r") as file:
    ```

> [!TIP]
> **Compatibilidad de Separadores de Ruta:**
> En Windows, Python admite el uso de barras inclinadas hacia adelante (`/`) en las cadenas de ruta, lo que evita colisiones con el carácter de escape de barra invertida (`\` en `"C:\temp"` interpretaría `\t` como tabulación). Alternativamente, se recomienda usar cadenas crudas (`r"C:\Users\analyst\logs"`) o el módulo estándar `pathlib`.

#### Parámetro 2: Modo de Acceso (*Access Mode*)
Especifica la intención y los permisos de la operación:
* **`"r"` (Read):** Lectura exclusiva. El archivo debe existir previamente; de lo contrario, arroja `FileNotFoundError`.
* **`"w"` (Write):** Escritura destructiva. Si el archivo existe, su contenido es **truncado a 0 bytes**. Si no existe, lo crea.
* **`"a"` (Append):** Escritura al final del archivo (*append-only*). Preserva los datos existentes y escribe tras el último byte.

#### Parámetro de Codificación (`encoding="utf-8"`)
Aunque a menudo se omite en ejemplos básicos, en ciberseguridad es una buena práctica obligatoria especificar `encoding="utf-8"` para evitar errores de decodificación (`UnicodeDecodeError`) cuando los logs contienen caracteres internacionales o marcas forenses especiales.

---

### 2.3. La Cláusula `as` y la Variable de Referencia
La palabra clave `as` crea una variable local que apunta directamente al flujo de I/O (*stream*) devuelto por `open()`, conocido como el **manejador del archivo (*file handle*)**. En el código `with open(...) as file:`, `file` es una instancia de la clase `_io.TextIOWrapper`, sobre la cual se invocan los métodos `.read()` o `.write()`.

## 3. Lectura de Archivos en Memoria con `.read()`

El método `.read()` extrae la totalidad del contenido del archivo y lo transfiere a la memoria RAM como una única cadena de texto (`str`).

```python
with open("update_log.txt", "r", encoding="utf-8") as file:
    updates = file.read()

print("Contenido leído:")
print(updates)
```

```
┌──────────────────────────────────────┐       .read()        ┌──────────────────────────────────────┐
│        ARCHIVO EN DISCO              │ ───────────────────► │          OBJETO str EN RAM           │
│ "2026-09-21,OS_Patch_v4.2,SUCCESS\n" │                      │ updates = "2026-09-21,OS_Patch..."   │
│ "2026-09-21,AV_Update_v1.1,SUCCESS"  │                      │ (Permite slicing, .index, len, etc.) │
└──────────────────────────────────────┘                      └──────────────────────────────────────┘
```

### 3.1. Manipulación de la Cadena Resultante
Una vez que el archivo ha sido leído en la variable `updates`, se aplican todas las operaciones estándar de cadenas analizadas previamente:

```python
with open("update_log.txt", "r", encoding="utf-8") as file:
    updates = file.read()

# 1. Medir la longitud total del log en caracteres
log_length = len(updates)
print(f"Total de caracteres en el archivo: {log_length}")

# 2. Localizar subcadenas específicas de incidentes
search_term = "SUCCESS"
if search_term in updates:
    first_index = updates.index(search_term)
    print(f"La primera aparición de '{search_term}' está en el índice: {first_index}")

# 3. Segmentar por líneas para procesamiento estructurado
lines = updates.splitlines()
print(f"Total de registros individuales: {len(lines)}")
```

> [!WARNING]
> **Consideración de Memoria con Archivos Masivos:**
> El método `.read()` carga **absolutamente todo** el archivo en la memoria del proceso. Si se intenta leer un archivo de volcado de red (*packet capture dump*) o un log de proxy de 30 GB utilizando `.read()` en un servidor con 16 GB de RAM, Python arrojará un error fatal `MemoryError` o el sistema activará el *OOM Killer*. Para logs gigantescos, se debe iterar línea a línea (`for line in file:`).

## 4. Escritura en Archivos: Modo `"w"` vs. Modo `"a"`

En la automatización de ciberseguridad, la escritura permite generar reportes, aislar eventos sospechosos y actualizar políticas de control de acceso.

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│                             COMPARATIVA DE ESCRITURA EN PYTHON                           │
├────────────────────────────┬─────────────────────────────┬───────────────────────────────┤
│ Característica             │ Modo Escritura ("w")        │ Modo Anexado ("a")            │
├────────────────────────────┼─────────────────────────────┼───────────────────────────────┤
│ Si el archivo existe       │ BORRA y TRUNCA a 0 bytes    │ PRESERVA el contenido previo  │
│ Si el archivo no existe    │ Crea un archivo nuevo vacío │ Crea un archivo nuevo vacío   │
│ Posición inicial cursor    │ Inicio (byte 0)             │ Final del archivo (EOF)       │
│ Caso de uso en el SOC      │ Generar allowlist limpia    │ Registrar nuevo intento login │
│ Riesgo operativo           │ Pérdida accidental de logs  │ Crecimiento indefinido disco  │
└────────────────────────────┴─────────────────────────────┴───────────────────────────────┘
```

---

### 4.1. Modo `"w"`: Escritura y Creación de Archivos Nuevos
El modo `"w"` se utiliza para sobrescribir configuraciones o inicializar nuevos archivos:

```python
# Creación de un nuevo archivo de lista de usuarios permitidos
approved_users = "elarson\nbmoreno\ntshah\nsgilmore\n"

with open("approved_users.txt", "w", encoding="utf-8") as file:
    file.write(approved_users)

print("Lista de permitidos generada con éxito.")
```

> [!CAUTION]
> **Peligro de Truncado Accidental en Auditoría:**
> Ejecutar accidentalmente `with open("critical_audit_log.txt", "w")` sobre un archivo de evidencia histórica eliminará instantáneamente todos los registros previos de forma irrecuperable. Para registros de eventos, el modo predeterminado debe ser siempre `"a"`.

---

### 4.2. Modo `"a"`: Anexado Forense (*Append-Only*)
El modo `"a"` es el estándar para escribir eventos de seguridad, ya que garantiza que el historial nunca sea destruido:

```python
# Nueva línea de telemetría a registrar
new_log_entry = "jrafael,192.168.243.140,04:56:27,True\n"

with open("access_log.txt", "a", encoding="utf-8") as file:
    file.write(new_log_entry)

print("Evento anexado exitosamente al registro de accesos.")
```

---

### 4.3. El Método `.write()` y el Salto de Línea Explícito
A diferencia de la función `print()`, que incluye de forma predeterminada un carácter de fin de línea (`\n`), el método `.write()` **no agrega ningún carácter adicional**:
* Si se llama a `file.write("linea1")` y luego a `file.write("linea2")`, el archivo resultante contendrá `linea1linea2` pegado en una única línea.
* El analista debe incluir siempre el delimitador `\n` al final de cada registro para garantizar la integridad tabular.

### 4.4. Búfer de Entrada/Salida (*I/O Buffering*)
Los sistemas operativos no escriben físicamente en el disco sector por sector cada vez que se llama a `.write()`, sino que acumulan los bytes en un búfer en RAM para optimizar el rendimiento.
* Al usar `with open(...)`, el método `__exit__()` realiza un **vaciado forzado del búfer (*flush*)** antes de cerrar el archivo.
* Si no se usa `with` y el script finaliza abruptamente, parte de los datos en el búfer pueden perderse en el vacío, generando archivos de log corruptos o incompletos.

---

## 5. Matriz Completa de Modos de Apertura de Archivos

| Modo | Propósito | Puntero Inicial | ¿Crea Archivo si no existe? | ¿Sobrescribe / Trunca? |
| :---: | :--- | :---: | :---: | :---: |
| **`"r"`** | Solo lectura | Inicio | No (Lanza `FileNotFoundError`) | No |
| **`"w"`** | Solo escritura | Inicio | **Sí** | **Sí (Destructivo)** |
| **`"a"`** | Solo anexado | Final (EOF) | **Sí** | No (Preserva) |
| **`"r+"`** | Lectura y Escritura | Inicio | No (Lanza `FileNotFoundError`) | No |
| **`"w+"`** | Lectura y Escritura | Inicio | **Sí** | **Sí (Destructivo)** |
| **`"a+"`** | Lectura y Anexado | Final (EOF) | **Sí** | No (Preserva) |

## 6. Laboratorio Integrador: Sistema de Auditoría y Control de Acceso en Python

El siguiente script profesional implementa un flujo completo de ciberseguridad: verifica un registro de actualizaciones existente, procesa intentos de autenticación en un archivo de accesos y genera un nuevo archivo con las cuentas bloqueadas:

```python
import os
from typing import List

# Rutas de los artefactos forenses
UPDATE_LOG_PATH = "update_log.txt"
ACCESS_LOG_PATH = "access_log.txt"
QUARANTINE_FILE_PATH = "quarantine_list.txt"

# 1. Preparación de datos simulados en disco
initial_updates = (
    "2026-09-21 02:00:00,Patch_KB4012,SUCCESS\n"
    "2026-09-21 02:15:30,Patch_KB4015,FAILED\n"
    "2026-09-21 02:30:10,Patch_KB4019,SUCCESS\n"
)

with open(UPDATE_LOG_PATH, "w", encoding="utf-8") as f:
    f.write(initial_updates)

# 2. Lectura y Análisis de update_log.txt (Modo 'r')
print("=== FASE 1: AUDITORÍA DE PARCHES Y ACTUALIZACIONES ===")
with open(UPDATE_LOG_PATH, "r", encoding="utf-8") as file:
    updates_content = file.read()

print("Telemetría cargada exitosamente:")
print(updates_content.strip())

# Verificación de parches fallidos
if "FAILED" in updates_content:
    failed_index = updates_content.index("FAILED")
    print(f"[!] ALERTA: Se detectó una actualización fallida en la posición {failed_index}.")
else:
    print("[V] Todas las actualizaciones del sistema se aplicaron correctamente.")

# 3. Anexado en Tiempo Real a access_log.txt (Modo 'a')
print("\n=== FASE 2: REGISTRO DE EVENTOS EN TIEMPO REAL ===")
new_access_event = "jrafael,192.168.243.140,04:56:27,SUCCESS\n"
unauthorized_event = "attacker_bot,203.0.113.19,04:57:10,FAILED\n"

with open(ACCESS_LOG_PATH, "a", encoding="utf-8") as file:
    file.write(new_access_event)
    file.write(unauthorized_event)

print(f"[+] Eventos anexados a '{ACCESS_LOG_PATH}' sin alterar el historial.")

# 4. Generación de Lista de Cuarentena (Modo 'w')
print("\n=== FASE 3: GENERACIÓN DE POLÍTICA DE CUARENTENA ===")
# Leemos el archivo de accesos para detectar eventos 'FAILED'
blocked_users: List[str] = []

with open(ACCESS_LOG_PATH, "r", encoding="utf-8") as file:
    for line in file:
        line_clean = line.strip()
        if not line_clean:
            continue
        parts = line_clean.split(",")
        username = parts[0]
        status = parts[3]
        if status == "FAILED" and username not in blocked_users:
            blocked_users.append(username)

# Sobrescribimos el archivo de cuarentena con las cuentas identificadas
with open(QUARANTINE_FILE_PATH, "w", encoding="utf-8") as file:
    for user in blocked_users:
        file.write(f"{user}\n")

print(f"[+] Archivo '{QUARANTINE_FILE_PATH}' generado con {len(blocked_users)} cuentas bloqueadas.")

# 5. Limpieza de archivos de prueba
for temp_file in [UPDATE_LOG_PATH, ACCESS_LOG_PATH, QUARANTINE_FILE_PATH]:
    if os.path.exists(temp_file):
        os.remove(temp_file)
print("\n[V] Entorno de laboratorio limpiado correctamente.")
```

## 7. Resumen y Puntos Clave

1. **Sentencia `with`:** Gestiona el ciclo de vida del archivo mediante el protocolo de contexto; garantiza el cierre inmediato y determinista del descriptor de archivo, impidiendo la saturación de recursos del sistema (*resource leaks*).
2. **Función `open()`:** Requiere la ruta del archivo (relativa o absoluta), el modo de operación (`"r"`, `"w"`, `"a"`) y la codificación recomendada (`encoding="utf-8"`).
3. **Lectura con `.read()`:** Convierte el archivo completo en una cadena `str` en memoria, permitiendo el uso de métodos de texto (`.index()`, `len()`, `.splitlines()`). Debe emplearse con precaución ante archivos masivos.
4. **Modo Escritura (`"w"`):** Destructivo. Trunca a cero bytes los archivos preexistentes o crea uno nuevo si no existe. Ideal para inicializar listas de permitidos limpias.
5. **Modo Anexado (`"a"`):** Seguro y no destructivo. Añade datos exclusivamente al final del archivo, siendo el modo estándar para registrar telemetría e incidentes forenses.
6. **Método `.write()`:** Requiere datos de tipo cadena y no inserta automáticamente saltos de línea (`\n`), requiriendo que el analista estructure explícitamente los delimitadores.
