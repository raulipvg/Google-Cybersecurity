# Parámetros, Argumentos y Ámbito de Variables en Python: Variables Globales vs. Locales en Ciberseguridad

En esta octava entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se analizan los mecanismos de **intercambio de datos entre funciones** y el **modelo de visibilidad o ámbito (*scope*) de las variables**. En la programación defensiva y la automatización del SOC, entender la diferencia exacta entre **parámetros** y **argumentos**, dominar la salida estructurada con **`return`** y evitar errores de **sombreamiento de variables (*variable shadowing*)** entre ámbitos globales y locales es fundamental para prevenir fallos silenciosos en scripts de contención de cuentas, bloqueo de cortafuegos y análisis forense.

---

## 1. Flujo de Datos y Fronteras de Ejecución en Funciones

Una función bien diseñada opera como una **caja negra modular**: recibe entradas claramente definidas, ejecuta transformaciones internas aisladas y devuelve un resultado explícito sin alterar impredeciblemente el entorno global del sistema.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                          FLUJO DE DATOS EN UNA FUNCIÓN DE PYTHON                          │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
    [ ARGUMENTOS REALES ]                     │
    (Valores en la llamada)                   │
             │                                │
             ▼                                │
  ┌─────────────────────────────────────┐     │
  │ PARÁMETROS (Variables receptoras)   │     │
  ├─────────────────────────────────────┤     │
  │ maximum_attempts, total_attempts    │     │
  ├─────────────────────────────────────┤     │
  │      CUERPO DE LA FUNCIÓN           │     │
  │ • Variables Locales (Efímeras)      │     │
  │ • Cálculos y lógica de detección    │     │
  ├─────────────────────────────────────┤     │
  │ SENTENCIA RETURN                    │     │
  └──────────────────┬──────────────────┘     │
                     │                        │
                     ▼                        │
         [ VALOR DE RETORNO ]                 │
         (Capturado en variable / if)         │
```

## 2. Parámetros vs. Argumentos: Mecanismo de Mapeo

Aunque en el lenguaje coloquial se utilizan indistintamente, en computación poseen definiciones técnicas y roles operativos rigurosamente diferenciados:

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                         PARÁMETROS vs. ARGUMENTOS: DISTINCIÓN TÉCNICA                     │
├──────────────────────────────────────┬────────────────────────────────────────────────────┤
│ PARÁMETRO (*Parameter*)              │ ARGUMENTO (*Argument*)                             │
├──────────────────────────────────────┼────────────────────────────────────────────────────┤
│ • Variable definida en el encabezado │ • Valor concreto o dato real que se pasa a la      │
│   de la función al declararla.       │   función al momento de invocarla.                 │
│ • Actúa como un marcador de posición │ • Asigna un valor en memoria al parámetro receptor.│
│   (*placeholder*) a la espera de     │ • Determinado comúnmente por su posición en la     │
│   datos reales.                      │   llamada (*positional argument*).                 │
│ • Ej: `maximum_attempts`             │ • Ej: `3`, `"nzhao"`, `True`                       │
└──────────────────────────────────────┴────────────────────────────────────────────────────┘
```

### 2.1. Mapeo Posicional en la Práctica
Python asigna los argumentos a los parámetros de izquierda a derecha según el orden en que fueron pasados:

```python
# Definición: maximum_attempts y total_attempts son PARÁMETROS
def remaining_login_attempts(maximum_attempts, total_attempts):
    print(maximum_attempts - total_attempts)

# Invocación: 3 y 2 son ARGUMENTOS
remaining_login_attempts(3, 2)
```

```
ASIGNACIÓN POSICIONAL:
  Argumento 1: 3 ──► Asignado a Parámetro 1: maximum_attempts
  Argumento 2: 2 ──► Asignado a Parámetro 2: total_attempts
  Cálculo:     3 - 2 ──► Salida: 1
```

## 3. La Sentencia `return`: Explotación y Control de Flujo

La palabra clave **`return`** se utiliza para enviar información computada desde el interior de la función hacia el entorno que la invocó.

### 3.1. Reglas Sintácticas Fundamentales de `return`
1. **No es una Función:** `return` es una **palabra reservada del lenguaje**, no una función. Por tanto, no se colocan paréntesis obligatorios tras ella (escriba `return valor`, no `return(valor)`).
2. **Finalización Inmediata de la Ejecución:** Cuando el intérprete alcanza un `return`, evalúa la expresión asociada, devuelve el resultado y **sale de la función al instante**. Cualquier línea de código escrita después de un `return` en el mismo bloque es **código inalcanzable (*dead code*)** y jamás se ejecutará.

### 3.2. Captura y Reutilización en Lógica Condicional del SOC
A diferencia de `print()` (que solo muestra caracteres en consola y descarta el dato), `return` permite almacenar la salida en una variable para alimentar reglas de contención:

```python
def remaining_login_attempts(maximum_attempts, total_attempts):
    """Calcula y devuelve los intentos restantes antes del bloqueo."""
    return maximum_attempts - total_attempts

# Captura del valor retornado en una variable operativa
remaining_attempts = remaining_login_attempts(3, 3)

# Evaluación lógica para contención de cuentas comprometidas
if remaining_attempts <= 0:
    print("Your account is locked")
```

```text
Salida:
Your account is locked
```

## 4. Ámbito de Variables (*Variable Scope*): Globales vs. Locales

El **ámbito (*scope*)** define la región de un programa donde un identificador o variable es reconocido, accesible y válido en memoria.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                      MAPA DE ÁMBITOS EN LA MEMORIA DE CPYTHON                             │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌─────────────────────────────────────────────────────────────────────────────────────────┐
 │ ESPACIO GLOBAL (Raíz del Script / Global Scope)                                         │
 │ device_id = "7ad2130bd"                                                                 │
 │ MAX_RETRIES = 5                                                                         │
 │                                                                                         │
 │   ┌─────────────────────────────────────────────────────────────────────────────────┐   │
 │   │ MARCO LOCAL DE FUNCIÓN (Stack Frame / Local Scope)                              │   │
 │   │ def greet_employee(name):                                                       │   │
 │   │     name = "Alice"              ◄── Parámetro (Local)                           │   │
 │   │     total_string = "Welcome..." ◄── Variable Local                              │   │
 │   │     [Se destruyen al terminar]                                                  │   │
 │   └─────────────────────────────────────────────────────────────────────────────────┘   │
 └─────────────────────────────────────────────────────────────────────────────────────────┘
```

---

### 4.1. Variables Globales
* **Definición:** Se declaran en el nivel principal del script, fuera de cualquier función.
* **Ciclo de Vida:** Nacen cuando se ejecuta la línea de asignación y persisten en la memoria RAM durante toda la vida útil del proceso.
* **Disponibilidad:** Son legibles desde cualquier parte del código, incluyendo el interior de bucles, condicionales y funciones.

```python
# Variable global accesible en todo el programa
device_id = "7ad2130bd"

def auditar_dispositivo():
    # La función lee la variable global sin problemas
    print("Auditando hardware con ID:", device_id)

auditar_dispositivo()
print("Verificación de ID fuera de la función:", device_id)
```

---

### 4.2. Variables Locales
* **Definición:** Variables asignadas **dentro del cuerpo de una función**, así como sus **parámetros**.
* **Ciclo de Vida Efímero:** Python crea un nuevo marco en la pila (*stack frame*) al invocar la función, aloja las variables locales mientras se ejecutan sus instrucciones y **las destruye de la memoria RAM** tan pronto como la función retorna.
* **Inaccesibilidad Externa:** Intentar acceder a una variable local desde fuera de su función provoca un error fatal `NameError`.

```python
def greet_employee(name):
    total_string = "Welcome " + name # total_string y name son LOCALES
    return total_string

saludo = greet_employee("nzhao")
print(saludo) # Welcome nzhao

# INTENTO DE ACCESO INVÁLIDO:
# print(total_string) 
# Provoca: NameError: name 'total_string' is not defined
```

## 5. Sombreamiento de Variables (*Variable Shadowing*) y Colisiones de Nombres

El **sombreamiento (*variable shadowing*)** ocurre cuando se asigna una variable local con el **mismo nombre exacto** que una variable global existente.

### 5.1. Mecanismo de Sombreamiento en CPython
Cuando una función define una variable local con un nombre idéntico a una global:
1. Python crea una **variable local independiente** en el marco de la función.
2. La variable local "hace sombra" (*shadows*) a la variable global, volviéndola invisible dentro del cuerpo de esa función.
3. **La variable global original permanece intacta e inalterada**.

```python
# 1. Asignación global
username = "elarson"
print("1: " + username) # Lee global -> "elarson"

def greet():
    # 2. Asignación LOCAL: Sombrea a la global
    username = "bmoreno"
    print("2: " + username) # Lee local -> "bmoreno"

greet()

# 3. Lectura post-función
print("3: " + username) # Sigue leyendo la global -> "elarson"
```

```text
Salida del programa:
1: elarson
2: bmoreno
3: elarson
```

```
ANÁLISIS DE MEMORIA DEL SOMBREAMIENTO:

  Espacio Global: [ username = "elarson" ] ─────────────────────────┐ (Permanece Intacto)
                          │                                         │
                          ▼ (Invocación greet())                    │
  Marco Local:    [ username = "bmoreno" ] ──► Se destruye al salir │
                                                                    ▼
  Espacio Global: [ username = "elarson" ] ◄────────────────────────┘
```

---

### 5.2. El Peligro del Sombreamiento en Ciberseguridad

En scripts de automatización de seguridad, el sombreamiento accidental es una fuente crítica de **vulnerabilidades de lógica y falsos estados**:
* Un analista puede escribir una función para revocar un token o agregar una IP a una lista de bloqueo:
  ```python
  blocked_ips = ["192.168.1.10"] # Global

  def isolate_host(ip):
      # ERROR: Crea una variable local blocked_ips sin alterar la global
      blocked_ips = [ip] 
      print("[+] IP bloqueada localmente:", blocked_ips)

  isolate_host("203.0.113.50")
  # ¡La IP 203.0.113.50 NUNCA se agregó a la lista global de firewall!
  print("[!] Estado del cortafuegos real:", blocked_ips) # ['192.168.1.10']
  ```

---

### 5.3. La Regla de Resolución de Ámbitos LEGB
Cuando Python busca el valor de un identificador, recorre cuatro niveles de resolución en orden estricto:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                         LA REGLA LEGB EN PYTHON                              │
├──────────────────────────────────────────────────────────────────────────────┤
│ 1. Local (L):      Variables definidas dentro de la función actual.          │
│ 2. Enclosing (E):  Ámbito de funciones anidadas superiores (si existen).     │
│ 3. Global (G):     Variables declaradas en el nivel raíz del módulo/script.  │
│ 4. Built-in (B):   Nombres integrados del lenguaje (`print`, `len`, `range`).│
└──────────────────────────────────────────────────────────────────────────────┘
```

> [!WARNING]
> **La Palabra Clave `global` y por qué Debe Evitarse:**
> Python proporciona la instrucción `global variable_name` para permitir que una función modifique directamente una variable global. Sin embargo, en el desarrollo seguro de software del SOC, **se desaconseja rotundamente su uso**. Las variables globales mutables generan efectos secundarios ocultos, dificultan el rastreo forense de errores y rompen el aislamiento modular. La solución pythónica correcta es **pasar los datos como parámetros y devolver las modificaciones con `return`**.

## 6. Matriz Comparativa: Variables Globales vs. Variables Locales

| Característica | Variables Globales | Variables Locales |
| :--- | :--- | :--- |
| **Ubicación de Definición** | Nivel raíz del script (fuera de funciones). | Dentro del cuerpo de la función o parámetros. |
| **Visibilidad / Alcance** | En todo el archivo (módulo completo). | Exclusiva dentro de la función que la aloja. |
| **Tiempo de Vida (*Lifetime*)**| Persiste mientras el script esté corriendo. | Efímero (se destruye al terminar la función). |
| **Alojamiento en Memoria** | Tabla de símbolos global del módulo. | Marco de pila (*Stack frame*) de la función. |
| **Riesgo de Colisión** | Alto (puede ser leída o sombreada por error).| Nulo (completamente aislada del resto del código).|
| **Mejor Uso en SOC** | Constantes de configuración (`MAX_ATTEMPTS`). | Variables de cómputo, bucles y lógica de triage. |

## 7. Casos Prácticos en Operaciones de Ciberseguridad (SOC)

### Caso 1: Sistema de Bloqueo Progresivo de Cuentas

```python
# Constante global de configuración (Inmutable según convención PEP 8)
MAX_GLOBAL_ATTEMPTS = 5

def evaluar_acceso(usuario, intentos_actuales):
    """
    Evalúa el estado de bloqueo de forma pura sin depender de variables globales mutables.
    Devuelve una tupla (esta_bloqueado, intentos_restantes).
    """
    restantes = MAX_GLOBAL_ATTEMPTS - intentos_actuales
    if restantes <= 0:
        return True, 0
    return False, restantes

# Prueba con dos cuentas independientes
usuario_a = "jdoe"
intentos_a = 5

bloqueado, margen = evaluar_acceso(usuario_a, intentos_a)

if bloqueado:
    print(f"[BLOQUEO SOC] La cuenta {usuario_a} ha sido suspendida. Intentos restantes: {margen}")
```

### Caso 2: Función Pura de Sanitización y Aislamiento de Credenciales

```python
def sanitizar_cabecera_auth(token_crudo):
    """
    Elimina espacios y valida la longitud del token.
    La variable 'token_limpio' existe únicamente en memoria durante el análisis,
    protegiendo la credencial de fugas accidentales en el entorno global.
    """
    token_limpio = token_crudo.strip()
    if len(token_limpio) == 64: # Longitud estándar de token SHA-256
        return token_limpio
    return None

# El token global sin procesar entra a la función
token_recibido = "   9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08   "
token_verificado = sanitizar_cabecera_auth(token_recibido)

if token_verificado:
    print("[+] Autenticación API autorizada con credencial sanitizada.")
else:
    print("[-] Token corrupto o de longitud no válida.")
```

## 8. Puntos Clave para el Analista de Ciberseguridad

* **Parámetros vs. Argumentos:** Los parámetros son las variables receptoras declaradas en `def`; los argumentos son los datos reales que se envían al invocar la función.
* **`return` Explicito:** La instrucción `return` finaliza inmediatamente la función y entrega el dato al llamador. No requiere paréntesis.
* **Ámbito Local Efímero:** Las variables locales y los parámetros se crean al ejecutarse la función y se purgan de la memoria RAM al concluir, garantizando el aislamiento de datos sensibles.
* **Prevención del Sombreamiento (*Shadowing*):** Asignar una variable dentro de una función con el mismo nombre que una variable global no modifica la global; crea una variable local oculta que genera fallas de lógica graves en scripts de seguridad.
* **Arquitectura de Funciones Puras:** Evite el uso de variables globales mutables y la instrucción `global`. Reciba siempre los datos por parámetros y devuelva las modificaciones mediante `return`.
