# Entornos de Desarrollo y Ejecución de Python: Notebooks, IDEs y Línea de Comandos (CLI)

En esta segunda entrega del **Curso 7: Automatizar tareas de ciberseguridad con Python**, se analizan los distintos entornos en los que un analista de seguridad escribe, prueba, depura y ejecuta código. Se profundiza en la arquitectura interna y dinámica de los **cuadernos interactivos (*notebooks*)** —el entorno pedagógico principal del curso—, las características avanzadas de los **Entornos de Desarrollo Integrados (*IDEs*)**, el poder operativo de la **interfaz de línea de comandos (*CLI*)** y el bucle interactivo **REPL**, así como el aislamiento de dependencias mediante **entornos virtuales (*virtual environments*)**.

## 2. Cuadernos Interactivos (*Notebooks*): Jupyter y Google Colab

Un **cuaderno (*notebook*)** es una interfaz basada en web que integra código ejecutable, visualizaciones gráficas y texto explicativo enriquecido dentro de un único documento interactivo (con extensión estándar `.ipynb`).

### 2.1. Arquitectura Cliente-Servidor del Notebook

Los notebooks no ejecutan el código directamente en el navegador web; operan bajo un modelo desacoplado:

```
┌────────────────────────────────────────┐       WebSockets / ZeroMQ       ┌────────────────────────────────────────┐
│             NAVEGADOR WEB              │ ◄─────────────────────────────► │          KERNEL DE PYTHON              │
│  (Frontend: Celdas, Markdown, Gráficos)│                                 │   (Backend: Intérprete CPython + RAM)  │
└────────────────────────────────────────┘                                 └────────────────────────────────────────┘
```

1. **Frontend (Interfaz de Usuario):** El analista escribe código en el navegador e interactúa con los controles de ejecución.
2. **Kernel (Motor de Computación):** Es un proceso independiente de Python que mantiene el estado de las variables en la memoria RAM del sistema, ejecuta el código enviado por las celdas y devuelve las salidas estructuradas o errores al navegador.

---

### 2.2. Anatomía de un Notebook: Celdas de Código vs. Celdas de Markdown

El contenido de un notebook se divide en dos tipos fundamentales de bloques o **celdas**:

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                          TIPOS DE CELDAS EN UN CUADERNO PYTHON                            │
├────────────────────────────┬──────────────────────────────────────────────────────────────┤
│ Celda de Código            │ Diseñada para escribir y ejecutar sintaxis Python válida.    │
│                            │ • Posee un botón de ejecución (*Play* o `Shift + Enter`).     │
│                            │ • Muestra el resultado (stdout, gráficos o trazas de error)   │
│                            │   inmediatamente debajo del bloque.                          │
├────────────────────────────┼──────────────────────────────────────────────────────────────┤
│ Celda de Markdown          │ Diseñada para documentación técnica en texto plano formateado.│
│                            │ • Soporta encabezados, negritas, enlaces, tablas e imágenes. │
│                            │ • No se ejecuta en el kernel; se renderiza como HTML visual. │
└────────────────────────────┴──────────────────────────────────────────────────────────────┘
```

#### Ejemplo de Flujo en Celdas de un Notebook:

```markdown
<!-- Celda Markdown: Contexto de la investigación -->
### Investigación de Alerta: Escaneo de Puertos Detectado
Analizamos el archivo `/var/log/auth.log` para aislar las IPs que superaron 10 intentos fallidos.
```

```python
# Celda de Código: Ejecución de la lógica en Python
with open("ips_sospechosas.txt", "r") as f:
    ips_bloqueadas = [line.strip() for line in f if line.strip()]

print(f"Total de direcciones IP catalogadas para contención: {len(ips_bloqueadas)}")
```

```text
[Salida de la Celda de Código]:
Total de direcciones IP catalogadas para contención: 42
```

> [!WARNING]
> **El Peligro del Estado Compartido y la Ejecución Desordenada:**
> En un notebook, las celdas pueden ejecutarse en cualquier orden. Si el analista modifica una variable en la Celda 5 y luego vuelve a ejecutar la Celda 2, el kernel mantendrá los valores sobreescritos. En investigaciones forenses, se debe garantizar la reproducibilidad ejecutando siempre el notebook secuencialmente desde el menú: **Kernel ➔ Restart & Run All**.

### 2.3. Entornos Comunes de Cuadernos
* **Project Jupyter (Jupyter Notebook / JupyterLab):** Plataforma de código abierto que se ejecuta localmente en la máquina del analista o en servidores del SOC vía `localhost:8888`. Ofrece soberanía total sobre los datos, garantizando que logs sensibles no salgan de la red corporativa.
* **Google Colaboratory (Google Colab):** Servicio en la nube alojado por Google. Permite ejecutar notebooks sin necesidad de instalar Python en el equipo local, ofreciendo integración nativa con Google Drive y acceso a recursos computacionales de alto rendimiento (GPUs/TPUs). Ideal para prototipar modelos de *Machine Learning* aplicados a detección de anomalías.

## 3. Entornos de Desarrollo Integrados (*IDEs*)

Un **Entorno de Desarrollo Integrado (*IDE*)** es una aplicación de escritorio que consolida todas las herramientas necesarias para diseñar proyectos de software complejos en una única interfaz gráfica de usuario (GUI).

### 3.1. Componentes Clave de un IDE Profesional

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                              ARQUITECTURA DE UN IDE MODERNO                               │
├─────────────────────────────┬─────────────────────────────────────────────────────────────┤
│ Componente                  │ Función Operativa en Ciberseguridad                         │
├─────────────────────────────┼─────────────────────────────────────────────────────────────┤
│ **Editor de Código con LSP**│ Resaltado de sintaxis, autocompletado inteligente           │
│ *(Language Server Protocol)*│ (*IntelliSense*) y detección de errores sintácticos al vuelo│
├─────────────────────────────┼─────────────────────────────────────────────────────────────┤
│ **Depurador (*Debugger*)**  │ Permite pausar la ejecución en puntos de interrupción       │
│                             │ (*breakpoints*), inspeccionar variables y llamadas de pila. │
├─────────────────────────────┼─────────────────────────────────────────────────────────────┤
│ **Terminal Integrada**      │ Ejecuta comandos del sistema, activa entornos virtuales y   │
│                             │ realiza pruebas CLI sin salir del entorno de edición.       │
├─────────────────────────────┼─────────────────────────────────────────────────────────────┤
│ **Control de Versiones**    │ Integración visual con Git (commits, diffs, ramas y fusiones│
│ *(Git Integration)*         │ para manuales de respuesta a incidentes automatizados).     │
└─────────────────────────────┴─────────────────────────────────────────────────────────────┘
```

### 3.2. IDEs Destacados en Seguridad
* **Visual Studio Code (VS Code):** Editor extensible líder gracias a su ecosistema de extensiones (Pylance, Python Debugger, extensiones de YARA, Hex Editor y Docker).
* **PyCharm (JetBrains):** IDE especializado en Python con análisis estático profundo, refactorización avanzada y gestión visual de bases de datos.
* **Antigravity IDE:** Entorno optimizado para flujos asistidos por agentes inteligentes y automatización directa de infraestructuras.

## 4. La Interfaz de Línea de Comandos (*CLI*) y el Modo REPL

La **interfaz de línea de comandos (*CLI*)** es el entorno nativo por excelencia del analista de sistemas y ciberseguridad. Proporciona acceso directo al sistema de archivos del sistema operativo sin sobrecarga gráfica.

### 4.1. El Bucle Interactivo REPL (*Read-Eval-Print Loop*)

Al escribir únicamente `python` o `python3` en una terminal (Bash, Zsh o PowerShell), se inicia el entorno interactivo de Python:

```
┌──────────────┐     Lee la instrucción ingresada por el analista.
│   1. READ    │ ──► [ Entrada: hashlib.md5(b"malware.exe").hexdigest() ]
└──────────────┘
       │
       ▼
┌──────────────┐     El intérprete compila y ejecuta la lógica en memoria.
│   2. EVAL    │
└──────────────┘
       │
       ▼
┌──────────────┐     Muestra el resultado inmediatamente en la consola.
│  3. PRINT    │ ──► [ Salida: 'e4d909c290d0fb1ca068ffaddf22cbd0' ]
└──────────────┘
       │
       ▼
┌──────────────┐     Vuelve a mostrar el prompt `>>>` esperando la siguiente orden.
│   4. LOOP    │
└──────────────┘
```

> [!TIP]
> **Uso del REPL en Incidentes:** El modo REPL es ideal para pruebas rápidas de laboratorio: validar una expresión regular contra una cadena sospechosa, decodificar un fragmento Base64 o verificar si un módulo específico (`import scapy`) está disponible en el servidor.

---

### 4.2. Ejecución de Scripts por Lotes (*Batch Scripts* `.py`)

Para tareas de automatización permanente (ej. demonios de monitoreo, analizadores de logs programados en *cron jobs* o conectores SIEM), los analistas guardan el código en archivos de texto plano con extensión `.py` y los invocan desde la CLI:

```bash
# Ejecución estándar de un script pasando argumentos posicionales
python3 escanear_red.py --subred 192.168.1.0/24 --puertos 22,80,443
```

#### Editores de Texto en Consola para Respuestas de Emergencia:
Cuando se responde a un incidente en un servidor Linux remoto sin interfaz gráfica vía SSH, el analista no dispone de VS Code ni de Notebooks. En estas circunstancias, el código se edita directamente en la terminal mediante editores ligeros como:
* **`nano`:** Sencillo, con atajos visibles en pantalla (ideal para ediciones rápidas).
* **`vim` / `neovim`:** Editor modal altamente eficiente para navegación y modificación rápida de scripts en servidores de producción.

## 5. Aislamiento de Entornos mediante Entornos Virtuales (`venv`)

En proyectos de seguridad reales, diferentes herramientas requieren versiones incompatibles de paquetes externos (por ejemplo, una herramienta de extracción forense requiere `cryptography==3.4` mientras que un script de API Cloud requiere `cryptography==41.0`). Instalar todo en el Python global del sistema operativo puede corromper las herramientas del propio sistema.

Un **entorno virtual (*virtual environment*)** es un directorio aislado que contiene su propio intérprete de Python y su propio conjunto independiente de librerías:

```bash
# 1. Crear un entorno virtual aislado llamado 'entorno_soc'
python3 -m venv entorno_soc

# 2. Activar el entorno virtual
# En GNU/Linux y macOS:
source entorno_soc/bin/activate
# En Windows (PowerShell):
.\entorno_soc\Scripts\Activate.ps1

# 3. Instalar librerías exclusivas para este proyecto
pip install requests scapy

# 4. Desactivar el entorno al finalizar
deactivate
```

## 6. Matriz Comparativa: Notebooks vs. IDEs vs. CLI

| Dimensión Técnica | Notebooks (Jupyter / Colab) | IDEs (VS Code / PyCharm) | Línea de Comandos (CLI / REPL) |
| :--- | :--- | :--- | :--- |
| **Formato de Archivo** | Archivos JSON estructurados (`.ipynb`) | Archivos de texto plano (`.py`) | Entrada en memoria (REPL) o `.py` |
| **Estilo de Ejecución** | Incremental celda por celda | Archivo completo o bloque seleccionado | Línea por línea (REPL) o por lotes |
| **Capacidad de Visualización**| Gráficos y tablas incrustados inline | Salida en terminal o ventana flotante | Texto plano ANSI en consola |
| **Depuración (*Debugging*)** | Básica (inspección de celda y print) | Avanzada (Breakpoints, Call Stack, Watch)| Básica con `pdb` en consola |
| **Consumo de Recursos** | Medio (requiere servidor web y kernel)| Alto (interfaz gráfica y analizadores) | Mínimo absoluto (ideal en servidores) |
| **Caso de Uso en SOC** | Informes de CTI, Threat Hunting interactivo | Construcción de herramientas y agentes | Automatización, Cron jobs, SSH triage |

## 7. Puntos Clave para el Analista de Ciberseguridad

* **La Herramienta Adecuada para la Tarea:** Se emplean Notebooks para documentar y presentar análisis forenses reproducibles; IDEs para desarrollar aplicaciones y scripts complejos; y la CLI para triage rápido en caliente y ejecución desatendida.
* **Estructura Dual del Notebook:** La combinación de **celdas de código** (computación) y **celdas de Markdown** (narrativa técnica) permite crear *Playbooks* ejecutables donde se explica la lógica del ataque junto con las pruebas de detección.
* **Indispensabilidad de la CLI:** Todo analista de incidentes debe ser capaz de editar y depurar scripts mediante la terminal (`nano`/`vim`) en servidores remotos restringidos sin acceso a entornos web o gráficos.
* **Aislamiento con `venv`:** El uso de entornos virtuales previene conflictos entre paquetes y protege la integridad del intérprete de Python nativo del sistema operativo.
