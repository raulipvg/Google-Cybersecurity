# Ejemplo de Actividad: Aplicar Técnicas de Endurecimiento del OS

Este documento presenta un ejemplo de reporte de análisis de incidente de ciberseguridad, documentando el protocolo de red comprometido, la secuencia del ataque y las recomendaciones de remediación mediante técnicas de endurecimiento del sistema operativo y controles de autenticación.

---

## Sección 1: Identificar el Protocolo de Red Involucrado en el Incidente

El protocolo involucrado en el incidente es el **Protocolo de Transferencia de Hipertexto (HTTP - *Hypertext Transfer Protocol*)**.

### Justificación Técnica:
- Debido a que el problema surgió al intentar acceder al servidor web del sitio `yummyrecipesforme.com`, sabemos que las solicitudes de páginas web implican tráfico HTTP.
- Al ejecutar la herramienta `tcpdump` e interactuar con el sitio web `yummyrecipesforme.com`, el archivo de registro resultante confirmó el uso del protocolo HTTP al contactar al servidor.
- El archivo malicioso fue transportado hacia las computadoras de los usuarios finales a través del protocolo HTTP en la **Capa de Aplicación** del modelo TCP/IP.

---

## Sección 2: Documentar el Incidente

### 1. Reporte Inicial del Incidente:
Varios clientes se pusieron en contacto con la mesa de ayuda del sitio web indicando que, al visitar la página, se les solicitó descargar y ejecutar un archivo que supuestamente ofrecía acceso a nuevas recetas. Desde entonces, sus computadoras personales han estado funcionando con extrema lentitud. Simultáneamente, el propietario del sitio web intentó iniciar sesión en el servidor web pero notó que había sido **bloqueado de su cuenta de administrador**.

### 2. Investigación en Entorno Aislado (Sandbox) y `tcpdump`:
- El analista de ciberseguridad utilizó un **entorno aislado (Sandbox)** para abrir el sitio web sin poner en riesgo la red corporativa.
- A continuación, ejecutó la herramienta `tcpdump` para capturar los paquetes de tráfico de red generados al interactuar con la página.
- El analista recibió el aviso de descarga de un archivo promocionado como acceso a recetas gratuitas, aceptó la descarga y ejecutó el archivo. De inmediato, el navegador lo redirigió a un sitio web falso (`greatrecipesforme.com`).

```
                              SECUENCIA DEL ATAQUE
┌───────────────────────┐       Tráfico HTTP       ┌───────────────────────┐
│ yummyrecipesforme.com ├─────────────────────────>│ Descarga de Malware   │
│   (Sitio Legítimo)    │                          │  (Falsa Actualización)│
└───────────────────────┘                          └───────────┬───────────┘
                                                               │
                                                               ▼
┌───────────────────────┐        Redirección       ┌───────────────────────┐
│ Compromiso del Host   │<─────────────────────────┤ greatrecipesforme.com │
│ (Equipos de Usuarios) │                          │     (Sitio Falso)     │
└───────────────────────┘                          └───────────────────────┘
```

### 3. Análisis de Registros de Red y Código Fuente:
- Al inspeccionar el registro de `tcpdump`, se observó que el navegador solicitó inicialmente la dirección IP de `yummyrecipesforme.com`. Una vez establecida la conexión mediante el protocolo HTTP, se descargó y ejecutó el archivo.
- Los registros mostraron un cambio repentino e inesperado en el tráfico de red cuando el navegador solicitó una nueva IP para la URL `greatrecipesforme.com`, redirigiendo todo el tráfico saliente hacia esa nueva IP.
- El profesional sénior de ciberseguridad analizó el código fuente de los sitios web y del archivo descargado, descubriendo que un atacante había manipulado el código del sitio original para inyectar un aviso emergente que incitaba a los usuarios a descargar un **archivo malicioso disfrazado de actualización del navegador**.

### 4. Causa Raíz del Incidente:
Dado que el propietario del sitio afirmó estar bloqueado de su cuenta de administrador, el equipo concluyó que el atacante ejecutó un **ataque de fuerza bruta** aprovechando una **contraseña por defecto** para comprometer la cuenta de administración, modificar el código fuente del sitio e infectar a los usuarios finales.

---

## Sección 3: Recomendar Remedios para Ataques de Fuerza Bruta

Para endurecer el sistema y prevenir futuros ataques de fuerza bruta, el equipo planea implementar las siguientes medidas de seguridad:

| Medida de Remediación | Descripción y Funcionamiento | Impacto en la Seguridad |
| :--- | :--- | :--- |
| **Prohibir Contraseñas Anteriores y por Defecto** | Impedir que el sistema permita reutilizar contraseñas antiguas o claves por defecto predeterminadas de fábrica al restablecer accesos. | Elimina la vulnerabilidad principal explotada en este ataque (uso de credenciales por defecto desatendidas). |
| **Actualizaciones Frecuentes de Contraseñas** | Exigir la rotación periódica de contraseñas mediante políticas de expiración en el sistema. | Reduce la ventana de oportunidad de un atacante si llega a obtener una credencial válida. |
| **Autenticación de Dos Factores (2FA)** | Requerir autenticación mediante la contraseña estándar más la confirmación de una clave de un solo uso (**OTP**) enviada al teléfono o correo. | Invalida los ataques de fuerza bruta directos, ya que la contraseña por sí sola no permite acceder al sistema. |

---

## Puntos Clave

1. **Protocolo Involucrado:** HTTP (Capa de Aplicación) utilizado para la entrega y descarga del malware.
2. **Vector de Ataque:** Fuerza bruta sobre la cuenta de administración debido al uso de contraseñas por defecto no modificadas.
3. **Impacto:** Alteración del código fuente del servidor web para inyectar descargas maliciosas (falsas actualizaciones) y redirección de usuarios a sitios maliciosos (`greatrecipesforme.com`).
4. **Endurecimiento Aplicado:** Eliminación de contraseñas por defecto, políticas de rotación de claves e implementación obligatoria de 2FA con OTP.
