# Protocolos de Red Adicionales

En esta lectura se estudian conceptos y protocolos de red fundamentales para el análisis de seguridad. Se analiza el funcionamiento de la traducción de direcciones de red (**NAT**), la asignación dinámica de IPs (**DHCP**), la resolución de direcciones de enlace (**ARP**), protocolos de acceso remoto (**Telnet** y **SSH**) y la suite de protocolos de correo electrónico (**POP3**, **IMAP** y **SMTP**), junto con sus respectivos puertos asignados por la **IANA** *(Internet Assigned Numbers Authority)*.

---

## Traducción de Direcciones de Red (NAT)

Los dispositivos en una red local doméstica o corporativa (LAN) disponen de **direcciones IP privadas** para comunicarse internamente. Sin embargo, para acceder a la Internet pública, la red requiere de **direcciones IP públicas**.

**NAT (*Network Address Translation*)** es el proceso mediante el cual un router o firewall sustituye la dirección IP de origen privada de un paquete saliente por su dirección IP pública única, y realiza el proceso inverso para los paquetes de respuesta entrantes.

- **Ubicación en el Modelo TCP/IP:** Capa de Internet y Capa de Transporte.
- **Propósito:** Conservar el agotamiento de direcciones IPv4 globales y proporcionar una capa básica de ocultamiento de la estructura de la red interna.

### Comparativa: Direcciones IP Privadas vs. Públicas

| Característica | Direcciones IP Privadas | Direcciones IP Públicas |
| :--- | :--- | :--- |
| **Asignación** | Asignadas localmente por el router (vía DHCP). | Asignadas por el Proveedor de Servicios (ISP) e IANA. |
| **Alcance** | Únicas únicamente dentro de la red local privada. | Únicas globalmente en toda la Internet. |
| **Costo** | Gratuito sin costo de arrendamiento. | Sujetas a costos de arrendamiento/alquiler. |
| **Enrutabilidad** | No enrutables en la Internet pública. | Enrutables públicamente en todo el mundo. |

#### Rangos Reservados de IP Privadas (RFC 1918):
- **Clase A:** `10.0.0.0` a `10.255.255.255` (`10.0.0.0/8`)
- **Clase B:** `172.16.0.0` a `172.31.255.255` (`172.16.0.0/12`)
- **Clase C:** `192.168.0.0` a `192.168.255.255` (`192.168.0.0/16`)

#### Rangos de IP Públicas Asignables:
- `1.0.0.0` – `9.255.255.255`
- `11.0.0.0` – `126.255.255.255`
- `128.0.0.0` – `172.15.255.255`
- `172.32.0.0` – `192.167.255.255`
- `192.169.0.0` – `233.255.255.255`

## Asignación y Resolución de Direcciones

### 1. DHCP (Dynamic Host Configuration Protocol / Protocolo de Configuración Dinámica de Host)
- **Capa TCP/IP:** Capa de Aplicación (Protocolo de Gestión).
- **Puertos:** 
  - **Servidor DHCP:** `UDP 67`
  - **Cliente DHCP:** `UDP 68`
- **Funcionamiento:** Automatiza la asignación de direcciones IP a los dispositivos que se conectan a la red. Además de la IP, suministra la máscara de red, la dirección de la **puerta de enlace predeterminada** *(Default Gateway)* y los servidores **DNS**.

### 2. ARP (Address Resolution Protocol / Protocolo de Resolución de Direcciones)
- **Capa TCP/IP:** Capa de Acceso a la Red (Capa 2 - Enlace de Datos).
- **Puerto:** **Ninguno** (opera en Capa 2 por debajo de los puertos de transporte/aplicación).
- **Funcionamiento:** Traduce una dirección IP conocida (lógica) a la dirección MAC (física y permanente de la tarjeta de interfaz de red - NIC) del dispositivo dentro de la misma red local.
- **Caché ARP:** Cada dispositivo mantiene una tabla o caché ARP local para almacenar temporalmente las correspondencias `IP <-> MAC` y evitar enviar solicitudes ARP *(ARP Requests)* constantes.

## Protocolos de Acceso Remoto

### 1. Telnet
- **Capa TCP/IP:** Capa de Aplicación.
- **Puerto:** `TCP 23`.
- **Funcionamiento:** Permite la administración remota de dispositivos mediante una interfaz de línea de comandos (CLI).
- **Riesgo de Ciberseguridad:** **Inseguro**. Transmite todo el tráfico (incluidas contraseñas y comandos) en **texto plano** *(cleartext)*. Cualquier atacante que capture paquetes mediante *sniffing* puede ver la información sin cifrar.

### 2. SSH (Secure Shell)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puerto:** `TCP 22`.
- **Funcionamiento:** Proporciona un canal seguro cifrado para la administración remota, la ejecución de comandos y la transferencia de archivos.
- **Ventaja:** Utiliza cifrado fuerte y autenticación mediante clave pública/privada. Es el reemplazo seguro y estándar para Telnet.

## Protocolos de Correo Electrónico

La gestión del correo electrónico implica protocolos específicos para la recepción (descarga/sincronización) y para el envío (transmisión).

```
                      ┌─────────────────────────────────────────┐
                      │    SUITE DE CORREO ELECTRÓNICO          │
                      └────────────────────┬────────────────────┘
                                           │
         ┌─────────────────────────────────┴─────────────────────────────────┐
         │ (Recepción / Recuperación)                                       │ (Envío / Transmisión)
         ▼                                                                   ▼
┌─────────────────────────────────┐                         ┌─────────────────────────────────┐
│ • POP3 (TCP 110 / TCP 995 SSL)  │                         │ • SMTP (TCP 25 / TCP 587 TLS)   │
│ • IMAP (TCP 143 / TCP 993 TLS)  │                         └─────────────────────────────────┘
└─────────────────────────────────┘
```

### 1. POP3 (Post Office Protocol version 3)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puertos:** 
  - **No Cifrado:** `TCP/UDP 110`
  - **Cifrado (SSL/TLS):** `TCP/UDP 995`
- **Funcionamiento:** Descarga los mensajes del servidor de correo al almacenamiento local del dispositivo del usuario. 
- **Consideración:** Tradicionalmente elimina el correo del servidor tras la descarga. No permite sincronizar fácilmente la bandeja de entrada entre múltiples dispositivos.

### 2. IMAP (Internet Message Access Protocol)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puertos:** 
  - **No Cifrado:** `TCP 143`
  - **Cifrado (TLS):** `TCP 993`
- **Funcionamiento:** Sincroniza el correo entre el cliente y el servidor. Descarga las cabeceras y el contenido mientras mantiene una copia en el servidor.
- **Ventaja:** Permite previsualizar correos antes de descargarlos por completo y mantener la bandeja de entrada perfectamente sincronizada en múltiples dispositivos (celular, laptop, web).

### 3. SMTP (Simple Mail Transfer Protocol)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puertos:** 
  - **No Cifrado:** `TCP/UDP 25` (frecuentemente usado/bloqueado por spam).
  - **Cifrado (SMTPS / TLS):** `TCP/UDP 587`
- **Funcionamiento:** Protocolo para el envío y enrutamiento del correo electrónico saliente desde el cliente hacia el servidor de correo o entre servidores de correo (mediante *Mail Transfer Agents* - MTA).
- **Seguridad y Spam:** SMTP regula y limita el número de mensajes enviados simultáneamente por una fuente para prevenir el envío masivo de spam.

## Relevancia para la Ciberseguridad y Filtrado de Puertos

1. **Configuración de Firewalls:** Los firewalls aplican reglas basadas en números de puerto e IP para bloquear tráfico no deseado.
   - *Ejemplo:* Bloquear los puertos de correo inseguros (`TCP 110`, `143`, `25`) y restringir la comunicación a sus versiones cifradas (`TCP 995`, `993`, `587`).
2. **Reemplazo de Protocolos Inseguros:** Prohibir el uso de Telnet (`TCP 23`) en favor de SSH (`TCP 22`) para evitar ataques de captura de credenciales *(eavesdropping)*.
3. **Monitoreo de Ataques ARP:** Detectar ataques de **ARP Spoofing / ARP Poisoning**, donde un atacante intercepta o desvía el tráfico introduciendo falsas entradas `MAC-IP` en la caché ARP de los dispositivos.
4. **Preparación Técnica:** La memorización de protocolos y puertos comunes es fundamental tanto en entrevistas técnicas como en el análisis diario en un centro de operaciones de seguridad (SOC).

---

## Puntos Clave

1. **NAT:** Traduce direcciones IP privadas no enrutables a una única IP pública para permitir el acceso a Internet.
2. **DHCP vs. ARP:** DHCP asigna direcciones IP a dispositivos en la Capa 7/Aplicación; ARP resuelve direcciones IP a direcciones MAC físicas en la Capa 2.
3. **Seguridad en Acceso Remoto:** SSH reemplaza a Telnet al ofrecer cifrado de punto a punto.
4. **Protocolos de Email:** POP3 descarga y borra del servidor; IMAP sincroniza en múltiples dispositivos; SMTP envía y enruta mensajes.
