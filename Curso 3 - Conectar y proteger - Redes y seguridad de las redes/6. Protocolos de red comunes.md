# Protocolos de Red Comunes

En esta lectura se profundiza en los **protocolos de red**, examinando cómo organizan y estructuran la comunicación a través de las redes informáticas, sus distintas categorías (comunicación, gestión y seguridad) y sus implicaciones directas en la ciberseguridad.

---

## Visión General de los Protocolos de Red

Un **protocolo de red** es un conjunto estandarizado de reglas utilizadas por dos o más dispositivos para definir la estructura, el formato y el orden de entrega de los datos en una transmisión.

### Características Clave:
- **Instrucciones adjuntas:** Funcionan como un conjunto de instrucciones que acompañan a cada paquete de datos, indicándole al dispositivo receptor qué hacer con la información recibida.
- **Lenguaje común:** Permiten que hardware y software de diversos fabricantes y ubicaciones geográficas puedan comunicarse e interoperar sin problemas.
- **Implicaciones de Seguridad:** Aunque son esenciales para la conectividad, muchos protocolos poseen vulnerabilidades inherentes o pueden ser manipulados por actores maliciosos. 
  - *Ejemplo de amenaza:* Un atacante puede explotar el protocolo **DNS** mediante técnicas como el envenenamiento de caché *(DNS Cache Poisoning)* o la suplantación *(DNS Spoofing)* para desviar tráfico legítimo hacia sitios web maliciosos que contienen malware.

## 1. Protocolos de Comunicación

Rigen el intercambio de información y la transmisión de datos entre dispositivos. Establecen la sincronización, el formato del mensaje y los mecanismos de recuperación en caso de pérdida de paquetes.

### A. TCP (Transmission Control Protocol / Protocolo de Control de Transmisión)
- **Capa TCP/IP:** Capa de Transporte.
- **Tipo:** Orientado a conexión *(Connection-oriented)*.
- **Funcionamiento:** Requiere establecer una conexión formal antes de transmitir datos mediante el **Apretón de Manos de Tres Vías (*Three-Way Handshake*)**:
  1. **SYN:** El dispositivo cliente envía una solicitud de sincronización al servidor.
  2. **SYN/ACK:** El servidor responde con un paquete de sincronización y acuse de recibo.
  3. **ACK:** El cliente envía el acuse de recibo final para confirmar y establecer la conexión TCP.
- **Uso:** Transmisiones donde la integridad y entrega de los datos son críticas (ej. transferencia de archivos, correos, páginas web).

### B. UDP (User Datagram Protocol / Protocolo de Datagramas de Usuario)
- **Capa TCP/IP:** Capa de Transporte.
- **Tipo:** No orientado a conexión *(Connectionless)*.
- **Funcionamiento:** Transmite datos directamente sin establecer una conexión previa ni confirmar la recepción de paquetes.
- **Características:** Menos fiable que TCP (no retransmite datos perdidos), pero ofrece **alta velocidad y baja latencia**.
- **Uso:** Streaming de video/audio, juegos en línea y consultas rápidas como solicitudes DNS.

### C. HTTP (Hypertext Transfer Protocol / Protocolo de Transferencia de Hipertexto)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puerto:** **80** (TCP).
- **Funcionamiento:** Protocolo cliente-servidor que gobierna la transferencia de datos e hipertexto en la World Wide Web.
- **Seguridad:** **Inseguro**. Trasmite los datos en texto plano *(cleartext)*, lo que permite que sean interceptados y leídos por terceros. Está siendo reemplazado activamente por HTTPS.

### D. DNS (Domain Name System / Sistema de Nombres de Dominio)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puerto:** **53** (UDP / TCP).
- **Funcionamiento:** Traduce nombres de dominio legibles para los humanos (ej. `example.com`) en direcciones IP numéricas que las computadoras utilizan para enrutar el tráfico.
- **Detalle de transporte:** 
  - Utiliza habitualmente **UDP** en el puerto 53 para consultas rápidas.
  - Cambia a **TCP** si el tamaño de la respuesta excede el límite estándar o para transferencias de zona entre servidores DNS.

## 2. Protocolos de Gestión

Diseñados para supervisar, administrar, diagnosticar y optimizar el funcionamiento de la infraestructura de red.

### A. SNMP (Simple Network Management Protocol / Protocolo Simple de Administración de Red)
- **Capa TCP/IP:** Capa de Aplicación.
- **Funcionamiento:** Permite a los administradores monitorear la salud de la red, recopilar métricas de dispositivos (routers, switches, servidores) y realizar cambios de configuración centralizados.
- **Capacidades:**
  - Consultar el uso de ancho de banda en tiempo real.
  - Restablecer contraseñas o modificar configuraciones base en dispositivos de red.
  - Recibir alertas (traps) ante fallos de hardware o sobrecargas.

### B. ICMP (Internet Control Message Protocol / Protocolo de Mensajes de Control de Internet)
- **Capa TCP/IP:** Capa de Internet.
- **Funcionamiento:** Utilizado por los dispositivos de red para enviar mensajes de diagnóstico e informar errores en la entrega de paquetes (por ejemplo, destino inalcanzable o tiempo de vida expirado).
- **Uso común:** Es la base de utilidades de diagnóstico de conectividad y latencia como el comando `ping` y `traceroute`.

## 3. Protocolos de Seguridad

Aplican mecanismos de cifrado y autenticación para garantizar la confidencialidad, integridad y autenticidad de los datos durante su tránsito por la red.

### A. HTTPS (Hypertext Transfer Protocol Secure / Protocolo Seguro de Transferencia de Hipertexto)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puerto:** **443** (TCP).
- **Funcionamiento:** Versión segura de HTTP que cifra la comunicación utilizando protocolos **SSL/TLS** *(Secure Sockets Layer / Transport Layer Security)*.
- **Protección:** Evita la interceptación *(eavesdropping)* y la manipulación de datos sensibles (credenciales, información financiera) entre el navegador del usuario y el servidor web.

### B. SFTP (SSH File Transfer Protocol / Protocolo Seguro de Transferencia de Archivos)
- **Capa TCP/IP:** Capa de Aplicación.
- **Puerto:** **22** (TCP).
- **Funcionamiento:** Protocolo seguro para la transferencia y manipulación de archivos que opera sobre un canal **SSH** *(Secure Shell)*.
- **Cifrado:** Utiliza algoritmos de cifrado fuerte como **AES** *(Advanced Encryption Standard)* para proteger el canal de transmisión.
- **Uso común:** Muy utilizado en servicios de almacenamiento en la nube e infraestructura corporativa para subir y descargar archivos de forma segura.

> [!IMPORTANT]
> **Nota sobre la visibilidad de direcciones IP en tráfico cifrado:**
> Los protocolos de seguridad (como HTTPS y SFTP) cifran el **contenido del paquete (payload)**, pero **NO ocultan las direcciones IP de origen ni de destino** presentes en las cabeceras de la capa de red. Un analista de seguridad o un actor malicioso que capture el tráfico aún podrá ver hacia dónde se dirigen las conexiones y desde dónde provienen.

## Resumen Técnico de Protocolos

| Protocolo | Nombre Completo | Capa TCP/IP | Puerto Predeterminado | Tipo de Conexión | Función Principal |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **TCP** | Transmission Control Protocol | Transporte | Variable | Orientado a conexión | Transmisión fiable con protocolo de enlace de 3 vías |
| **UDP** | User Datagram Protocol | Transporte | Variable | Sin conexión | Transmisión rápida sin verificación de entrega |
| **HTTP** | Hypertext Transfer Protocol | Aplicación | 80 / TCP | Cliente-Servidor | Comunicación web en texto plano (inseguro) |
| **DNS** | Domain Name System | Aplicación | 53 / UDP (TCP) | Sin conexión / Conexión | Traducción de nombres de dominio a direcciones IP |
| **SNMP** | Simple Network Mgmt Protocol | Aplicación | 161/162 (UDP) | Sin conexión | Monitoreo y gestión de dispositivos de red |
| **ICMP** | Internet Control Message Protocol | Internet | N/A (Protocolo IP 1) | Sin conexión | Reporte de errores de red y diagnóstico (`ping`) |
| **HTTPS** | Hypertext Transfer Protocol Secure | Aplicación | 443 / TCP | Orientado a conexión | Navegación web segura cifrada con SSL/TLS |
| **SFTP** | SSH File Transfer Protocol | Aplicación | 22 / TCP | Orientado a conexión | Transferencia segura de archivos sobre SSH (AES) |

## Relevancia para la Ciberseguridad

Para un analista de ciberseguridad de nivel básico, el conocimiento de los protocolos de red es indispensable por las siguientes razones:

1. **Detección de Tráfico Anómalo:** Identificar puertos inusuales o tráfico sin cifrar (HTTP/SNMP v1-v2) en zonas donde debería existir cifrado.
2. **Mitigación de Vulnerabilidades:** Implementar alternativas seguras (migrar de HTTP a HTTPS, o de FTP a SFTP).
3. **Análisis de Incidentes:** Entender cómo se establecen las conexiones TCP (analizando banderas SYN/ACK en pcaps) o cómo ataques DDoS aprovechan inundaciones de paquetes (SYN flood, UDP amplification).
4. **Respuesta ante Suplantaciones:** Reconocer anomalías en consultas DNS e ICMP para prevenir o detectar ataques de desvío de tráfico o escaneo de red.

---

## Puntos Clave

1. **Definición de Protocolo:** Reglas que rigen el orden, formato y entrega de los datos en una red.
2. **Tres Categorías:** Comunicación (TCP, UDP, HTTP, DNS), Gestión (SNMP, ICMP) y Seguridad (HTTPS, SFTP).
3. **TCP vs. UDP:** TCP garantiza entrega mediante conexión previa (*3-way handshake*); UDP prioriza la velocidad sin establecer conexión.
4. **Cifrado Parcial de Tráfico:** HTTPS y SFTP protegen los datos internos, pero no enmascaran las IP de origen y destino en el encabezado.
