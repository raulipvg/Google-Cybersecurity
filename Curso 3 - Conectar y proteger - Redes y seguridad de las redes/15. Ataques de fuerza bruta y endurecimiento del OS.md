# Ataques de Fuerza Bruta y Endurecimiento del OS

En esta lectura se analizan los **ataques de fuerza bruta**, los métodos utilizados por los ciberdelincuentes para adivinar credenciales de acceso, el papel del **endurecimiento del sistema operativo (OS Hardening)**, las herramientas de evaluación en entornos aislados (**Máquinas Virtuales** y **Sandboxes**) y las principales medidas de mitigación y prevención en la infraestructura.

---

## Visión General

Las credenciales de acceso (nombres de usuario y contraseñas) constituyen uno de los controles de seguridad perimetral más comunes en la actualidad. Se emplean para proteger teléfonos personales, computadoras corporativas y aplicaciones restringidas. Sin embargo, su principal debilidad radica en la vulnerabilidad ante robos, filtraciones de datos y suposiciones por parte de actores maliciosos.

El **endurecimiento del sistema operativo** *(OS Hardening)* consiste en aplicar un conjunto de configuraciones, políticas de seguridad y parches en el sistema para reducir su superficie de ataque y prevenir que los intentos de fuerza bruta comprometan la red.

---

## Tipos de Ataques de Fuerza Bruta

Un **ataque de fuerza bruta** es un proceso sistemático de ensayo y error diseñado para adivinar credenciales privadas o claves de cifrado probando múltiples combinaciones hasta encontrar la correcta.

```
                         ┌─────────────────────────────────┐
                         │   ATAQUES DE FUERZA BRUTA       │
                         └────────────────┬────────────────┘
                                          │
         ┌────────────────────────────────┴────────────────────────────────┐
         │                                                                 │
         ▼                                                                 ▼
┌─────────────────────────────────┐                       ┌─────────────────────────────────┐
│     FUERZA BRUTA SIMPLE         │                       │     ATAQUES DE DICCIONARIO      │
├─────────────────────────────────┤                       ├─────────────────────────────────┤
│ • Prueba sistemática de todas   │                       │ • Uso de listas de contraseñas  │
│   las combinaciones de caracteres│                      │   comunes y credenciales robadas│
│ • Puede ser manual o automática.│                       │ • Basado en filtraciones previas│
│ • Lento sin herramientas avanzadas│                      │   (Data Breaches).              │
└─────────────────────────────────┘                       └─────────────────────────────────┘
```

### 1. Ataque de Fuerza Bruta Simple
- Los atacantes intentan adivinar las credenciales probando combinaciones arbitrarias de nombres de usuario y contraseñas de forma consecutiva.
- Realizar este proceso de forma manual es tedioso y poco eficiente, por lo que los atacantes utilizan herramientas automatizadas (*brute-force tools*) para acelerar los intentos por segundo.

### 2. Ataque de Diccionario
- Técnica que emplea una lista predefinida de palabras, contraseñas comunes (ej. `12456`, `password`) y credenciales comprometidas en violaciones de seguridad masivas previas.
- Es más rápido que probar combinaciones aleatorias de caracteres.

## Evaluación de Vulnerabilidades en Entornos Aislados

Antes de que ocurra un ataque, las organizaciones realizan pruebas en sus redes y aplicaciones utilizando entornos de pruebas (*testbeds*) para identificar fallas de seguridad y evaluar el comportamiento de software sospechoso.

```
                               ┌───────────────────┐
                               │ ENTORNOS DE PRUEBA│
                               └─────────┬─────────┘
                                         │
                  ┌──────────────────────┴──────────────────────┐
                  ▼                                             ▼
    ┌───────────────────────────┐                 ┌───────────────────────────┐
    │  MÁQUINAS VIRTUALES (VM)  │                 │    SANDBOXES (AISLADOS)   │
    ├───────────────────────────┤                 ├───────────────────────────┤
    │ • Emulación de hardware   │                 │ • Aislamiento completo    │
    │ • Snapshots y restauración│                 │ • Pruebas de malware y    │
    │ • Aislamiento del Host    │                 │   parches                 │
    │ • Riesgo de VM Escape     │                 │ • Riesgo de detección de  │
    └───────────────────────────┘                 │   Sandbox por malware     │
                                                  └───────────────────────────┘
```

### 1. Máquinas Virtuales (VMs)
- **Definición:** Instancias emuladas por software de una computadora física ejecutadas sobre un hipervisor.
- **Beneficios de Seguridad:**
  - **Aisle de Código Malicioso:** Permiten ejecutar archivos no confiables sin comprometer el sistema operativo anfitrión (*host*).
  - **Restauración Rápida (*Snapshots*):** Posibilidad de revertir el sistema a un estado limpio inmediatamente después de analizar una amenaza.
- **Riesgos:** Existe un riesgo residual de **fuga de virtualización (*VM Escape*)**, donde un programa malicioso logra romper los límites del hipervisor y acceder al sistema operativo base.

### 2. Espacios Aislados (Sandboxes)
- **Definición:** Entornos de ejecución restringidos y separados de la red de producción diseñados para analizar código no verificado.
- **Casos de Uso:** Probar parches de software, solucionar *bugs*, inspeccionar archivos adjuntos sospechosos y simular vectores de ataque.
- **Implementación:** Pueden ser equipos físicos independientes desconectados de la red o entornos virtuales basados en la nube.
- **Evasión de Malware:** Algunos creadores de malware diseñan su código con rutinas de detección de Sandboxes/VMs. Si el malware detecta que está dentro de una sandbox, suspende su carga útil maliciosa y se comporta como software inofensivo.

## Medidas de Prevención y Mitigación

Para evitar que los ataques de fuerza bruta tengan éxito, las organizaciones implementan múltiples capas de seguridad:

| Mecanismo de Seguridad | Descripción y Funcionamiento | Impacto en la Seguridad |
| :--- | :--- | :--- |
| **Salting & Hashing** | El **hashing** convierte datos en un valor unidireccional único (ej. SHA-256). El **salting** agrega una cadena aleatoria de caracteres a la contraseña antes del hash. | Invalida el uso de tablas arcoíris (*rainbow tables*) y dificulta el cracking de contraseñas de diccionario. |
| **MFA / 2FA** | Exige 2 o más factores de autenticación (contraseña + OTP/SMS + biometría). | Invalida los ataques de fuerza bruta directos; obtener la contraseña no basta para acceder. |
| **CAPTCHA / reCAPTCHA** | Prueba de Turing automatizada para distinguir humanos de scripts/bots. | Detiene las herramientas automáticas de fuerza bruta y ataques de relleno de credenciales (*Credential Stuffing*). |
| **Políticas de Contraseñas** | Reglas de longitud, complejidad, expiración y límite de intentos fallidos (*Account Lockout*). | Bloquea temporalmente las cuentas tras múltiples intentos fallidos, frenando ataques de fuerza bruta. |

> [!IMPORTANT]
> **Bloqueo de Cuentas (Account Lockout):** Establecer un límite estricto de intentos fallidos de inicio de sesión (ej. máximo 3 a 5 intentos antes de bloquear la cuenta) es una de las medidas más efectivas para neutralizar ataques de fuerza bruta automatizados.

---

## Puntos Clave

1. **Ataques de Fuerza Bruta:** Método de ensayo y error para adivinar credenciales, realizado de forma simple (combinaciones arbitrarias) o mediante listas (ataques de diccionario).
2. **Entornos de Prueba:** Las Máquinas Virtuales (VMs) y Sandboxes permiten evaluar archivos maliciosos y simular ataques de forma aislada a la red de producción.
3. **Protección Criptográfica:** El uso de *salting* junto con *hashing* protege las bases de datos de contraseñas frente a ataques de fuerza bruta sobre hashes robados.
4. **Defensas Perimetrales:** La implementación de MFA/2FA, CAPTCHA y políticas de bloqueo de cuenta inutilizan la mayoría de los ataques automáticos de fuerza bruta.
