# Más Información sobre la Captura de Paquetes

En esta lectura del **Curso 6: Haga sonar la alarma: Detección y respuesta**, se profundiza en los tres pilares del análisis de tráfico en redes informáticas: la estructura anatómica de los **paquetes de datos**, el funcionamiento de los **analizadores de protocolos de red** (rastreadores de paquetes o *packet sniffers*) y los formatos y librerías utilizados en las **capturas de paquetes (PCAP)**.

---

## 1. La Detección a Nivel de Paquetes

La detección de intrusiones comienza a nivel de red, donde los datos se transmiten subdivididos en unidades discretas denominadas **paquetes de datos**.

* Cada vez que un usuario interactúa con un recurso en red (como cargar una página web, enviar un archivo o reproducir un video), los datos de la aplicación se fragmentan en múltiples paquetes que viajan individualmente hasta el host de destino, donde se reensamblan.
* Para un analista de seguridad, los paquetes proporcionan el contexto forense indispensable: permiten reconstruir sesiones de ataque, identificar anomalías en protocolos y determinar la presencia de malware o exfiltración de información.

---

## 2. Anatomía de un Paquete de Datos

Un paquete de datos completo se organiza jerárquicamente en tres componentes estructurales:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                      ESTRUCTURA DE UN PAQUETE DE DATOS                   │
├─────────────────────┬────────────────────────────────┬───────────────────┤
│      CABECERA       │          CARGA ÚTIL            │   PIE DE PÁGINA   │
│      (Header)       │           (Payload)            │ (Footer / Trailer)│
├─────────────────────┼────────────────────────────────┼───────────────────┤
│ Metadatos de        │ Los datos reales que se        │ Información de    │
│ enrutamiento,       │ transportan (texto, imágenes,  │ verificación de   │
│ direcciones IP,     │ peticiones web, archivos).     │ integridad y      │
│ puertos y control.  │                                │ control de errores│
└─────────────────────┴────────────────────────────────┴───────────────────┘
```

### 1. Cabecera (*Header*)
Es el componente inicial y más crítico para el transporte. Según el protocolo de cada capa del modelo OSI/TCP-IP, un paquete puede acumular varias cabeceras anidadas (por ejemplo: cabecera Ethernet, cabecera IP y cabecera TCP/UDP).

Una cabecera contiene información vital de control:
* Direcciones de origen y destino (direcciones MAC en capa de enlace, direcciones IP en capa de red).
* Longitud total del paquete y longitud de la cabecera.
* Protocolo de la capa superior transportado (TCP, UDP, ICMP).
* Banderas de control (*flags*), números de secuencia y acuse de recibo.
* Tiempo de vida del paquete (TTL) para evitar bucles de enrutamiento infinitos.

```
                  ESTRUCTURA TÍPICA DE UNA CABECERA IPv4
┌────────────────────────────────────────────────────────────────────────┐
│ Versión │ Longitud │ Tipo de Servicio │          Longitud Total        │
├─────────┴──────────┴──────────────────┼────────────────────────────────┤
│       Identificador de Fragmento      │ Banderas │ Desplazamiento      │
├───────────────────────┬───────────────┴──────────┴─────────────────────┤
│ Tiempo de Vida (TTL)  │ Protocolo (TCP/UDP) │ Checksum de Cabecera     │
├───────────────────────┴─────────────────────┴──────────────────────────┤
│                       Dirección IP de Origen                           │
├────────────────────────────────────────────────────────────────────────┤
│                       Dirección IP de Destino                          │
└────────────────────────────────────────────────────────────────────────┘
```

### 2. Carga Útil (*Payload*)
Sigue inmediatamente a las cabeceras y contiene los datos reales transferidos entre el emisor y el receptor. Si un usuario sube una imagen a un servidor, la carga útil del paquete estará conformada por los fragmentos de bytes de dicha imagen.

### 3. Pie de Página (*Footer* o *Trailer*)
Se ubica al final de la trama. El protocolo Ethernet utiliza el pie de página para incorporar una secuencia de verificación de trama (FCS / CRC), la cual permite comprobar si los datos sufrieron corrupción durante la transmisión física por el cable o medio inalámbrico.
> **Nota:** La gran mayoría de los protocolos de capas superiores, como el Protocolo de Internet (IP), no emplean pie de página; delegan la comprobación de errores en el checksum de la cabecera.

## 3. Analizadores de Protocolos de Red (*Packet Sniffers*)

Un **analizador de protocolos de red** es un software o dispositivo diseñado para interceptar, decodificar y analizar el tráfico que circula a través de un medio de transmisión.

```
[ Host Emisor ] ══════════════════════════════════════════► [ Host Receptor ]
                                 ║
                                 ▼
                 ┌───────────────────────────────┐
                 │ Analizador de Protocolos      │
                 │ (tcpdump / Wireshark / TShark)│
                 │ Intercepta y decodifica       │
                 └───────────────────────────────┘
```

### Casos de Uso
1. **Defensa e Investigación de Ciberseguridad:** Monitorear comunicaciones en busca de patrones hostiles, malware, escaneos de puertos y credenciales en texto plano.
2. **Diagnóstico y Rendimiento:** Medir el ancho de banda consumido, tasas de retransmisión, latencia y diagnosticar cuellos de botella o fallos de conectividad.
3. **Uso Malicioso:** Los atacantes pueden emplear rastreadores para realizar escuchas clandestinas (*eavesdropping*) y sustraer contraseñas no cifradas, tokens de autenticación y secretos corporativos.

## 4. Principio de Funcionamiento de los Analizadores

Para capturar y presentar la información de red en un formato comprensible, los analizadores operan mediante una secuencia coordinada de hardware y software:

```
┌───────────────────────────┐
│     Tráfico de Red        │
└─────────────┬─────────────┘
              │
              ▼
┌───────────────────────────┐
│ Tarjeta de Red (NIC)      │  Modo Promiscuo (Cableado)
│ en Modo Especial          │  Modo Monitor (Inalámbrico / Wi-Fi)
└─────────────┬─────────────┘
              │ Flujo de 0s y 1s (Binario)
              ▼
┌───────────────────────────┐
│ Motor del Analizador      │  Decodificación y análisis sintáctico
└─────────────┬─────────────┘
              │
              ▼
┌───────────────────────────┐
│ Interfaz Legible          │  Presentación estructurada por capas
│ (Analista de Seguridad)   │  (Campos, protocolos, marcas de tiempo)
└───────────────────────────┘
```

### 1. El Rol de la Tarjeta de Red (NIC) y el Modo Promiscuo
* Por defecto, una tarjeta de red (NIC) solo procesa los paquetes cuyas direcciones MAC de destino coinciden con su propia dirección física o con direcciones de difusión (*broadcast*), descartando todo lo demás.
* Para capturar todas las comunicaciones visibles en el medio, la NIC debe configurarse en **modo promiscuo** (en redes Ethernet por cable) o en **modo monitor** (en interfaces inalámbricas Wi-Fi).
* **Ubicación en la red:** Cambiar la tarjeta a modo promiscuo no basta si la red utiliza conmutadores (*switches*) modernos, ya que estos aíslan el tráfico por puerto. Para acceder a las comunicaciones entre otros hosts, el analizador debe conectarse a un **puerto espejo (*port mirroring* / SPAN)** o a un dispositivo TAP de red.

### 2. Conversión de Binario a Formato Legible
Los paquetes viajan como secuencias de bits (ceros y unos). El analizador interpreta estas cadenas conforme a las especificaciones RFC de cada protocolo, organizando la información en paneles legibles con campos diferenciados (marcas de tiempo, IPs, puertos, banderas y datos).

> **Consideraciones de Seguridad y Legalidad:**
> * Activar el modo promiscuo permite interceptar datos sensibles que circulen por el segmento de red.
> * Interceptar y registrar comunicaciones de red privadas sin autorización explícita es un delito tipificado por las leyes de ciberseguridad en la mayoría de las jurisdicciones internacionales. Debe realizarse únicamente dentro del marco de auditorías autorizadas o en entornos de prueba propios.

## 5. Capturas de Paquetes (PCAP) y Bibliotecas Principales

Una **captura de paquetes (*PCAP*)** es un archivo informático que almacena los paquetes de datos interceptados en una interfaz de red, preservando sus cabeceras, marcas de tiempo y cargas útiles para su posterior filtrado, reconstrucción y análisis forense.

Existen diferentes bibliotecas y formatos de archivo según el sistema operativo y la herramienta empleada:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   BIBLIOTECAS Y FORMATOS DE CAPTURA                      │
├─────────────────────┬────────────────────────────────────────────────────┤
│ Formato / Librería  │ Características Principales                        │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Libpcap             │ Biblioteca estándar para sistemas tipo Unix        │
│                     │ (Linux y macOS). Es el formato predeterminado      │
│                     │ utilizado por herramientas como tcpdump.           │
├─────────────────────┼────────────────────────────────────────────────────┤
│ WinPcap             │ Adaptación histórica de código abierto de Libpcap   │
│                     │ para sistemas Windows. Actualmente obsoleta.       │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Npcap               │ Biblioteca moderna para Windows desarrollada por   │
│                     │ el proyecto Nmap. Ofrece soporte para Windows 10/11│
│                     │ con mejoras de velocidad, seguridad y captura Wi-Fi│
├─────────────────────┼────────────────────────────────────────────────────┤
│ PCAPng              │ Formato de archivo de "Próxima Generación"         │
│ (Next Generation)   │ (Next Generation). Permite capturar simultáneamente│
│                     │ de múltiples interfaces, agregar comentarios a     │
│                     │ paquetes y almacenar metadatos de resolución DNS.  │
└─────────────────────┴────────────────────────────────────────────────────┘
```

## 6. Herramientas Destacadas de Captura y Análisis

* **tcpdump:** Herramienta de línea de comandos ligera y potente, ampliamente utilizada en servidores Linux para capturas rápidas y automatización de scripts.
* **Wireshark:** El analizador gráfico de protocolos de referencia en la industria. Permite aplicar filtros de visualización avanzados, reconstruir secuencias de streams TCP y examinar cargas útiles en detalle.
* **TShark:** Versión de terminal de Wireshark, ideal para procesar y filtrar grandes volúmenes de archivos de captura sin requerir entorno gráfico.

---

## 7. Puntos Clave

* Los **paquetes de datos** son la unidad atómica de transporte en la red y se estructuran en **cabecera**, **carga útil** y **pie de página**.
* Para capturar el tráfico circundante, las tarjetas de red deben configurarse en **modo promiscuo** (cableado) o **modo monitor** (inalámbrico).
* Las capturas se guardan en formatos estandarizados (**PCAP** y **PCAPng**) gestionados por bibliotecas como **Libpcap** (Linux/macOS) y **Npcap** (Windows).
* El análisis de tráfico es una habilidad técnica central tanto para detectar intrusiones en tiempo real como para investigar incidentes pasados.
