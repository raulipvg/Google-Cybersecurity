# Visión General de tcpdump

En esta lectura del **Curso 6: Haga sonar la alarma: Detección y respuesta**, se analiza en profundidad **tcpdump**, la herramienta de línea de comandos estándar de la industria para la captura, inspección y filtrado de paquetes de red en sistemas tipo Unix/Linux. Se detalla su sintaxis, sus opciones esenciales, el uso de expresiones de filtrado y la interpretación de su salida en terminal.

---

## 1. ¿Qué es tcpdump?

**tcpdump** es un analizador de protocolos de red (*packet sniffer*) que opera mediante una **interfaz de línea de comandos (CLI)**. A diferencia de analizadores gráficos como Wireshark, tcpdump está optimizado para entornos de servidor sin interfaz gráfica, scripts de automatización e investigaciones rápidas en terminal.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                         CARACTERÍSTICAS DE TCPDUMP                       │
├─────────────────────┬────────────────────────────────────────────────────┤
│ Plataforma          │ Nativo en la mayoría de distribuciones Linux y     │
│                     │ disponible en sistemas basados en Unix (macOS).    │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Formato de Captura  │ Genera y lee archivos estándar PCAP mediante la    │
│                     │ biblioteca Libpcap.                                │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Propósito Defensivo │ Diagnóstico de problemas de red, detección de      │
│                     │ intrusiones, auditoría de puertos y análisis post. │
└─────────────────────┴────────────────────────────────────────────────────┘
```

> **Nota sobre el cifrado:** Gran parte del tráfico contemporáneo viaja cifrado (como TLS/HTTPS o SSH). tcpdump captura la totalidad del paquete; sin embargo, examinar la carga útil en texto claro puede requerir las claves privadas correspondientes para su posterior desencriptación.

## 2. Sintaxis Básica y Privilegios Requeridos

La captura de paquetes a nivel de interfaz de red requiere interactuar directamente con la tarjeta de red (NIC) en modo promiscuo, por lo que **exige privilegios de superusuario (`root`) o el uso de `sudo`**:

```bash
sudo tcpdump [-i interfaz] [opción(es)] [expresión(es)]
```

```
┌──────────────┬───────────────────────────────────────────────────────────┐
│ Componente   │ Función                                                   │
├──────────────┼───────────────────────────────────────────────────────────┤
│ sudo tcpdump │ Ejecuta el binario con privilegios administrativos.       │
│ -i interfaz  │ Especifica la tarjeta o interfaz de red a escuchar.       │
│ opción(es)   │ Banderas que modifican la captura, salida o formato.      │
│ expresión(es)│ Filtros de paquetes basados en BPF (Berkeley Packet Filter│
└──────────────┴───────────────────────────────────────────────────────────┘
```

### Listar Interfaces de Red Disponibles (`-D`)
Antes de iniciar la captura, es indispensable conocer qué interfaces posee el sistema:

```bash
sudo tcpdump -D
```
*Salida típica:*
```text
1.eth0 [Up, Running]
2.wlan0 [Up, Running]
3.any (Pseudo-device that captures on all interfaces) [Up, Running]
4.lo [Up, Running, Loopback]
```
> El uso de `-i any` captura simultáneamente el tráfico de todas las interfaces activas del equipo.

## 3. Opciones y Banderas Esenciales

Las opciones de tcpdump pueden utilizarse en formato corto (`-i`) o largo (`--interface`), y **distinguen estrictamente entre mayúsculas y minúsculas** (por ejemplo, `-w` no realiza la misma función que `-W`).

```
                              BANDERAS ESENCIALES
┌───────────┬──────────────────────────────────────────────────────────────┐
│ Bandera   │ Descripción y Caso de Uso                                    │
├───────────┼──────────────────────────────────────────────────────────────┤
│ -w        │ Escribe (guarda) los paquetes capturados en un archivo PCAP. │
│ -r        │ Lee e interpreta paquetes desde un archivo PCAP guardado.    │
│ -c        │ Limita la captura a un número exacto (recuento) de paquetes. │
│ -v / -vv  │ Incrementa el nivel de detalle y verbosidad en la salida.    │
│ -n / -nn  │ Desactiva la resolución de nombres DNS y números de puerto.  │
└───────────┴──────────────────────────────────────────────────────────────┘
```

### 1. Guardar Capturas en Archivo (`-w`)
En lugar de saturar la consola imprimiendo miles de líneas por segundo, se recomienda guardar el tráfico para inspeccionarlo posteriormente:

```bash
sudo tcpdump -i any -w captura_red.pcap
```

### 2. Leer Archivos de Captura Existentes (`-r`)
Permite procesar archivos PCAP previamente generados (tanto por tcpdump como por Wireshark):

```bash
sudo tcpdump -r captura_red.pcap
```

### 3. Limitar el Recuento de Paquetes (`-c`)
Detiene la ejecución automáticamente una vez alcanzado el número de paquetes indicado:

```bash
sudo tcpdump -i any -c 5
```

### 4. Niveles de Verbosidad (`-v`, `-vv`, `-vvv`)
Proporciona información progresivamente más detallada de cada paquete (campos de cabecera IP, TTL, ID de fragmentación, opciones y marcas de verificación):

```bash
sudo tcpdump -r captura_red.pcap -v
```

### 5. Desactivar Resolución de Nombres (`-n` y `-nn`)
Por defecto, tcpdump intenta resolver las direcciones IP a nombres de dominio (mediante consultas DNS inversas) y los números de puerto a nombres de servicios conocidos (por ejemplo, traduce el puerto 80 a `http`).

**Esto presenta dos problemas críticos en ciberseguridad:**
1. **Riesgo Operativo:** Realizar una consulta DNS inversa contra la dirección IP de un atacante puede alertarlo en sus propios servidores DNS de que está siendo investigado.
2. **Ambigüedad Técnica:** Un atacante puede utilizar el puerto 80 para un canal de malware que nada tiene que ver con HTTP.

```
┌───────────┬──────────────────────────────────────────────────────────────┐
│ Bandera   │ Comportamiento de Resolución                                 │
├───────────┼──────────────────────────────────────────────────────────────┤
│ -n        │ No resuelve direcciones IP a nombres de host.                │
│ -nn       │ No resuelve ni direcciones IP ni números de puerto.          │
└───────────┴──────────────────────────────────────────────────────────────┘
```

*Comando recomendado para análisis limpio y seguro:*
```bash
sudo tcpdump -r captura_red.pcap -nn -v
```

> **Combinación de banderas:** Las opciones que no requieren argumentos posteriores pueden agruparse (por ejemplo, `-vn` o `-vnc 5`).

## 4. Expresiones de Filtrado (Filtros BPF)

Las expresiones de filtrado permiten aislar con precisión matemática los paquetes relevantes para una investigación, reduciendo el ruido.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   OPERADORES Y TIPOS DE FILTROS BPF                      │
├─────────────────────┬────────────────────────────────────────────────────┤
│ Por Protocolo       │ tcp, udp, icmp, ip, ip6, arp                       │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Por Dirección       │ host 192.168.1.10, src host 10.0.0.5, dst host ... │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Por Puerto          │ port 80, src port 443, dst port 53, portrange ...  │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Lógica Booleana     │ and (&&), or (||), not (!)                         │
└─────────────────────┴────────────────────────────────────────────────────┘
```

### Ejemplos Prácticos de Filtrado

* **Filtrar únicamente tráfico web (puerto 80 o 443):**
  ```bash
  sudo tcpdump -i any -nn 'port 80 or port 443'
  ```

* **Filtrar tráfico dirigido a un servidor DNS específico:**
  ```bash
  sudo tcpdump -i any -nn 'udp and dst host 8.8.8.8 and port 53'
  ```

* **Excluir tráfico SSH propio para evitar bucles de salida en terminal:**
  ```bash
  sudo tcpdump -i eth0 -nn 'not port 22'
  ```

* **Uso de paréntesis para agrupaciones lógicas complejas:**
  ```bash
  sudo tcpdump -i any -nn 'ip and (port 80 or port 443) and host 192.168.1.50'
  ```
  *(Se recomienda el uso de comillas simples para evitar que la shell interprete los paréntesis como comandos de bash).*

## 5. Interpretación de la Salida de tcpdump

Al capturar o leer paquetes, tcpdump genera una línea estructurada por cada paquete recibido. A continuación se desglosa la anatomía de una línea típica correspondiente a una conexión TCP:

```text
11:45:30.125840 IP 192.168.1.45.54230 > 93.184.216.34.443: Flags [S], seq 3541829104, win 64240, options [mss 1460,sackOK], length 0
```

```
┌───────────────────┬──────────────────────────────────────────────────────┐
│ Sección           │ Significado Técnico                                  │
├───────────────────┼──────────────────────────────────────────────────────┤
│ 11:45:30.125840   │ Marca de tiempo: horas, minutos, segundos y          │
│                   │ fracciones de microsegundo.                          │
├───────────────────┼──────────────────────────────────────────────────────┤
│ IP                │ Protocolo de capa de red (IPv4).                     │
├───────────────────┼──────────────────────────────────────────────────────┤
│ 192.168.1.45      │ Dirección IP de origen del paquete.                  │
├───────────────────┼──────────────────────────────────────────────────────┤
│ .54230            │ Puerto de origen efímero del cliente.                │
├───────────────────┼──────────────────────────────────────────────────────┤
│ >                 │ Dirección del flujo (indica envío hacia el destino). │
├───────────────────┼──────────────────────────────────────────────────────┤
│ 93.184.216.34     │ Dirección IP de destino (servidor receptor).         │
├───────────────────┼──────────────────────────────────────────────────────┤
│ .443              │ Puerto de destino (en este caso, servicio HTTPS).    │
├───────────────────┼──────────────────────────────────────────────────────┤
│ Flags [S]         │ Banderas de control TCP: [S] indica sincronización   │
│                   │ (SYN), inicio del protocolo de enlace de 3 vías.     │
├───────────────────┼──────────────────────────────────────────────────────┤
│ seq 3541829104    │ Número de secuencia inicial del flujo TCP.           │
├───────────────────┼──────────────────────────────────────────────────────┤
│ win 64240         │ Tamaño de la ventana TCP del receptor (buffer).      │
├───────────────────┼──────────────────────────────────────────────────────┤
│ length 0          │ Longitud de la carga útil transportada (0 en un SYN).│
└───────────────────┴──────────────────────────────────────────────────────┘
```

### Banderas TCP Habituales en tcpdump
* `[S]` — **SYN:** Solicitud de inicio de conexión.
* `[S.]` — **SYN-ACK:** Respuesta y confirmación de inicio.
* `[.]` — **ACK:** Confirmación sin datos.
* `[P.]` — **PUSH:** Envío de datos hacia la aplicación inmediatamente.
* `[F.]` — **FIN:** Cierre ordenado de la conexión.
* `[R]` — **RST:** Reseteo o terminación forzada e inmediata de la conexión.

## 6. Puntos Clave

* **tcpdump** es la herramienta de terminal de referencia para monitorear tráfico en tiempo real y generar capturas PCAP en entornos Unix/Linux.
* Su uso requiere privilegios de **administrador (`sudo`)**.
* Emplear las banderas **`-n` o `-nn`** es una regla de oro en ciberseguridad para evitar fugas de información por consultas DNS inversas y para analizar los puertos reales sin suposiciones de servicio.
* La combinación de **banderas operativas** (`-w`, `-r`, `-c`, `-v`) con **expresiones de filtrado BPF** permite a los analistas de seguridad aislar vectores de intrusión de manera ágil y precisa.
