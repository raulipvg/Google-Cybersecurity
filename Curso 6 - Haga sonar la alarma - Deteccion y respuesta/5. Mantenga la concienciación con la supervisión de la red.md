# Mantenga la Concienciación con la Supervisión de la Red

En esta lectura del **Curso 6: Haga sonar la alarma: Detección y respuesta**, se aborda la importancia del **monitoreo de redes** para mantener la conciencia situacional de la seguridad, el establecimiento de **líneas de base** de comportamiento normal, los componentes esenciales a supervisar (análisis de flujo, carga útil y patrones temporales), las diferencias entre un **SOC** y un **NOC**, y las herramientas de análisis de paquetes.

---

## 1. El Tráfico de Red y la Conciencia Situacional

En cualquier entorno empresarial, la comunicación a través de la red es constante y voluminosa: transmisiones de video, envío de correos electrónicos, consultas a bases de datos y navegación web generan un flujo ininterrumpido de paquetes.

Para gestionar este entorno, es indispensable distinguir dos conceptos fundamentales:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   CONCEPTOS BÁSICOS DE RED Y MONITOREO                   │
├─────────────────────┬────────────────────────────────────────────────────┤
│ Tráfico de Red      │ Cantidad y tasa de transferencia de datos que se   │
│                     │ desplazan a través de la red, incluyendo los       │
│                     │ protocolos utilizados (por ejemplo, HTTP o HTTPS). │
├─────────────────────┼────────────────────────────────────────────────────┤
│ Datos de Red        │ La información específica que se transmite entre   │
│                     │ los dispositivos conectados a una infraestructura. │
└─────────────────────┴────────────────────────────────────────────────────┘
```

El **monitoreo de red** es esencial para conservar el **conocimiento de la situación** (conciencia situacional) respecto a cualquier actividad interna o externa. Al capturar y analizar el tráfico, los equipos de seguridad pueden identificar anomalías e intrusiones antes de que se conviertan en incidentes mayores.

---

## 2. Conozca su Red: La Importancia de la Línea de Base

Las comunicaciones de red revelan metadatos clave sobre cada conexión:
* Direcciones IP de origen y destino.
* Puertos y protocolos empleados.
* Volumen de bytes transmitidos.
* Marcas de fecha, hora y duración de las sesiones.

Con estos datos, los analistas de seguridad construyen una **línea de base**.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                       ¿QUÉ ES UNA LÍNEA DE BASE?                         │
├──────────────────────────────────────────────────────────────────────────┤
│ Una línea de base es un punto de referencia técnico que define el        │
│ comportamiento esperado y habitual de los sistemas, usuarios y redes.   │
│                                                                          │
│ Principio rector:                                                        │
│ "Solo conociendo el comportamiento normal de la red es posible detectar  │
│ con precisión comportamientos anómalos o sospechosos."                   │
└──────────────────────────────────────────────────────────────────────────┘
```

## 3. Componentes Críticos para Monitorear la Red

Una vez establecida la línea de base, se monitorean los componentes de red para identificar cualquier desviación sospechosa. Destacan tres áreas de análisis:

```
                      ┌─────────────────────────────────┐
                      │    ÁREAS DE ANÁLISIS DE RED     │
                      └────────────────┬────────────────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
┌──────────────────┐          ┌──────────────────┐          ┌──────────────────┐
│ ANÁLISIS DE      │          │ CARGA ÚTIL DE    │          │ PATRONES         │
│ FLUJO            │          │ LOS PAQUETES     │          │ TEMPORALES       │
├──────────────────┤          ├──────────────────┤          ├──────────────────┤
│ Puertos,         │          │ Inspección del   │          │ Horarios de      │
│ protocolos y     │          │ contenido real y │          │ tráfico habitual │
│ canales de C2    │          │ detección de     │          │ frente a picos   │
│ no autorizados.  │          │ exfiltración.    │          │ fuera de hora.   │
└──────────────────┘          └──────────────────┘          └──────────────────┘
```

### 1. Análisis de Flujo
El flujo describe el trayecto y la dinámica de las comunicaciones de red (paquetes, protocolos y puertos).
* **Asociaciones estándar:** Los protocolos reconocidos utilizan puertos predefinidos (por ejemplo, el protocolo HTTPS suele operar en el puerto 443 para cifrar el tráfico web).
* **Canales de Comando y Control (C2):** Los atacantes a menudo eluden las inspecciones convencionales utilizando puertos no asociados comúnmente a un protocolo para mantener comunicación encubierta con sistemas comprometidos (por ejemplo, transmitir tráfico HTTPS a través del puerto 8088 en lugar del 443).
* **Control de puertos:** Las organizaciones deben auditar permanentemente qué puertos están abiertos y autorizados, vigilando cualquier discrepancia entre el puerto y el protocolo que viaja por él.

### 2. Información sobre la Carga Útil del Paquete
La carga útil (*payload*) representa los datos reales que se transportan dentro de cada paquete, independientemente de las cabeceras de red.
* Dado que gran parte del tráfico moderno viaja cifrado, las organizaciones requieren mecanismos de inspección profunda y desencriptación autorizada para analizar el contenido.
* Monitorear la carga útil permite identificar la fuga no autorizada de información confidencial hacia servidores externos (**exfiltración de datos**).

### 3. Patrones Temporales
Los paquetes de red contienen marcas de tiempo que permiten reconocer hábitos de uso periódicos.
* **Ejemplo de línea de base temporal:** Una compañía con oficinas en horario diurno experimenta el 95% de su volumen de tráfico entre las 09:00 y las 17:00 horas.
* **Desviación anómala:** Si un servidor de base de datos genera transferencias masivas de datos a las 03:00 AM hacia una dirección IP externa desconocida, este evento se sale de la línea de base y debe investigarse inmediatamente como una potencial brecha o copia no autorizada.

## 4. Estructura Defensiva: SOC frente a NOC

Ambas unidades organizativas vigilan la infraestructura tecnológica de la empresa, pero persiguen metas operativas diferentes y complementarias:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                   CENTRO DE OPERACIONES: SOC vs. NOC                     │
├─────────────────────────────────────┬────────────────────────────────────┤
│ SOC (Security Operations Center)    │ NOC (Network Operations Center)    │
├─────────────────────────────────────┼────────────────────────────────────┤
│ • Enfoque: Seguridad y defensa.     │ • Enfoque: Rendimiento y servicio. │
│ • Monitorea amenazas, malware,      │ • Monitorea ancho de banda, caídas │
│   intrusiones y accesos indebidos.  │   de red, latencia y disponibilidad│
│ • Detecta Indicadores de Compromiso │ • Garantiza el tiempo de actividad │
│   (IoC) y coordina la respuesta.    │   (uptime) de routers y enlaces.   │
└─────────────────────────────────────┴────────────────────────────────────┘
```

Los analistas de seguridad del SOC se enfocan en identificar **Indicadores de Compromiso (IoC)**, que son evidencias forenses y artefactos digitales que revelan que un sistema o red ha sido vulnerado.

## 5. Herramientas para el Monitoreo de Red

El monitoreo de la red se apoya en soluciones automatizadas y en herramientas de análisis manual de paquetes:

| Tipo de Herramienta | Función Principal | Ejemplos / Casos de Uso |
| :--- | :--- | :--- |
| **Sistemas de Detección de Intrusiones (IDS)** | Inspección automatizada en tiempo real. Analiza el tráfico y la carga útil en busca de firmas de malware, escaneos o intentos de phishing, emitiendo alertas cuando se detectan desviaciones de las reglas configuradas. | *Snort, Suricata, Zeek.* |
| **Analizadores de Protocolos / Rastreadores de Paquetes (*Packet Sniffers*)** | Captura y examen minucioso del tráfico paquete por paquete. Permiten registrar sesiones de comunicación (*PCAP*) para realizar análisis forenses detallados y confirmar actividades maliciosas. | *Wireshark (interfaz gráfica), tcpdump (línea de comandos).* |

---

## 6. Puntos Clave

* **"No se puede proteger lo que no se conoce":** La base de la ciberseguridad defensiva radica en comprender a fondo la topología de la red, los dispositivos conectados y el flujo normal de datos.
* **Las líneas de base son indispensables:** Establecen el estándar de normalidad para discernir entre el ruido operativo y un incidente de seguridad genuino.
* El análisis integral combina la revisión de **flujos (puertos/protocolos)**, **cargas útiles (prevención de exfiltración)** y **patrones temporales (horarios anómalos)**.
* Mientras el **NOC** vela por la disponibilidad y conectividad, el **SOC** vigila la integridad y confidencialidad frente a ciberataques.
