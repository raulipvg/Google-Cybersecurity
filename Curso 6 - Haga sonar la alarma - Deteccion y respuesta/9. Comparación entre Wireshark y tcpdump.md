# Comparación entre Wireshark y tcpdump: Análisis Comparativo, Diagrama de Venn y Casos de Uso

En esta guía del **Curso 6: Haga sonar la alarma: Detección y respuesta**, se profundiza en las dos herramientas de análisis de paquetes más influyentes en la ciberseguridad defensiva: **tcpdump** y **Wireshark**. A través de un análisis visual y técnico, se examina su arquitectura compartida, sus diferencias operativas, sus motores de filtrado (BPF vs. Display Filters) y el flujo de trabajo conjunto recomendado para la detección e investigación de incidentes en el SOC.

---

## 1. Introducción: El Rol de la Captura de Paquetes en Detección y Respuesta

En las operaciones de un **Centro de Operaciones de Seguridad (SOC)** o de un **Equipo de Respuesta a Incidentes de Seguridad Informática (CSIRT)**, las alertas generadas por sistemas IDS/IPS o SIEM a menudo requieren una verificación a bajo nivel. 

La captura de paquetes (*packet sniffing*) y la inspección profunda de protocolos permiten al analista responder con certeza a preguntas críticas:
* ¿Se completó la conexión TCP con el servidor malicioso (SYN ➔ SYN-ACK ➔ ACK)?
* ¿Qué comando exacto o carga útil (*payload*) viajó dentro de la sesión?
* ¿Hubo exfiltración efectiva de datos o la conexión fue abortada con un paquete `RST`?

Para abordar estas investigaciones, **tcpdump** y **Wireshark** representan dos extremos complementarios de un mismo espectro analítico: la agilidad y ligereza en línea de comandos frente a la riqueza visual y granularidad forense.

## 3. tcpdump en Profundidad: La Herramienta Esencial del Servidor

**tcpdump** es un analizador de paquetes de red por línea de comandos, desarrollado originalmente en 1988 en el Lawrence Berkeley National Laboratory. Es la herramienta por excelencia para capturas inmediatas y silenciosas en sistemas operativos tipo Unix/Linux.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                      VENTAJAS OPERATIVAS DE TCPDUMP                          │
├──────────────────────────────────────────────────────────────────────────────┤
│ • Operación Remota: Funciona en servidores remotos sin entorno gráfico.      │
│ • Bajo Impacto: Mínima sobrecarga de CPU y memoria RAM.                      │
│ • Automatización: Se integra directamente en pipelines Bash y tareas cron.   │
│ • Captura Continua: Permite rotación de archivos mediante banderas (-C y -W).│
└──────────────────────────────────────────────────────────────────────────────┘
```

### Principales Casos de Uso de tcpdump
1. **Triaje Inmediato en Servidores de Producción:** Cuando se sospecha que un servidor web o de base de datos está bajo ataque, iniciar una captura ligera sin interferir con los servicios en producción.
2. **Monitoreo en Dispositivos Embebidos y Routers:** En firewalls perimetrales (ej. pfSense, OPNsense) o routers donde los recursos son limitados y no existe servidor X.
3. **Capturas Continuas con Rotación (*Ring Buffers*):** Supervisar interfaces críticas escribiendo archivos de tamaño fijo para evitar saturar el almacenamiento:
   ```bash
   sudo tcpdump -i eth0 -w captura_rotativa.pcap -C 50 -W 5
   ```
   *(Escribe un búfer circular de hasta 5 archivos de 50 MB cada uno).*

## 4. Wireshark en Profundidad: El Estándar de la Investigación Forense

**Wireshark** (conocido en sus inicios como Ethereal) es el analizador de protocolos de red con interfaz gráfica más utilizado a nivel mundial. Permite examinar el tráfico en tiempo real o a partir de capturas previas con un nivel microscópico de detalle.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                     VENTAJAS OPERATIVAS DE WIRESHARK                         │
├──────────────────────────────────────────────────────────────────────────────┤
│ • Disección Microscópica: Decodifica cientos de protocolos capa por capa.    │
│ • Visualización Intuitiva: Coloreado inteligente según protocolo y errores.  │
│ • Reconstrucción de Sesiones: Follow TCP Stream unifica peticiones y datos.  │
│ • Desencriptación y Forense: Descifra TLS e inspecciona objetos transmitidos.│
└──────────────────────────────────────────────────────────────────────────────┘
```

### Principales Casos de Uso de Wireshark
1. **Análisis Forense Profundo de Malware:** Inspeccionar la comunicación de comando y control (C2) de un binario sospechoso ejecutado en una sandbox, analizando consultas DNS y peticiones HTTP anómalas.
2. **Reconstrucción y Extracción de Archivos (*Object Carving*):** Si un atacante utilizó SMB o HTTP para transferir un script o un archivo ejecutable, Wireshark permite extraer el binario directamente del tráfico capturado (`File > Export Objects > HTTP / SMB`).
3. **Diagnóstico de Rendimiento y Retransmisiones TCP:** Análisis de retardos temporales (RTT), ventanas de congestión, paquetes duplicados (*TCP Dup ACK*) y conexiones caídas.

## 5. Comparativa de Motores de Filtrado: BPF vs. Display Filters

Uno de los contrastes técnicos más importantes entre ambas herramientas radica en **cómo y cuándo** se aplican los filtros:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    FILTROS DE CAPTURA vs. VISUALIZACIÓN                      │
├──────────────────────────────────────┬───────────────────────────────────────┤
│ FILTROS DE CAPTURA (BPF)             │ FILTROS DE VISUALIZACIÓN (DISPLAY)    │
├──────────────────────────────────────┼───────────────────────────────────────┤
│ • Utilizados por: tcpdump y          │ • Utilizados exclusivamente por:      │
│   Wireshark (al iniciar captura).    │   Wireshark y tshark.                 │
│ • Se evalúan en el kernel antes de   │ • Se evalúan en memoria sobre         │
│   escribir los paquetes a disco.     │   paquetes ya capturados.             │
│ • Los paquetes descartados se        │ • No se pierde ningún paquete;        │
│   pierden para siempre.              │   solo se ocultan temporalmente.      │
│ • Sintaxis: Berkeley Packet Filter   │ • Sintaxis: Protocol-Field-Operator   │
│   (ej: `src host 10.0.0.1 and port 53`) (ej: `ip.src == 10.0.0.1 && udp.port == 53`) │
└──────────────────────────────────────┴───────────────────────────────────────┘
```

### Tabla de Equivalencias de Sintaxis

| Objetivo del Filtro | Filtro BPF (tcpdump / Wireshark Capture) | Filtro de Visualización (Wireshark Display) |
| :--- | :--- | :--- |
| **Filtrar por dirección IP** | `host 192.168.1.10` | `ip.addr == 192.168.1.10` |
| **Filtrar solo IP de origen** | `src host 10.0.0.5` | `ip.src == 10.0.0.5` |
| **Filtrar por puerto TCP** | `tcp port 443` | `tcp.port == 443` |
| **Filtrar rango de puertos** | `portrange 20-25` | `tcp.port >= 20 && tcp.port <= 25` |
| **Filtrar paquetes SYN** | `tcp[tcpflags] & tcp-syn != 0` | `tcp.flags.syn == 1 && tcp.flags.ack == 0` |
| **Excluir tráfico SSH** | `not port 22` | `!(tcp.port == 22)` |
| **Métodos HTTP específicos** | *No nativo en BPF simple* | `http.request.method == "POST"` |

## 6. Matriz Comparativa Exhaustiva

| Parámetro | `tcpdump` | `Wireshark` |
| :--- | :--- | :--- |
| **Tipo de Interfaz** | CLI (Línea de comandos pura) | GUI interactiva (y CLI complementaria `tshark`) |
| **Biblioteca Central** | `libpcap` | `libpcap` (Linux/macOS), `Npcap` (Windows) |
| **Consumo de Memoria** | Muy bajo (megabytes) | Alto a muy alto (cientos de MB a GB con pcaps grandes) |
| **Soporte de Formatos** | Lee/escribe PCAP, PCAPng | Lee/escribe PCAP, PCAPng, snoop, cap, y formatos propietarios |
| **Momento de Filtrado** | En tiempo de captura (BPF) | En captura (BPF) y post-captura (*Display Filters*) |
| **Reconstrucción de Flujo** | No nativa (requiere herramientas externas) | Nativa (*Follow TCP / UDP / TLS / HTTP Stream*) |
| **Desencriptación TLS** | No disponible | Soportada (vía claves RSA o *SSLKEYLOGFILE*) |
| **Facilidad de Automatización** | Excelente (Bash, scripts, pipes `\|`, redirecciones) | Moderada (requiere `tshark` para scripts) |
| **Uso en Servidores Headless** | Nativo e ideal | Inviable (requiere X11 o entorno de escritorio) |
| **Curva de Aprendizaje** | Media (memorización de banderas y sintaxis BPF) | Baja para visualización básica, Alta para análisis experto |

## 7. El Flujo de Trabajo Operativo Conjunto (*The Golden Workflow*)

En entornos de ciberseguridad corporativa, los analistas no eligen una herramienta en detrimento de la otra; implementan una **metodología de dos fases**:

```
 [ Servidor Remoto en Producción ]                     [ Estación de Trabajo del Analista ]
┌─────────────────────────────────┐                 ┌─────────────────────────────────────┐
│ 1. Captura con tcpdump:         │                 │ 3. Carga y disección en Wireshark:  │
│    sudo tcpdump -i eth0 -nn     │  Transferencia  │    • Aplicación de Display Filters  │
│    -s 0 -w incidente.pcap       │   segura SCP    │    • Reensamblado de flujos TCP     │
│    "port 80 or port 443"        │ ──────────────► │    • Búsqueda de IoCs y payloads    │
│                                 │                 │    • Extracción de malware embebido │
│ 2. Archivo ligero generado      │                 │                                     │
│    sin degradar rendimiento     │                 │ 4. Documentación y reporte en el    │
│    del servidor.                │                 │    Diario del Gestor de Incidentes  │
└─────────────────────────────────┘                 └─────────────────────────────────────┘
```

### Paso a Paso Operativo:

1. **Fase de Captura (Perímetro / Servidor):**
   El analista se conecta vía SSH al servidor afectado y lanza una captura acotada para aislar la actividad sospechosa:
   ```bash
   sudo tcpdump -i eth0 -nn -s 0 -w sospechoso.pcap host 198.51.100.24
   ```
   * `-nn`: Desactiva la resolución de nombres de host y de puertos para máxima velocidad.
   * `-s 0`: Captura el paquete completo (*snaplen* ilimitado).
   * `-w`: Guarda la salida cruda en formato PCAP estándar.

2. **Fase de Transferencia:**
   Se descarga el archivo resultante hacia la estación de análisis forense mediante un canal seguro (`scp` o `sftp`).

3. **Fase de Análisis Forense (Wireshark):**
   El analista abre `sospechoso.pcap` en Wireshark, filtra la conversación con `ip.addr == 198.51.100.24`, reconstruye la sesión con **Follow TCP Stream** para leer las interacciones y exporta cualquier artefacto para su hash y análisis en VirusTotal.

## 8. Puntos Clave

* **Complementariedad:** `tcpdump` es el motor de recolección eficiente en el origen; `Wireshark` es el microscopio de análisis en el destino.
* **Mismo Estándar:** La interoperabilidad total a través de los formatos **PCAP** y **PCAPng** permite que ambas herramientas colaboren de forma transparente.
* **Filtros Clave:** Recuerda que los filtros BPF de `tcpdump` descartan datos irreversiblemente durante la captura, mientras que los filtros de visualización de `Wireshark` permiten explorar y ocultar datos sin perder la evidencia original.
* **Regla de Oro en SOC:** Nunca ejecutes una interfaz gráfica pesada como Wireshark en un servidor crítico de producción en tiempo real; utiliza `tcpdump` para capturar y analiza fuera de línea en una máquina aislada.
