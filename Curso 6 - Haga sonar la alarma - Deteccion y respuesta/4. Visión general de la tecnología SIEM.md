# Visión General de la Tecnología SIEM

En esta lectura del **Curso 6: Haga sonar la alarma: Detección y respuesta**, se profundiza en la tecnología de **Gestión de Información y Eventos de Seguridad (SIEM)**, sus ventajas clave en las operaciones defensivas, las tres fases del proceso de ingesta y análisis de registros, y las soluciones líderes empleadas en la industria.

---

## 1. ¿Qué es un Sistema SIEM?

Una herramienta de **Información de Seguridad y Gestión de Eventos (SIEM)** es una plataforma centralizada diseñada para recopilar, normalizar, almacenar y analizar datos de registro (*logs*) procedentes de toda la infraestructura tecnológica de una organización.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                          DEFINICIÓN FUNDAMENTAL                          │
├──────────────────────────────────────────────────────────────────────────┤
│ Un SIEM combina dos disciplinas históricas:                              │
│ • SIM (Security Information Management): Gestión, almacenamiento a largo │
│   plazo, auditoría y generación de informes de datos de seguridad.       │
│ • SEM (Security Event Management): Monitoreo en tiempo real, correlación │
│   de eventos, procesamiento de alertas y notificación inmediata.         │
└──────────────────────────────────────────────────────────────────────────┘
```

El SIEM constituye el pilar operativo sobre el cual los analistas del Centro de Operaciones de Seguridad (SOC) realizan el **análisis de registros**, examinando eventos en busca de patrones anómalos o indicadores de compromiso (IoC) que requieran respuesta inmediata.

## 2. Ventajas Principales de un SIEM

La implementación de una solución SIEM aporta capacidades críticas para la detección temprana y la investigación de incidentes:

```
                      ┌─────────────────────────────────┐
                      │    VENTAJAS CLAVE DE UN SIEM    │
                      └────────────────┬────────────────┘
                                       │
         ┌─────────────────────────────┼─────────────────────────────┐
         ▼                             ▼                             ▼
┌──────────────────┐          ┌──────────────────┐          ┌──────────────────┐
│  ACCESIBILIDAD   │          │  MONITOREO Y     │          │  ALMACENAMIENTO  │
│  CENTRALIZADA    │          │  ALERTAS EN VIVO │          │  Y RETENCIÓN     │
├──────────────────┤          ├──────────────────┤          ├──────────────────┤
│ Acceso unificado │          │ Detección en     │          │ Preservación     │
│ a registros de   │          │ tiempo real      │          │ histórica para   │
│ cientos de       │          │ mediante reglas  │          │ auditoría, leyes │
│ sistemas en una  │          │ lógicas y de     │          │ de cumplimiento  │
│ sola consola.    │          │ correlación.     │          │ y análisis post. │
└──────────────────┘          └──────────────────┘          └──────────────────┘
```

### 1. Accesibilidad Centralizada a los Datos de Eventos
* En una empresa moderna existen cientos o miles de dispositivos interconectados (servidores, enrutadores, cortafuegos, estaciones de trabajo, servicios en la nube).
* Consultar manualmente el registro local de cada equipo es inviable durante un incidente activo. El SIEM ingiere todos estos datos y permite realizar consultas globales desde una única interfaz unificada.

### 2. Monitoreo Continuo, Detección y Generación de Alertas
* Supervisa continuamente los flujos de datos en tiempo real mediante motores de reglas analíticas.
* Cuando un evento o serie de eventos coincide con una regla de detección (por ejemplo, diez intentos fallidos de autenticación en menos de un minuto seguidos de un acceso exitoso), genera y despacha automáticamente una alerta para que los analistas inicien el triaje.

### 3. Almacenamiento y Retención de Registros
* Funciona como un repositorio central seguro donde los registros se conservan intactos.
* Permite cumplir con requerimientos normativos (PCI-DSS, ISO 27001, GDPR, HIPAA) que exigen conservar registros durante meses o años para fines de auditoría forense retrospectiva.

## 3. El Proceso SIEM: Tres Pasos Críticos

Para transformar millones de líneas de texto dispersas en inteligencia procesable, el SIEM ejecuta un proceso continuo estructurado en tres etapas:

```
┌──────────────────────────────────────────────────────────────────────────┐
│                            EL FLUJO DEL SIEM                             │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │
                                     ▼
         ┌───────────────────────────────────────────────────────┐
         │ 1. RECOPILAR Y AGREGAR DATOS                          │
         │    Ingesta de eventos de múltiples fuentes + Parsing  │
         └───────────────────────────┬───────────────────────────┘
                                     │
                                     ▼
         ┌───────────────────────────────────────────────────────┐
         │ 2. NORMALIZACIÓN DE DATOS                             │
         │    Conversión de formatos heterogéneos a un estándar  │
         └───────────────────────────┬───────────────────────────┘
                                     │
                                     ▼
         ┌───────────────────────────────────────────────────────┐
         │ 3. ANALIZAR LOS DATOS                                 │
         │    Reglas de detección, correlación y alertas         │
         └───────────────────────────────────────────────────────┘
```

---

### Paso 1: Recopilación y Agregación de Datos

Las herramientas SIEM requieren alimentarse de registros generados por diversas fuentes de la organización:
* **Cortafuegos y Enrutadores:** Conexiones bloqueadas, aperturas de sesión, denegaciones de tráfico.
* **Servidores y Directorios Activos:** Inicios de sesión, cambios de permisos, creación de cuentas.
* **Sistemas de Punto Final (EDR):** Ejecución de procesos, llamadas a librerías, modificaciones de registro.
* **Aplicaciones y Bases de Datos:** Consultas transaccionales, accesos administrativos, errores web.

**Agregación:** Consiste en consolidar todos estos registros dispersos en un único repositorio centralizado, eliminando la necesidad de acceder individualmente a cada servidor o dispositivo.

#### El Análisis Sintáctico (*Parsing*)
Durante la recopilación, los registros en texto sin procesar (*raw logs*) se analizan sintácticamente para identificar y vincular campos con sus respectivos valores.

* **Ejemplo de registro sin procesar (difícil de interpretar para un motor analítico):**
  ```text
  April 3 11:01:21 server sshd[1088]: Failed password for user nuhara from 218.124.14.105 port 5023
  ```

* **Mapeo estructurado tras el análisis sintáctico (*parsing*):**
  ```text
  equipo_anfitrion  = server
  proceso           = sshd
  pid               = 1088
  usuario_origen    = nuhara
  ip_origen         = 218.124.14.105
  puerto_origen     = 5023
  evento            = Autenticación Fallida (Failed password)
  ```

---

### Paso 2: Normalización de Datos

Cada fabricante y sistema operativo utiliza nomenclaturas y estructuras diferentes para documentar el mismo concepto:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        EL RETO DE LA DISPARIDAD                        │
├────────────────────────────────┬───────────────────────────────────────┤
│ Fabricante / Fuente            │ Nombre del Campo para la IP de Origen │
├────────────────────────────────┼───────────────────────────────────────┤
│ Cortafuegos de Red             │ src_ip                                │
│ Servidor Windows               │ Source_Network_Address                │
│ Servidor Web Apache            │ c-ip (Client IP)                      │
│ Dispositivo de Red Cisco       │ source_ip_addr                        │
└────────────────────────────────┴───────────────────────────────────────┘
```

**Normalización:** Es la conversión sistemática de los datos sin procesar provenientes de fuentes heterogéneas a un **esquema unificado y estándar**.

Al normalizar, el SIEM mapea todas las variantes anteriores a un único identificador universal (por ejemplo, `ip_origen`). De este modo, un analista puede buscar una dirección IP sospechosa en toda la red corporativa mediante una única consulta, sin importar qué equipo generó el registro.

---

### Paso 3: Análisis de Datos y Correlación de Eventos

Una vez estructurados y normalizados, el SIEM aplica lógica analítica avanzada sobre los registros:

```
                     MOTOR DE CORRELACIÓN DEL SIEM
┌────────────────────────────────────────────────────────────────────────┐
│ Evento 1: Cortafuegos detecta escaneo de puertos (IP 203.0.113.50)     │
│                                  +                                     │
│ Evento 2: Servidor SSH registra 15 intentos fallidos (IP 203.0.113.50) │
│                                  +                                     │
│ Evento 3: Servidor SSH registra inicio de sesión exitoso (root)        │
│                                  │                                     │
│                                  ▼                                     │
│  ¡REGLA DE CORRELACIÓN CUMPLIDA! (Posible Intrusión por Fuerza Bruta)  │
│                                  │                                     │
│                                  ▼                                     │
│             Genera Alerta Crítica para el Analista SOC                 │
└────────────────────────────────────────────────────────────────────────┘
```

* **Reglas de Detección:** Condiciones lógicas preconfiguradas que buscan indicadores de actividad maliciosa conocida.
* **Correlación de Eventos:** Proceso analítico que compara y vincula múltiples eventos individuales ocurridos en distintas fuentes a lo largo del tiempo para revelar una secuencia de ataque que pasaría inadvertida si los eventos se observaran de manera aislada.

## 4. Herramientas SIEM Destacadas en la Industria

En el mercado de la ciberseguridad existen diversas plataformas SIEM comerciales y de código abierto ampliamente adoptadas:

| Solución SIEM | Características Destacadas |
| :--- | :--- |
| **Chronicle (Google Cloud)** | Diseñada para procesar petabytes de telemetría a escala global con velocidades de búsqueda instantáneas impulsadas por la infraestructura de Google. |
| **Splunk Enterprise Security** | Una de las plataformas más extendidas en entornos corporativos, con capacidades avanzadas de visualización, búsquedas en tiempo real y paneles personalizables. |
| **Elastic Security (Elasticsearch)** | Solución basada en el motor de búsqueda Elastic, optimizada para ingesta a gran escala, búsqueda rápida y monitoreo en tiempo real. |
| **IBM QRadar Security Intelligence** | Plataforma con fuerte motor de correlación automatizada, detección de anomalías y análisis de riesgos normativos. |
| **AlienVault OSSIM / USM** | Solución que integra SIEM con detección de intrusiones y evaluación de vulnerabilidades en una arquitectura lista para desplegar. |
| **Exabeam** | Destacada por su análisis de comportamiento de usuarios y entidades (UEBA), modelando la actividad habitual para detectar amenazas internas o credenciales comprometidas. |
| **LogRhythm** | Plataforma integral orientada a la automatización de la detección y la respuesta orquestada ante incidentes en el SOC. |

---

## 5. Puntos Clave

* Un **SIEM** recopila y organiza volúmenes masivos de datos para convertirlos en inteligencia útil y procesable para los equipos de seguridad.
* El ciclo operativo de un SIEM se sustenta en tres fases indispensables: **recopilación y agregación** (con análisis sintáctico de campos), **normalización** (estandarización a un modelo de datos común) y **análisis** (aplicación de reglas y correlación de eventos).
* La **correlación de eventos** es la capacidad más distintiva del SIEM, ya que conecta indicios dispersos en diferentes sistemas para descubrir ataques coordinados que de otra forma permanecerían ocultos.
