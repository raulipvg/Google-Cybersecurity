# Herramientas y Técnicas de Detección: HIDS vs. NIDS, Análisis de Firmas y Análisis de Anomalías

En esta guía del **Curso 6: Haga sonar la alarma: Detección y respuesta**, se exploran en profundidad los **Sistemas de Detección de Intrusiones (*Intrusion Detection Systems - IDS*)**, sus tipologías de despliegue según el entorno (**HIDS** y **NIDS**) y las dos metodologías analíticas fundamentales para identificar actividades maliciosas: el **Análisis basado en firmas** y el **Análisis basado en anomalías**. Se examinan sus ventajas operativas, vectores de evasión, limitaciones estructurales y cómo articular una estrategia de detección multicapa en el SOC.

---

## 1. El Rol de los Sistemas de Detección de Intrusiones (IDS)

Un **Sistema de Detección de Intrusiones (IDS)** es una solución tecnológica (software o hardware) diseñada para monitorizar de manera continua el tráfico de red o la actividad interna de los sistemas informáticos, con el fin de identificar indicios de accesos no autorizados, ataques en curso o violaciones a las políticas de seguridad corporativas.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    DIFERENCIA CONCEPTUAL: IDS vs. IPS                        │
├──────────────────────────────────────┬───────────────────────────────────────┤
│ IDS (DETECCIÓN DE INTRUSIONES)       │ IPS (PREVENCIÓN DE INTRUSIONES)       │
├──────────────────────────────────────┼───────────────────────────────────────┤
│ • Modo: **Pasivo / Fuera de banda**. │ • Modo: **Activo / En línea (In-line) │
│ • Acción: Inspecciona eventos,       │ • Acción: Inspecciona paquetes y      │
│   registra evidencias y genera       │   **bloquea/descarta el tráfico**     │
│   alertas para los analistas.        │   malicioso en tiempo real.           │
│ • Impacto en red: Cero latencia      │ • Impacto en red: Si el sensor falla  │
│   (no interrumpe el flujo normal).   │   o se satura, puede frenar la red.   │
└──────────────────────────────────────┴───────────────────────────────────────┘
```

## 2. Tipologías de IDS según la Ubicación de Despliegue

La visibilidad de un IDS depende directamente del lugar físico o lógico donde se instale. La industria divide estas tecnologías en dos grandes familias:

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                      HIDS vs. NIDS EN LA ARQUITECTURA                        │
├──────────────────────────────────────┬───────────────────────────────────────┤
│ HIDS (BASADO EN EL HOST)             │ NIDS (BASADO EN LA RED)               │
├──────────────────────────────────────┼───────────────────────────────────────┤
│ • Instalado como agente local en     │ • Instalado en puntos estratégicos    │
│   cada endpoint (servidores/PCs).    │   de la red (switches core, perim).   │
│ • Visibilidad: Actividad interna del │ • Visibilidad: Paquetes en tránsito   │
│   sistema operativo y archivos.      │   entre múltiples dispositivos.       │
│ • Inspecciona tráfico descifrado     │ • Ciego ante tráfico cifrado          │
│   (a nivel de memoria/aplicación).   │   (HTTPS/TLS) sin proxys SSL.         │
│ • Ejemplo: Wazuh, OSSEC, Sysmon.     │ • Ejemplo: Snort, Suricata, Zeek.     │
└──────────────────────────────────────┴───────────────────────────────────────┘
```

---

### A. Sistema de Detección de Intrusiones Basado en el Anfitrión (HIDS)
Un **HIDS** opera como un agente residente en la máquina objetivo (*endpoint*), supervisando exclusivamente los eventos que tienen lugar dentro de ese dispositivo:
* **Monitoreo de Integridad de Archivos (FIM - *File Integrity Monitoring*):** Calcula hashes criptográficos periódicos de archivos binarios y librerías críticas del sistema (`/etc/passwd`, `C:\Windows\System32\kernel32.dll`) para alertar si un atacante los modifica.
* **Inspección de Procesos y Memoria:** Detecta la ejecución de aplicaciones no autorizadas, inyecciones de código en memoria o llamadas anómalas a la API del sistema operativo.
* **Auditoría de Registros Locales y Cuentas:** Alerta sobre modificaciones en el Registro de Windows (`HKLM\Run`), escalado de privilegios y creación de nuevos usuarios locales.
* **Superación del Cifrado de Red:** Dado que el HIDS reside en el host donde los datos HTTPS/TLS son finalmente descifrados por las aplicaciones, puede inspeccionar la carga útil en texto claro.

---

### B. Sistema de Detección de Intrusiones Basado en la Red (NIDS)
Un **NIDS** se implementa en la infraestructura de comunicaciones para inspeccionar el flujo de paquetes que viaja entre los diferentes segmentos de red:
* **Conexión mediante TAP o Puerto Espejo (*SPAN Port*):** El sensor NIDS opera en **modo promiscuo**, capturando copias del tráfico que atraviesa los conmutadores (*switches*) o enrutadores perimetrales.
* **Detección de Movimiento Lateral y Escaneos:** Identifica barridos de puertos TCP/UDP (*port scanning*), ataques de denegación de servicio (SYN Floods) y conexiones sospechosas entre subredes corporativas.
* **Desvinculación del Host:** Los endpoints no sufren ninguna degradación de CPU o memoria, y un atacante que comprometa un servidor no puede deshabilitar el sensor NIDS físico.

## 3. Técnicas de Detección: Firmas vs. Anomalías

Independientemente de si el IDS está en el host o en la red, el software debe utilizar un motor de análisis para decidir si un evento observado es legítimo o malicioso.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                    METODOLOGÍAS DE DETECCIÓN ANALÍTICA                       │
├──────────────────────────────────────┬───────────────────────────────────────┤
│ ANÁLISIS BASADO EN FIRMAS            │ ANÁLISIS BASADO EN ANOMALÍAS          │
├──────────────────────────────────────┼───────────────────────────────────────┤
│ • Busca lo **MALICIOSO CONOCIDO**.   │ • Busca lo **DIFERENTE DE LO NORMAL**.│
│ • Compara patrones fijos: bytes,     │ • Compara el comportamiento actual    │
│   hashes, expresiones regulares.     │   contra una línea base (*baseline*). │
│ • Falsos positivos: Muy bajos.       │ • Falsos positivos: Elevados.         │
│ • Efectividad Zero-Day: Nula.        │ • Efectividad Zero-Day: Alta.         │
└──────────────────────────────────────┴───────────────────────────────────────┘
```

---

### A. Análisis Basado en Firmas (*Signature-Based Detection*)

El análisis por firmas compara los datos inspeccionados contra una **base de datos de patrones predefinidos** (*signatures*) que representan amenazas identificadas previamente por investigadores.

* **Naturaleza de una Firma:** Puede ser un hash SHA-256 de un malware, una secuencia específica de bytes dentro de la cabecera de un paquete de red, o una regla de texto estructurada:
  ```text
  # Regla de firma típica de Snort / Suricata:
  alert tcp any any -> $HOME_NET 80 (msg:"WEB-ATTACKS /etc/passwd access attempt"; 
  content:"/etc/passwd"; nocase; sid:1000001; rev:1;)
  ```
* **Relación con la Pirámide del Dolor:** Las firmas suelen apoyarse en los niveles inferiores de la pirámide (valores hash, direcciones IP, nombres de archivos y patrones de red atómicos).

#### Ventajas del Análisis por Firmas
1. **Extrema Precisión y Pocos Falsos Positivos:** Si un paquete coincide exactamente con la firma de un exploit conocido, la probabilidad de que sea un ataque real es casi del 100%.
2. **Eficiencia Computacional:** Algoritmos altamente optimizados de búsqueda de patrones (*pattern matching*) permiten procesar gigabits de tráfico por segundo con bajo consumo de CPU.

#### Desventajas del Análisis por Firmas
1. **Ceguera Total ante Amenazas Desconocidas (*Zero-Days*):** Si un atacante utiliza un exploit recién creado o una variante de malware que no tiene firma en la base de datos, el IDS no alertará.
2. **Evasión Trivial:** Modificaciones menores en el código (polimorfismo, encriptación de la carga útil o espacios en blanco en peticiones web) rompen la firma fácilmente.
3. **Mantenimiento Continuo:** Requiere actualizar la base de firmas diariamente; una base desactualizada vuelve inútil al sistema.

---

### B. Análisis Basado en Anomalías (*Anomaly-Based Detection*)

El análisis por anomalías (también llamado heurístico o de comportamiento) no busca ataques concretos; en su lugar, **aprende el comportamiento normal del entorno y alerta ante cualquier desviación estadística**.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                 LAS DOS FASES DEL ANÁLISIS DE ANOMALÍAS                      │
├──────────────────────────────────────────────────────────────────────────────┤
│ 1. FASE DE ENTRENAMIENTO (TRAINING PHASE):                                   │
│    • El sistema recopila telemetría durante días o semanas en condiciones    │
│      de operación habituales.                                                │
│    • Establece la **Línea de Base (*Baseline*)**: Horarios de login típicos, │
│      volúmenes de transferencia de datos, puertos usados habitualmente.      │
├──────────────────────────────────────────────────────────────────────────────┤
│ 2. FASE DE DETECCIÓN (DETECTION PHASE):                                      │
│    • La actividad en vivo se compara en tiempo real con la línea de base.    │
│    • Si un usuario que normalmente transfiere 10 MB a las 14:00 descarga     │
│      50 GB hacia un servidor externo a las 03:00 AM, se dispara la alerta.   │
└──────────────────────────────────────────────────────────────────────────────┘
```

#### Ventajas del Análisis por Anomalías
1. **Detección de Exploits Desconocidos (*Zero-Days*):** Como no depende de firmas previas, puede identificar ataques nunca antes vistos simplemente porque alteran el comportamiento del sistema.
2. **Identificación de Amenazas Internas (*Insiders*) y Abuso de Cuentas:** Detecta cuando una cuenta de usuario legítima comienza a actuar de manera atípica.

#### Desventajas Críticas del Análisis por Anomalías
1. **Elevada Tasa de Falsos Positivos:** En entornos empresariales dinámicos, las personas cambian sus rutinas legítimamente (ej. cierre contable de fin de mes, migraciones masivas autorizadas). El IDS catalogará estas acciones normales como anomalías, saturando al SOC.
2. **El Peligro del Compromiso Preexistente (*Poisoning the Baseline*):** Si un atacante avanzado (APT) ya estaba dentro de la red **durante la fase de entrenamiento**, el sistema asumirá su actividad maliciosa como "comportamiento normal", volviendo al atacante completamente invisible para el motor de anomalías.

## 4. Matriz Comparativa Exhaustiva

### Tabla 1: HIDS vs. NIDS

| Criterio | **HIDS (Basado en Host)** | **NIDS (Basado en Red)** |
| :--- | :--- | :--- |
| **Punto de Instalación** | Agente local en servidores y estaciones de trabajo | Dispositivo dedicado / TAP en switches de red |
| **Alcance de Visión** | Microscópica (solo el host individual) | Macroscópica (toda la subred o segmento monitoreado) |
| **Impacto en el Endpoint** | Consume CPU, RAM y almacenamiento local | Cero impacto sobre los endpoints |
| **Tráfico Cifrado (TLS)** | Puede inspeccionarlo antes del cifrado o tras el descifrado | Ciego al contenido cifrado sin descifrado intermedio |
| **Detección de Movimiento Lateral**| Limitada a conexiones directas al host | Excelente (detecta propagación entre máquinas) |
| **Resistencia a Sabotaje** | Si el atacante obtiene privilegios `root`, puede matar el HIDS | Inmune a la manipulación directa desde el endpoint |

---

### Tabla 2: Análisis por Firmas vs. Análisis por Anomalías

| Criterio | **Análisis Basado en Firmas** | **Análisis Basado en Anomalías** |
| :--- | :--- | :--- |
| **Mecanismo Central** | Comparación exacta de patrones conocidos | Desviación estadística respecto a una línea de base |
| **Detección de Zero-Days** | Imposible (requiere firma previa) | Alta capacidad de detección |
| **Tasa de Falsos Positivos** | Extremadamente baja | Muy alta (alta fatiga de alertas) |
| **Carga de Mantenimiento** | Actualización diaria de bases de firmas | Calibración periódica y reentrenamiento de umbrales |
| **Riesgo Operativo Mayor** | Evasión por polimorfismo o cifrado | Envenenamiento de la línea base por intrusión previa |
| **Velocidad de Respuesta** | Casi instantánea | Requiere acumular muestras temporales |

## 5. Puntos Clave para el Analista de Ciberseguridad

* **La Sinergia es Indispensable:** Ningún IDS es suficiente por sí solo. El NIDS protege el perímetro y detecta movimientos laterales; el HIDS protege la integridad local y los procesos internos.
* **Firmas para lo Conocido, Anomalías para lo Desconocido:** Las firmas garantizan certeza inmediata ante malware común; los motores de anomalías y machine learning permiten descubrir campañas sofisticadas y *zero-days*.
* **El Problema del Cifrado Moderno:** Ante el predominio de TLS 1.3, el valor de los sensores NIDS tradicionales ha migrado hacia la inspección de metadatos (SNI, flujos de tráfico, huellas JA3), mientras que la inspección profunda de cargas útiles depende cada vez más del HIDS/EDR en el host.
* **Cuidado con la Fase de Entrenamiento:** Al desplegar un IDS basado en anomalías, el equipo de seguridad debe asegurarse rigurosamente de que la red esté limpia de intrusos antes de fijar la línea de base.
