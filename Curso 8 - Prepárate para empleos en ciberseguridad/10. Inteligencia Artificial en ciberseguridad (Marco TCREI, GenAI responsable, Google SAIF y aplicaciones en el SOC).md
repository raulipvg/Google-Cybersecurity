# Inteligencia Artificial en Ciberseguridad (Marco TCREI, GenAI Responsable, Google SAIF y Aplicaciones en el SOC)

En esta décima entrega del **Curso 8: Prepárate para empleos en ciberseguridad**, se analiza la convergencia entre la **Inteligencia Artificial (IA)**, la **IA Generativa (GenAI)** y las operaciones cotidianas de defensa digital. La IA está transformando radicalmente la ciberseguridad: los actores de amenazas emplean modelos de lenguaje para sofisticar ataques de ingeniería social, desarrollar malware polimórfico y automatizar escaneos de vulnerabilidades. Paralelamente, los defensores cuentan con herramientas sin precedentes para acelerar el triaje de incidentes, correlacionar eventos masivos, generar código de mitigación y traducir marcos normativos complejos.

Para un analista de ciberseguridad de nivel básico, dominar la **ingeniería de prompts (*Prompt Engineering*)** mediante metodologías rigurosas como el marco **TCREI (*Task, Context, References, Evaluate, Iterate*)**, comprender las directrices éticas de **uso responsable**, y conocer marcos globales de gobernanza como el **Marco de IA Segura de Google (*SAIF - Secure AI Framework*)** y las pautas del **NIST sobre sesgos en IA**, constituye una ventaja competitiva determinante.

## 2. Metodología de Ingeniería de Prompts: El Marco TCREI

Un error habitual de los usuarios novatos es interactuar con modelos de lenguaje mediante instrucciones ambiguas o desprovistas de contexto. En ciberseguridad, un prompt deficiente produce respuestas genéricas, códigos sintácticamente inválidos o, en el peor de los casos, **alucinaciones técnicas peligrosas**.

Para obtener resultados altamente precisos y procesables, Google promueve el marco metodológico **TCREI**:

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                EL MARCO TCREI PARA INGENIERÍA DE PROMPTS                         │
├───────────────────┬─────────────────────────────────────────────────────────────────────────────┤
│ Componente        │ Descripción Operativa en Ciberseguridad                                     │
├───────────────────┼─────────────────────────────────────────────────────────────────────────────┤
│ **T - Tarea**     │ Acción técnica concreta, delimitada y unívoca que el modelo debe ejecutar. │
│ *(Task)*          │ (Ej. *"Analiza este fragmento de log"*, *"Identifica la vulnerabilidad"*).   │
├───────────────────┼─────────────────────────────────────────────────────────────────────────────┤
│ **C - Contexto**  │ El entorno operativo, el rol asignado al modelo, restricciones y audiencia.│
│ *(Context)*       │ (Ej. *"Actúa como analista Tier 1 del SOC en una pasarela de pago B2B"*).   │
├───────────────────┼─────────────────────────────────────────────────────────────────────────────┤
│ **R - Referencias**│ Información fáctica de soporte: fragmentos de logs, código, CVEs o estándares│
│ *(References)*    │ (Ej. *"Utiliza la taxonomía MITRE ATT&CK v14 y el formato JSON RFC 8259"*). │
├───────────────────┼─────────────────────────────────────────────────────────────────────────────┤
│ **E - Evaluar**   │ Revisión crítica humana del resultado: verificar precisión, alucinaciones   │
│ *(Evaluate)*      │ y factibilidad técnica antes de aplicar cualquier acción en producción.     │
├───────────────────┼─────────────────────────────────────────────────────────────────────────────┤
│ **I - Iterar**    │ Diálogo continuo de refinamiento: ajustar restricciones, solicitar pasos de │
│ *(Iterate)*       │ razonamiento (*Chain of Thought*) y pulir la salida técnica.                │
└───────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

### Ciclo Operativo TCREI:

```
    ┌───────────────┐        ┌──────────────────┐        ┌──────────────────┐
    │  1. TAREA     │───────►│   2. CONTEXTO    │───────►│  3. REFERENCIAS  │
    │  Definir fin  │        │ Establecer marco │        │ Proveer insumos  │
    └───────────────┘        └──────────────────┘        └─────────┬────────┘
                                                                   │
                                                                   ▼
    ┌───────────────┐        ┌──────────────────┐        ┌──────────────────┐
    │  SALIDA FINAL │◄───────│    5. ITERAR     │◄───────│   4. EVALUAR     │
    │  Operacional  │        │ Refinar prompt   │        │ Validación humana│
    └───────────────┘        └──────────────────┘        └──────────────────┘
```

## 3. Aplicaciones Reales de la IA Generativa en el Flujo de Trabajo del SOC

Los profesionales de ciberseguridad (como los analistas e ingenieros de Google) emplean GenAI para optimizar múltiples etapas del ciclo de vida de operaciones de seguridad:

### 3.1. Detección y Análisis de Phishing y Cabeceras de Correo

GenAI descompone cabeceras complejas de correo electrónico y evalúa mecanismos de autenticación de mensajes en segundos:

* **Inspección de Autenticación:** Verificar alineación de SPF (*Sender Policy Framework*), firmas DKIM (*DomainKeys Identified Mail*) y políticas DMARC (*Domain-based Message Authentication, Reporting, and Conformance*).
* **Análisis Lingüístico de Urgencia:** Detectar patrones psicológicos de persuasión como urgencia artificial (*"transfiera fondos antes de las 14:00"*), suplantación de identidad ejecutiva (CEO Fraud / BEC) y anomalías léxicas.

### 3.2. Revisión Estática de Código y Detección de Vulnerabilidades (SAST Asistido)

Un analista puede solicitar a modelos como Gemini inspeccionar scripts de automatización en Python o Bash en busca de fallas reconocidas en el catálogo **CWE (*Common Weakness Enumeration*)** y en el **OWASP Top 10**:

* Identificación de inyección de comandos o SQL (`CWE-89`).
* Desbordamientos de búfer en código binario o integraciones C/C++ (`CWE-120`).
* Uso de bibliotecas obsoletas o métodos de hashing inseguros (MD5, SHA-1).
* **Propuesta de Remediación:** La IA no solo describe la vulnerabilidad, sino que genera el bloque de código corregido utilizando consultas parametrizadas (*Prepared Statements*) o funciones de escape seguras.

### 3.3. Navegación e Implementación de Marcos de Seguridad Complejos

Comprender la articulación entre marcos regulatorios puede requerir semanas de estudio normativo. Las herramientas de IA permiten:

* **Mapeo Cruzado:** Correlacionar requisitos de **PCI-DSS v4.0** con controles de **ISO/IEC 27001:2022** y subcategorías del **NIST Cybersecurity Framework 2.0 (CSF)**.
* **Correlación Táctica:** Vincular una detección de malware con las tácticas y técnicas de **MITRE ATT&CK** y sugerir contramedidas basadas en **MITRE D3FEND**.

### 3.4. Explicación y Triaje de Vulnerabilidades (CVEs)

Frente a una alerta del escáner de vulnerabilidades (ej. Nessus u OpenVAS):

* Traducir el vector de puntuación **CVSS (*Common Vulnerability Scoring System*)** a impacto operativo en el negocio.
* Diseñar planes de contingencia temporales cuando un parche oficial no puede aplicarse de inmediato debido a dependencias de producción.

## 4. Directrices Básicas para un Uso Responsable de la IA Generativa

El uso indiscriminado o negligente de la IA en entornos corporativos introduce riesgos legales, operativos y regulatorios severos. Todo analista debe regirse por los siguientes principios deontológicos y de gobierno:

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                       PRINCIPIOS DE USO RESPONSABLE DE LA IA EN EL SOC                          │
├───────────────────────────────┬─────────────────────────────────────────────────────────────────┤
│ Principio                     │ Medida Obligatoria para el Analista                             │
├───────────────────────────────┼─────────────────────────────────────────────────────────────────┤
│ **1. Validación Crítica**     │ Jamás asumir que el código o análisis de la IA es infalible.    │
│ *(Verification)*              │ Probar scripts en entornos de Sandbox aislados antes de aplicar.│
├───────────────────────────────┼─────────────────────────────────────────────────────────────────┤
│ **2. Protección de Datos**    │ PROHIBICIÓN ABSOLUTA de ingresar PII, SPII, credenciales de     │
│ *(Privacy & Confidentiality)* │ acceso, claves privadas o código sensible en modelos públicos.  │
├───────────────────────────────┼─────────────────────────────────────────────────────────────────┤
│ **3. Transparencia**          │ Declarar explícitamente en tickets, reportes forenses y peritajes│
│ *(Disclosure)*                │ qué secciones fueron asistidas por herramientas de IA.          │
├───────────────────────────────┼─────────────────────────────────────────────────────────────────┤
│ **4. Control Humano (HITL)**  │ Las decisiones de bloqueo de red, aislamiento de servidores o   │
│ *(Human Oversight)*           │ denuncias penales deben ser autorizadas por personas facultadas. │
└───────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

> [!WARNING]
> **Riesgo de Fuga de Datos por Reentrenamiento:** Muchos servicios públicos gratuitos de IA retienen los datos introducidos en los prompts para reentrenar sus modelos. Si un analista ingresa registros con direcciones de correo de clientes, números de tarjetas de crédito o credenciales de la red interna, incurre en una **violación grave de privacidad y cumplimiento (GDPR, PCI-DSS, HIPAA)**. Utilice únicamente instancias empresariales corporativas autorizadas donde el contrato garantice la confidencialidad estricta y la no retención de telemetría.

## 5. El Marco de IA Segura de Google (SAIF - *Secure AI Framework*)

Para abordar de manera integral los desafíos de seguridad específicos de los sistemas de inteligencia artificial y machine learning, Google presentó el **Marco de IA Segura (*Google's Secure AI Framework - SAIF*)**. Este marco se inspira en las mejores prácticas de ciberseguridad tradicionales y las extiende al ciclo de vida del aprendizaje automático.

```
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│                       LOS 6 ELEMENTOS CLAVE DE GOOGLE SAIF                                      │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. EXPANDIR BASES DE SEGURIDAD SÓLIDAS AL ECOSISTEMA DE IA                                      │
│    Aplicar controles de acceso fundamentales (IAM), principio de menor privilegio, cifrado en   │
│    tránsito y en reposo a la infraestructura donde residen los modelos y datasets de IA.        │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 2. EXTENDER DETECCIÓN Y RESPUESTA A AMENAZAS ESPECÍFICAS DE IA                                  │
│    Monitorear telemetría de inferencia para detectar ataques adversarios como inyecciones de    │
│    prompts (Prompt Injection), extracción de modelos y consultas anómalas continuas.            │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 3. AUTOMATIZAR LAS DEFENSAS PARA RESPONDER A LA VELOCIDAD DE LA IA                             │
│    Utilizar automatización e IA defensiva para contrarrestar ataques cibernéticos generados por │
│    actores maliciosos con herramientas automatizadas en tiempo real.                            │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 4. ARMONIZAR LOS CONTROLES A NIVEL DE PLATAFORMA PARA UNA SEGURIDAD HOMOGÉNEA                  │
│    Garantizar que las políticas de seguridad se apliquen uniformemente en toda la organización,  │
│    evitando que las iniciativas de IA operen en silos desprotegidos (Shadow AI).               │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 5. ADAPTAR CONTROLES Y CREAR BUCLES DE RETROALIMENTACIÓN DE MODELOS                             │
│    Realizar pruebas continuas de penetración (*Red Teaming* de IA), evaluar modelos frente a     │
│    nuevos vectores y reentrenar defensas basándose en incidentes reales.                        │
├─────────────────────────────────────────────────────────────────────────────────────────────────┤
│ 6. CONTEXTUALIZAR LOS RIESGOS DE LA IA EN LOS PROCESOS DE NEGOCIO                               │
│    Evaluar el impacto que una alucinación, un sesgo o una manipulación del modelo generaría en  │
│    la continuidad operativa, reputación y finanzas de la empresa.                               │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### Taxonomía de Amenazas Específicas contra Sistemas de IA (OWASP Top 10 for LLMs):

1. **Inyección de Prompts (*Prompt Injection*):**
   * *Directa (Jailbreaking):* Un usuario malicioso elabora entradas que engañan al modelo para que ignore sus instrucciones de seguridad del sistema (*System Prompt*).
   * *Indirecta:* El modelo consume contenido externo (ej. una página web o un correo) que contiene instrucciones ocultas para manipular la respuesta del modelo o exfiltrar datos.
2. **Envenenamiento de Datos (*Data Poisoning*):** Introducción deliberada de datos contaminados durante el entrenamiento o ajuste fino (*fine-tuning*) para inducir puertas traseras lógicas en el modelo.
3. **Inversión y Extracción de Modelos (*Model Theft / Inversion*):** Ataques diseñados para reconstruir los datos privados de entrenamiento o duplicar los pesos matemáticos del modelo mediante consultas sucesivas.
4. **Denegación de Servicio en Modelos (*Denial of Service - DoS*):** Generación de peticiones de inferencia masivas diseñadas para consumir la memoria GPU y agotar el presupuesto de procesamiento.

[TAREA]
Analiza el evento de log provisto a continuación. Determina:
1. Qué tipo de actividad sospechosa se evidencia.
2. Nivel de severidad técnica (Baja, Media, Alta o Crítica).
3. Mapeo a la técnica correspondiente de MITRE ATT&CK.
4. Una síntesis en formato BLUF (Bottom Line Up Front) de máximo 3 oraciones para notificar al supervisor de turno.

[REFERENCIAS]
Estándar de eventos de seguridad de Windows: Event ID 4625 (Logon Failure), Logon Type 3 (Network logon).
Log a analizar:
{"Timestamp": "2026-09-26T14:22:10Z", "EventID": 4625, "TargetUserName": "admin_db", "WorkstationName": "HOST-FIN-04", "IpAddress": "198.51.100.45", "FailureReason": "Unknown user name or bad password", "SubStatus": "0xC000006A", "CountInLast5Min": 54}

[EVALUACIÓN Y REFINAMIENTO HUMANO ESPERADO]

## 7. Demostración Técnica: Código Seguro Asistido por IA en Python

El siguiente script ilustra el antes y el después de una revisión de seguridad asistida por IA, reflejando cómo el analista valida e implementa la remediación:

```python
"""
Módulo: seguridad_autenticacion.py
Objetivo: Demostración práctica de vulnerabilidad CWE-89 (SQL Injection) 
          y su respectiva remediación segura validada por el analista.
"""

import sqlite3
import hashlib

# ❌ CÓDIGO VULNERABLE (Inseguro - Concatenación directa de cadenas)
def consulta_insegura(conexion, usuario_input, clave_input):
    cursor = conexion.cursor()
    # Peligro: Si usuario_input es: admin' --
    # La consulta anula la verificación de contraseña.
    query = f"SELECT * FROM usuarios WHERE usuario = '{usuario_input}' AND clave = '{clave_input}'"
    print(f"[DEBUG INSEGURO] Ejecutando: {query}")
    cursor.execute(query)
    return cursor.fetchall()


# ✔️ CÓDIGO SEGURO (Remediado mediante consultas parametrizadas)
def consulta_segura(conexion, usuario_input, clave_input):
    cursor = conexion.cursor()
    # Mitigación estándar: El motor de base de datos trata los valores como datos literales,
    # impidiendo que caracteres especiales modifiquen la lógica de la sentencia SQL.
    query = "SELECT id, usuario, rol FROM usuarios WHERE usuario = ? AND password_hash = ?"
  
    # Preprocesamiento seguro: Hashear la credencial ingresada
    clave_hasheada = hashlib.sha256(clave_input.encode("utf-8")).hexdigest()
  
    print("[DEBUG SEGURO] Ejecutando consulta con parámetros enlazados de forma segura.")
    cursor.execute(query, (usuario_input, clave_hasheada))
    return cursor.fetchall()


if __name__ == "__main__":
    # Demostración en base de datos en memoria para pruebas
    conexion = sqlite3.connect(":memory:")
    cursor = conexion.cursor()
    cursor.execute("CREATE TABLE usuarios (id INT, usuario TEXT, clave TEXT, password_hash TEXT, rol TEXT)")
  
    # Registro legítimo
    hash_correcto = hashlib.sha256("AdminP@ss123".encode("utf-8")).hexdigest()
    cursor.execute("INSERT INTO usuarios VALUES (1, 'admin', 'AdminP@ss123', ?, 'SuperUser')", (hash_correcto,))
    conexion.commit()

    print("--- Demostración de Seguridad Asistida por IA ---")
    payload_malicioso = "admin' --"
  
    print("\n1. Probando función vulnerable con ataque SQLi:")
    resultado_inseguro = consulta_insegura(conexion, payload_malicioso, "cualquier_clave")
    print(f"Resultado (Autenticación comprometida sin clave válida): {resultado_inseguro}")

    print("\n2. Probando función remediada con el mismo payload malicioso:")
    resultado_seguro = consulta_segura(conexion, payload_malicioso, "cualquier_clave")
    print(f"Resultado (Ataque neutralizado exitosamente, acceso denegado): {resultado_seguro}")
  
    conexion.close()
```

## 8. Lista de Verificación (*Checklist*) para el Uso Ético y Seguro de IA

Antes de integrar respuestas de herramientas de IA en sus labores diarias, el analista debe completar la siguiente lista de control:

* [ ] **Sanitización de Datos de Entrada:** ¿Se han eliminado todas las direcciones IP privadas internas, nombres reales de empleados, correos electrónicos corporativos, tokens y claves secretas antes de remitir el prompt?
* [ ] **Validación Sintáctica y Lógica:** ¿Se ejecutó el código o script generado en una máquina virtual o sandbox aislado antes de integrarlo en herramientas de producción?
* [ ] **Comprobación de Alucinaciones:** ¿Los comandos, flags de herramientas de seguridad (ej. Nmap, Wireshark, Suricata) y artículos de leyes/marcos citados por la IA existen realmente en la documentación oficial?
* [ ] **Trazabilidad y Registro:** ¿Se documentó en el informe o ticket de investigación que se utilizó asistencia de IA generativa para el análisis preliminar?
* [ ] **Alineación con la Política de la Organización:** ¿La herramienta de IA utilizada figura en la lista de software homologado por el Departamento de Seguridad y Riesgo Tecnológico de la empresa?
