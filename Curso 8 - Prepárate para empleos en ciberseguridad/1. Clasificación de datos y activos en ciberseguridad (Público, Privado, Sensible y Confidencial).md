# Clasificación de Datos y Activos en Ciberseguridad (Público, Privado, Sensible y Confidencial)

En esta primera entrega del **Curso 8: Prepárate para empleos en ciberseguridad**, se aborda un pilar estratégico de la gobernanza, el riesgo y el cumplimiento (GRC) y de las operaciones de seguridad: la **clasificación de datos y activos**. Para un analista de seguridad que inicia su trayectoria profesional, entender que la seguridad informática no aplica controles homogéneos a todos los elementos es fundamental. Los recursos defensivos (presupuesto, tiempo de cómputo, monitoreo del SOC y controles de cifrado) deben asignarse proporcionalmente a la criticidad y el impacto que sufriría la organización si un activo se ve comprometido. En esta guía se detalla la taxonomía de los cuatro niveles de datos (**Público, Privado, Sensible y Confidencial**), la jerarquía de activos de **Bajo Nivel vs. Alto Nivel**, y los marcos de referencia de la industria (NIST SP 800-60, FIPS 199 e ISO/IEC 27001).

## 1. La Mentalidad de Seguridad y la Gestión de Activos

La **mentalidad de seguridad (*Security Mindset*)** implica evaluar continuamente el entorno operativo desde la perspectiva del riesgo: identificar qué elementos poseen valor, cómo podrían ser atacados, qué vulnerabilidades presentan y cuál sería el impacto en el negocio ante una brecha.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                    EL CICLO FUNDAMENTAL DE LA PROTECCIÓN DE ACTIVOS                       │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌──────────────────────┐         ┌───────────▼───────────┐         ┌──────────────────────┐
 │    IDENTIFICAR       │────────►│      CLASIFICAR       │────────►│      PROTEGER        │
 │ ¿Qué activos posee   │         │ ¿Cuál es el valor e   │         │ Aplicar controles    │
 │ la organización?     │         │ impacto ante brecha?  │         │ proporcionales       │
 └──────────────────────┘         └───────────────────────┘         └──────────────────────┘
```

> [!IMPORTANT]
> **Axioma Fundamental de la Ciberseguridad:**
> *"No se puede proteger lo que no se conoce, y no se puede priorizar lo que no está clasificado."* 
> Tratar todos los datos con el máximo nivel de seguridad colapsa la operatividad del negocio por sobrecostos y fricción; tratarlos a todos con seguridad básica expone los activos más valiosos al desastre financiero y legal.

### ¿Qué es un Activo (*Asset*)?
Un **activo** es cualquier elemento tangible o intangible que posee valor económico, operativo, legal o estratégico para una organización. Incluye:
* **Activos de Información:** Bases de datos de clientes, código fuente propietario, algoritmos, registros financieros, secretos comerciales.
* **Activos de Hardware:** Servidores del centro de datos, estaciones de trabajo, dispositivos móviles, firewalls, switches de red.
* **Activos de Software:** Sistemas ERP, aplicaciones web de cara al cliente, sistemas operativos, herramientas analíticas.
* **Activos Intangibles:** Reputación corporativa, confianza de los clientes, propiedad intelectual, marcas registradas.

## 2. Taxonomía de Clasificación de Datos

Las organizaciones formulan su **Política de Clasificación de Datos (*Data Classification Policy*)** para categorizar la información en niveles discretos. Aunque cada empresa puede adaptar las nomenclaturas, el estándar internacional ampliamente adoptado por el sector corporativo y gubernamental comprende cuatro categorías principales:

```
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│                         NIVELES DE CLASIFICACIÓN DE DATOS                                │
├──────────────┬───────────────────────────────┬──────────────────────────────┬────────────┤
│ Nivel        │ Definición                    │ Requisito de Protección      │ Impacto de │
│              │                               │                              │ Brecha     │
├──────────────┼───────────────────────────────┼──────────────────────────────┼────────────┤
│ PÚBLICO      │ Información accesible a todos │ Integridad y Disponibilidad  │ Mínimo /   │
│              │ sin restricciones             │ (Evitar alteración o caída)  │ Nulo       │
├──────────────┼───────────────────────────────┼──────────────────────────────┼────────────┤
│ PRIVADO      │ Uso interno exclusivo de la   │ Confidencialidad interna y   │ Moderado / │
│              │ organización                  │ Control de Acceso (RBAC)     │ Operativo  │
├──────────────┼───────────────────────────────┼──────────────────────────────┼────────────┤
│ SENSIBLE     │ Datos personales e identidad  │ Cifrado (Reposo/Tránsito),   │ Severo /   │
│              │ regulados por ley (PII/PHI)   │ Auditorías y MFA obligatorio │ Regulatorio│
├──────────────┼───────────────────────────────┼──────────────────────────────┼────────────┤
│ CONFIDENCIAL │ Vitales para la estrategia y  │ Principio Need-to-Know,      │ Catastró-  │
│              │ continuidad del negocio       │ NDAs y aislamiento extremo   │ fico       │
└──────────────┴───────────────────────────────┴──────────────────────────────┴────────────┘
```

---

### 2.1. Datos Públicos (*Public Data*)
Los **datos públicos** son aquellos diseñados o autorizados explícitamente para el consumo abierto. Si son vistos, descargados o compartidos por cualquier persona fuera de la organización, no generan ningún perjuicio para la seguridad o las finanzas de la empresa.

* **Ejemplos Típicos:**
  * Comunicados de prensa oficiales.
  * Ofertas y descripciones de puestos de trabajo publicadas en bolsas de empleo.
  * Catálogos de productos, folletos y material de marketing.
  * Políticas de privacidad y términos de servicio web públicos.
  * La dirección URL y el contenido visible del sitio web corporativo.

> [!NOTE]
> **La Integridad en los Datos Públicos:**
> Que un dato sea público respecto a su **Confidencialidad** no significa que deba descuidarse su seguridad. Si un atacante altera un comunicado de prensa (*defacement*) o modifica las cifras de un catálogo público, la **Integridad** se ve vulnerada, provocando crisis de reputación y desinformación.

---

### 2.2. Datos Privados (*Private Data*)
Los **datos privados** constituyen información interna que no debe exponerse al público exterior. Aunque no suelen incluir identificadores regulados de clientes, su filtración expone la estructura interna de la organización y facilita ataques dirigidos (como phishing o ingeniería social).

* **Ejemplos Típicos:**
  * Direcciones de correo electrónico corporativas internas y organigramas.
  * Números de identificación de empleados (Employee IDs).
  * Políticas internas de procedimientos operativos estándar (SOPs).
  * Minutas de reuniones de equipo y memorandos de proyectos internos.
  * Datos preliminares de investigación y desarrollo sin carácter patentable inmediato.

* **Riesgo ante Acceso No Autorizado:**
  Permite a los atacantes mapear la superficie interna de ataque, identificar roles clave dentro de la compañía y construir campañas de spear-phishing altamente convincentes.

---

### 2.3. Datos Sensibles (*Sensitive Data*)
Los **datos sensibles** representan una categoría de alto riesgo estrictamente regulada por normativas nacionales e internacionales. El acceso no autorizado o la exfiltración de estos datos acarrea demandas civiles millonarias, multas gubernamentales y un deterioro drástico de la confianza pública.

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                          SUBDIVISIÓN DE LOS DATOS SENSIBLES                               │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
 ┌──────────────────────┐         ┌───────────▼───────────┐         ┌──────────────────────┐
 │         PII          │         │         SPII          │         │         PHI          │
 │ Información Personal │         │ PII de Alto Riesgo    │         │ Salud Protegida      │
 │ - Nombres completos  │         │ - Cuentas bancarias   │         │ - Historial médico   │
 │ - Direcciones post.  │         │ - Tarjetas (PCI-DSS)  │         │ - Diagnósticos       │
 │ - Teléfonos          │         │ - Números SSN / DNI   │         │ - Recetas farmacia   │
 │                      │         │ - Credenciales / Pass │         │ - Seguros de salud   │
 └──────────────────────┘         └───────────────────────┘         └──────────────────────┘
```

#### Desglose de Subcategorías Regulatorias:
1. **PII (*Personally Identifiable Information*):** Cualquier dato que permita identificar directa o indirectamente a una persona física (nombre, domicilio, teléfono personal). Regulado por normativas como GDPR (Europa), CCPA (California) o LGPD (Brasil).
2. **SPII (*Sensitive Personally Identifiable Information*):** Datos de identidad biométrica, números de Seguro Social (SSN), pasaportes, credenciales de inicio de sesión (usuarios y hashes de contraseñas) e información financiera (cuentas bancarias, números de tarjeta de crédito/débito bajo **PCI-DSS**).
3. **PHI (*Protected Health Information*):** Datos relacionados con el estado de salud físico o mental pasado, presente o futuro de un paciente, bajo normativas sanitarias estrictas como **HIPAA** en EE.UU.

---

### 2.4. Datos Confidenciales (*Confidential Data*)
Los **datos confidenciales** son el núcleo estratégico y comercial de la organización. Su pérdida o divulgación a la competencia o al público general puede destruir la ventaja competitiva de la empresa, invalidar patentes o amenazar directamente la viabilidad operativa y supervivencia del negocio.

* **Ejemplos Típicos:**
  * **Secretos Comerciales (*Trade Secrets*):** Fórmulas patentadas (ej. la receta de Coca-Cola), algoritmos de búsqueda y procesamiento, código fuente de software privativo.
  * **Información Financiera Estratégica:** Balances contables no publicados, previsiones de ingresos trimestrales antes del reporte a la bolsa de valores.
  * **Planes de Fusiones y Adquisiciones (M&A):** Negociaciones preliminares de compra de otras compañías.
  * **Registros de Auditoría Ejecutiva:** Minutas de juntas directivas y contratos corporativos confidenciales.

* **Salvaguardas Legales y Contractuales:**
  El acceso a datos confidenciales casi siempre está supeditado a la firma de **Acuerdos de Confidencialidad (NDAs - *Non-Disclosure Agreements*)**, que establecen responsabilidades penales y civiles directas en caso de fuga de información.

## 3. Clasificación de Activos: Bajo Nivel vs. Alto Nivel

La clasificación de activos consiste en inventariar y asignar un nivel de criticidad a los recursos tecnológicos y físicos de acuerdo con la sensibilidad de los datos que procesan o la función que desempeñan en la organización:

```
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│                        JERARQUÍA DE CRITICIDAD DE ACTIVOS                                 │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              │
     NIVEL DE RIESGO                          │                    EJEMPLOS EN EL SOC
  ▲                                           │
  │  ┌──────────────────────────────────┐     │     ┌──────────────────────────────────────┐
  │  │     ACTIVO DE ALTO NIVEL         │ ────┼───► │ Base de datos de pagos (PCI-DSS)     │
  │  │     (High-Level Asset)           │     │     │ Servidor con secretos comerciales    │
  │  ├──────────────────────────────────┤     │     │ Controlador de dominio (AD / DC)     │
  │  │     ACTIVO DE NIVEL MEDIO        │ ────┼───► │ Servidores de archivos internos      │
  │  │     (Mid-Level Asset)            │     │     │ Estaciones de trabajo de analistas   │
  │  ├──────────────────────────────────┤     │     │                                      │
  │  │     ACTIVO DE BAJO NIVEL         │ ────┼───► │ Servidor web público estático        │
  │  │     (Low-Level Asset)            │     │     │ Pantalla informativa de recepción    │
  │  └──────────────────────────────────┘     │     └──────────────────────────────────────┘
  └───────────────────────────────────────────┴─────────────────────────────────────────────►
                                                                  NIVEL DE CONTROLES REQUERIDOS
```

### 3.1. Activos de Bajo Nivel (*Low-Level Assets*)
* **Características:** Alojan o procesan exclusivamente datos públicos o de mínimo impacto. Si sufren una brecha de confidencialidad, el daño directo a la organización es insignificante.
* **Ejemplo Práctico:** El servidor que aloja la página informativa de la empresa (`https://www.empresa.com`). Si alguien lee su código HTML público, no hay pérdida de privacidad.
* **Controles Aplicados:** Seguridad perimetral estándar, parches periódicos de software y monitoreo de disponibilidad contra ataques DDoS.

### 3.2. Activos de Alto Nivel (*High-Level Assets*)
* **Características:** Alojan, procesan o transmiten datos sensibles o confidenciales, o soportan procesos de negocio indispensables para la operación (*Mission Critical Systems*). Su compromiso compromete la existencia misma de la entidad.
* **Ejemplo Práctico:** El servidor de correo de la alta dirección donde se negocian fusiones empresariales, o la base de datos PostgreSQL donde se almacenan historiales clínicos y números de tarjeta de crédito.
* **Controles Aplicados:** Cifrado de extremo a extremo, segmentación de red mediante VLANs y microsegmentación Zero Trust, autenticación MFA estricta basada en hardware (FIDO2), registros de auditoría inmutables en el SIEM y monitoreo 24/7 por el EDR.

## 4. Alineación con Estándares Internacionales (NIST, FIPS, ISO)

Los marcos de ciberseguridad formales estructuran la clasificación de activos bajo criterios objetivos:

### 4.1. FIPS 199 / NIST SP 800-60
El estándar federal estadounidense **FIPS 199** evalúa la información según el impacto potencial ante la pérdida de cada uno de los tres objetivos de seguridad de la Triada CIA:

$$\text{Categoría de Seguridad} = \{ (\text{Confidencialidad}, I), (\text{Integridad}, I), (\text{Disponibilidad}, I) \}$$

Donde $I \in \{\text{Bajo}, \text{Moderado}, \text{Alto}\}$:
* **Bajo:** Se espera un efecto adverso limitado en las operaciones de la organización o activos.
* **Moderado:** Se espera un efecto adverso serio (pérdidas financieras significativas o daño al prestigio).
* **Alto:** Se espera un efecto adverso severo o catastrófico (daños irreparables, quiebra, riesgos para la vida humana).

### 4.2. ISO/IEC 27001 (Control A.8 - Gestión de Activos)
Exige a las organizaciones:
1. Mantener un **Inventario de Activos** formalizado con propietarios asignados (*Asset Owners*).
2. Definir un esquema de **Clasificación de la Información** acorde a los requisitos legales y de negocio.
3. Establecer directrices de **Etiquetado de Información** (*Labeling*) y manipulación segura de medios físicos y digitales.

| **Monitoreo SIEM / Auditoría** | Errores / Disponibilidad | Accesos anómalos | Auditoría detallada | Registro inmutable de cada consulta |

## 6. Caso Práctico en el SOC: Triaje y Etiquetado Automatizado de Activos

En un entorno de seguridad real, el analista del SOC a menudo interactúa con listas de activos exportadas desde consolas de administración de activos (ITAM) o escáneres de vulnerabilidades para determinar qué alertas requieren atención prioritaria:

```python
"""
asset_risk_classifier.py - Script de Clasificación de Criticidad para Analistas SOC
Propósito: Evaluar el nivel de datos procesados por un activo y asignar su prioridad de triaje.
"""

from typing import Dict, List, Literal

ClassificationLevel = Literal["Público", "Privado", "Sensible", "Confidencial"]

# Definición del Inventario de Activos de la Organización
ASSET_INVENTORY = [
    {
        "hostname": "web-public-01",
        "ip": "203.0.113.10",
        "data_type": "Público",
        "description": "Servidor web principal de marketing corporativo"
    },
    {
        "hostname": "corp-mail-relay",
        "ip": "10.0.1.50",
        "data_type": "Privado",
        "description": "Servidor de retransmisión de correo interno de empleados"
    },
    {
        "hostname": "db-patient-records",
        "ip": "10.0.8.100",
        "data_type": "Sensible",
        "description": "Base de datos PostgreSQL con expedientes clínicos (PHI / HIPAA)"
    },
    {
        "hostname": "vault-rnd-patents",
        "ip": "10.0.9.25",
        "data_type": "Confidencial",
        "description": "Repositorio cifrado de fórmulas y secretos comerciales"
    }
]

def calculate_asset_priority(data_classification: ClassificationLevel) -> Dict[str, str]:
    """
    Determina la criticidad del activo y los controles exigidos en base a su nivel de datos.
    """
    if data_classification == "Público":
        return {
            "tier": "Bajo Nivel",
            "sla_response": "24 Horas",
            "required_controls": "Protección perimetral DDoS, parches regulares."
        }
    elif data_classification == "Privado":
        return {
            "tier": "Nivel Medio",
            "sla_response": "8 Horas",
            "required_controls": "Segmentación interna, RBAC, auditoría de accesos."
        }
    elif data_classification == "Sensible":
        return {
            "tier": "Alto Nivel (Crítico)",
            "sla_response": "1 Hora (Inmediato)",
            "required_controls": "Cifrado en reposo/tránsito, MFA estricto, DLP, auditoría regulatoria."
        }
    elif data_classification == "Confidencial":
        return {
            "tier": "Alto Nivel (Máxima Prioridad)",
            "sla_response": "15 Minutos (Crítico)",
            "required_controls": "Need-to-Know estricto, NDAs, aislamiento de red, logs inmutables."
        }
    else:
        return {"tier": "Desconocido", "sla_response": "N/A", "required_controls": "Investigación requerida."}

print("=" * 75)
print("       EVALUACIÓN DE CRITICIDAD DE ACTIVOS PARA EL SOC (CURSO 8)      ")
print("=" * 75)

for asset in ASSET_INVENTORY:
    priority_info = calculate_asset_priority(asset["data_type"])
    print(f"\n[+] Activo: {asset['hostname']} ({asset['ip']})")
    print(f"    - Clasificación de Datos : {asset['data_type']}")
    print(f"    - Nivel del Activo       : {priority_info['tier']}")
    print(f"    - SLA Respuesta a Alerta : {priority_info['sla_response']}")
    print(f"    - Controles Exigidos     : {priority_info['required_controls']}")

print("\n" + "=" * 75)
```

## 7. Resumen y Puntos Clave

1. **La Clasificación como Base:** No todos los activos requieren los mismos controles. Clasificar los datos permite priorizar recursos y proteger adecuadamente lo más crítico para la organización.
2. **Los 4 Niveles de Datos:**
   * **Público:** Accesible para todos; riesgo mínimo de confidencialidad, pero requiere integridad.
   * **Privado:** Uso interno exclusivo; su divulgación genera riesgos operacionales e ingeniería social.
   * **Sensible:** Información personal regulada (**PII**, **SPII**, **PHI**); su filtración conlleva severas multas legales y daño reputacional.
   * **Confidencial:** Vital para el negocio (secretos comerciales, finanzas no publicadas); protegido contractualmente mediante **NDAs**.
3. **Jerarquía de Activos:**
   * **Bajo Nivel:** Recursos cuya pérdida o alteración tiene un impacto superficial en la organización (ej. portal web informativo).
   * **Alto Nivel:** Sistemas y repositorios cuya vulneración amenaza la viabilidad o ventaja competitiva del negocio (ej. bases de datos bancarias, servidores de secretos comerciales).
4. **Rol del Analista de Ciberseguridad:** Familiarizarse inmediatamente con la política de clasificación de datos de la empresa para responder con precisión y priorizar las alertas que afectan a activos de alto nivel.
